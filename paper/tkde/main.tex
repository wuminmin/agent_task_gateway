\title{\systemname: Task-Scoped Clearance and Cumulative Exposure
Accounting for AI Agents}

\author{Anonymous Author(s)%
\thanks{The artifact includes a controlled local PostgreSQL performance
campaign and a three-scale, representative two-source TPC-H-derived
Join--Group campaign. Results remain single-host evidence; the latter is not
an official TPC-H run and neither campaign claims production generality.}}

\begin{abstract}
Large enterprises already operate governed reporting estates, but these
systems typically do not provide a unified, task-scoped cumulative release
contract for adaptive agents. \systemname{} (BDG) governs agents that query
immutable reporting publications produced by scheduled synchronization. For
each approved root task and its delegated descendants, BDG models three
profile-defined effects: accounted result facts, conservative positive-output
dependency facts, and canonical query outcomes. A visible query and its
provenance companion share one PostgreSQL snapshot. Before release, BDG
computes profile-relative exact set novelty against the root-family ledger and
atomically settles all three budgets. No modeled artifact becomes retrievable before
settlement; failed promotion remains recoverable without re-executing the
business query. The admitted positive relational fragment supports connected
inner equijoins, grouping, bounded unions, and nested View expansion. Immutable
ordinals, compressed bitmaps, and an incrementally updated Merkle-radix set
represent cumulative effects. Paper theorems, bounded model checking, and
executable PostgreSQL differential and fault-injection tests validate the
scoped semantics and protocol. BDG targets periodic governed reporting
products; it neither measures an agent's complete knowledge nor provides
differential privacy, and it excludes mutable transactional databases and
cross-publication knowledge accounting.
\end{abstract}

\begin{IEEEkeywords}
data exposure, query auditing, provenance, adaptive workloads, cumulative

\end{IEEEkeywords}

\section{Introduction}
\label{sec:introduction}

\IEEEPARstart{D}{atabase} authorization asks, ``Can this query execute?''
An adaptive agent adds, ``How much policy-defined exposure has this task
acquired?'' Within one approved task, an agent may split projections, overlap
pages, retry, rewrite, and delegate while individual queries remain legal.
Per-query authorization and row limits do not state the root family's distinct
cumulative exposure.
BDG accounts that contract-defined quantity, not the agent's knowledge.
Data-flow control (DFC) asks whether a SQL flow is allowed
\cite{summers2026dataflow,summers2026passant}; conditional on authorization and
any DFC checks, BDG asks whether the next allowed execution fits the root's
cumulative contract.

Query count ignores answer size; row count makes a one-row aggregate appear
cheap despite millions of source rows; bytes and cells depend on encoding and
shape. Query pricing develops anti-arbitrage objectives
\cite{koutris2012query,deep2017qirana,peng2025aria}, while provenance explains
where results came from \cite{green2007provenance,amsterdamer2011aggregate}.
BDG instead asks how human authorization can create a stateful disclosure
budget conserved across adaptive querying and delegation. It neither inspects
an LLM nor depends on an agent-specific planner.

Enterprise operational analytics commonly serves scheduled ETL outputs rather
than OLTP primaries. BDG compiles each completed cut into an immutable
publication. New roots may bind the next cut; unfinished roots and descendants
remain on the prior one through version routing or fail closed. BDG therefore
addresses adaptive disclosure within one reporting epoch, not freshness or
consistency over a changing database.

Large enterprises also operate data lakes or warehouses, reporting marts, Data
Catalogs, identity directories, and approval workflows. They organize data,
describe governed Products, identify employees, and record decisions, but do
not jointly turn one approved purpose into a machine-enforceable contract
across an agent's queries, retries, pages, and delegated subtasks. Implementing
that contract per agent--Product pair fragments the control surface. Models and
runtimes may change; the database data-egress boundary should not live in each
prompt or application.

Marketplace-integrated agents now close the discovery-and-request half of
this gap: Data Product MCP lets an agent find, request, and query governed
data products over MCP and validates the declared purpose against
natural-language contracts with an LLM-based governance check before each
query \cite{tonnarelli2026dataproductmcp}. The other half remains open. Once a
purpose is approved, per-query checks do not state how much governed data the
task has cumulatively released across retries, pages, rewrites, and delegated
subtasks, and that system's own expert panel names not letting a language
model make security decisions as an adoption barrier. BDG starts at that
boundary.

BDG is instead a brownfield-compatible data-egress layer at a governed serving
tier materialized from a lake or warehouse. The reporting pipeline supplies
immutable publications; the Catalog supplies Products, metadata, and candidate
business keys; identity/workflow systems supply subject, organization, purpose,
and approval; and object storage receives artifacts. BDG structurally validates
and version-binds administrator-attested stable semantic identities, compiles
these inputs into a signed task contract, and settles cumulative exposure under
a shared logical Gate contract implemented by Catalog-bound, version-routed
instances. At this
model-independent database boundary, human-approved bounds delimit
machine-enforced autonomy; the raw lake is not exposed directly to the agent.

This arrangement motivates a bonded-warehouse model. An immutable Reporting
Publication is governed inventory: a signed Grant permits queries but does not
clear an artifact to leave the trusted boundary. BDG releases only after scope
validation, cumulative settlement, and verified \code{AVAILABLE} promotion.
``Clearance'' is shorthand for that path, not legal or DFC compliance, and its
exactness is profile-relative rather than epistemic. The analogy covers only
declaration, settlement, and release. Formal terms remain \emph{Exposure
Ledger} and \emph{settlement receipt}; the latter certifies settlement and a
\code{PENDING} intent, not availability.

\system budgets the root task in three set-valued dimensions. \emph{Accounted
result exposure} identifies selected result values (wire label \emph{release});
accounting can precede availability. The \emph{positive-output dependency
footprint} conservatively identifies participating base facts---neither minimal
causes nor all physical reads---so a one-cell aggregate can expose large input.
\emph{Query outcome} combines canonical predicate atoms with one normalized
query/result composite. Existing set members add zero novelty: related
thresholds reuse shared atoms but charge different literals/composites, while
exact replay remains free.

The system follows a withhold-before-settlement discipline:

\begin{center}
\small
\code{reserve -> replay lookup / execute+stream -> derive -> settle -> publish}.
\end{center}

The visible query and ordinal companion share one frozen PostgreSQL snapshot
and remain withheld while one Control transaction computes exact set novelty,
checks all limits, advances the three-dimensional root head, and commits audit,
receipt, and a PENDING intent. A recoverable object-store step then promotes
the staged object and a second transaction records AVAILABLE/CONSUMED; a failed
limit rolls settlement back. Figure~\ref{fig:architecture-settlement} separates
offline publication from this online path.

Our unsubmitted SessionBound working manuscript, available as a preliminary
preprint, introduced the task-scoped authorization substrate
\cite{wu2026sessionbound}: a control plane that turns an approved task into a
signed, budgeted, auditable database session, and a runtime that enforces safe
views, row scope, denied fields, operation limits, per-session query and
disclosure counters, and receipts. It has not been accepted or submitted to
TDSC. Everything that makes the budget a set rather than a counter is new here:
the typed FactID semantics and closed algebra, the same-snapshot ordinal
companion and bitmap/Merkle-radix ledgers, canonical Outcome atoms and
composites, exact profile-relative novelty with atomic three-budget settlement
before \code{AVAILABLE}, root-family delegation conservation, the theorems and
bounded models, and the publication campaign. Its five implementation-backed
contributions are:

\begin{enumerate}
\item A typed FactID semantics for accounted Result, positive-output
Dependency, and canonical-atom/composite Outcome sets in a restricted algebra.
\item A same-snapshot ordinal companion for admitted one-Product, connected
2--16-role equijoins, two-branch union, grouping, and aggregates; bounded nested
Views flatten into this same core.
\item Profile-relative exact novelty and atomic three-budget settlement,
refined by immutable ordinal dictionaries, compressed bitmaps, and an exact
Merkle-radix Outcome set; settlement precedes \code{AVAILABLE}, and semantic
replay is zero-novelty.
\item Signed, monotonic delegation whose descendants share one root-family
ledger, preventing task-tree fan-out from multiplying capacity.
\item Separate algebraic theorems, bounded TLA+ safety models, and executable
Go/PostgreSQL differential and fault-injection evidence.
\end{enumerate}

These mechanisms expose a reusable task-to-data contract boundary for
governed serving Products while leaving the surrounding enterprise data,
identity, approval, storage, and audit systems in place.

\section{Context and Related Work}
\label{sec:related}

\subsection{Closest System Families}

GAAP provides the closest cross-tool IFC contrast \cite{stanley2026gaap}: its
persistent flow state spans steps, tasks, and services outside BDG's scope.
BDG instead specializes in typed SQL facts, same-snapshot evidence, and exact
profile-relative settlement per root.

\textbf{History and pricing.} Auditing reconstructs access or whether a history
determines forbidden data; simulatable auditing also protects denial
\cite{agrawal2004hippocratic,motwani2008auditing,kenthapadi2005simulatable}.
Query-pricing systems study determinacy, history, aggregation, and information
gain \cite{koutris2012query,deep2017qirana,peng2025aria}. BDG instead charges
declared facts and successful outcomes within one signed root and withholds
delivery unless settlement succeeds; it models neither prior knowledge nor
denial leakage.
Unlike DP accounting and answer reuse
\cite{dwork2014foundations,mazmudar2022cachedp,zhang2023dprovdb}, it releases
exact answers and claims no $\epsilon$ guarantee.

\textbf{Provenance.} Why/where/how provenance identifies witnesses, locations,
and algebraic derivations
\cite{buneman2001why,cui2001lineage,green2007provenance,cheney2009provenance};
aggregation needs value-level treatment \cite{amsterdamer2011aggregate}.
GProM and ProvSQL provide broader rewrite/circuit mechanisms
\cite{arab2018gprom,senellart2018provsql,sen2026provsql}. BDG claims no new
general provenance algebra; it co-generates typed effects and answers for a
positive fragment, then settles cumulative novelty before release.

\textbf{Data-flow policy enforcement.} FlowGuard and the later DFC/Passant work
in the same DFC line are the closest database-layer comparators to BDG
\cite{summers2026dataflow,summers2026passant}. The Passant paper formalizes
optimizer-invariant aggregate predicates over each output tuple's bag of
provenance monomials and introduces Provenance Guard Notation (PGN). It
describes rewrites that remove or replace violating tuples, terminate a query,
and constrain \code{INSERT}/\code{UPDATE} through source, sink, and
required-source policies. This per-query model covers contributor thresholds,
prohibited source combinations, grounding, prompt-bound untrusted flows, and
legal state transitions that BDG does not subsume.

The temporal unit differs. Passant focuses on one query and leaves trajectory
policy to future work. After authorization and applicable flow checks, BDG
persists Result, Dependency, and Outcome sets under one root and charges exact
profile-relative novelty across queries, retries, pages, supported rewrites,
and descendants. One root-head transaction co-commits settlement, audit,
receipt, and PENDING intent; AVAILABLE promotion is recoverable and fail-closed.
The prototype does not integrate or evaluate Passant--BDG composition. Thus DFC
asks whether a flow is allowed; BDG asks whether another allowed flow fits the
cumulative contract.

\textbf{Authorization and delegation.} Usage/history control, delegation,
RLS/VPD, ABAC/XACML, and query-policy systems establish ongoing authority,
attenuation, quotas, operations, and rows
\cite{park2004ucon,abadi2003history,li2003delegation,chadwick2008permis,
postgres16rls,hu2014abac,mehta2017qapla,zhang2022blockaid}.
BDG assumes that boundary, then makes every descendant settle against one
root ledger; distributed vouchers remain outside its centralized prototype.

\textbf{Agent controls.} MCP authorization and delegation scope capability
invocation \cite{mcp2025auth,mcp2025tools,south2025delegation}; AgentDojo
evaluates model/tool behavior under prompt injection
\cite{debenedetti2024agentdojo}. BDG treats the agent and generated SQL as
untrusted, but neither sanitizes result strings nor tracks later prompt/tool
flows. SafeNLIDB uses interaction history for model-side inference-risk
assessment and SQL generation \cite{liu2026safenlidb}; it is not a deterministic
database-side FactID ledger, while BDG claims no inference safety.

\textbf{Governed data products over MCP.} Data Product MCP
\cite{tonnarelli2026dataproductmcp} and the access-request assistant it builds
on \cite{dietz2025automating} automate discovery, purpose review, and
pre-execution contract guards at a data-product marketplace whose contracts
follow open standards \cite{bitol2025odcs}; enforcement is per query and the
purpose check is probabilistic. BDG is complementary and downstream: it assumes
a marketplace or Catalog has already bound Product, contract, and approved
purpose, and adds a deterministic, task-scoped ledger with atomic settlement
before availability. The two could compose---marketplace discovery and purpose
review upstream, BDG settlement at the serving tier---but the prototype does
not evaluate that composition.

\textbf{Novelty boundary.} Table~\ref{tab:system-comparison} separates these
controls. BDG adds three-set FactID novelty and shared-root settlement after
authorization and any DFC checks; it is narrower than DFC's policy/SQL/write
scope and cross-tool IFC. Exactness holds only for its signed profile, closed
language, root family, and publication, never as a DP or knowledge measure.

\section{Exposure Model}
\label{sec:model}

Agents, their plans, and delegated calls are untrusted. The model assumes
trusted identity, organizational-attribute, and approval assertions; Catalog
and Exposure-Profile authors and the immutable publication pipeline;
PostgreSQL execution and snapshot semantics; enforcement and Control services;
cryptographic and key-management configuration; and object-store access
control. Section~\ref{sec:system} states the associated failure and governance
boundary.

\subsection{Publication Epochs and Task Binding}

BDG's upstream boundary is a completed reporting synchronization, not a
mutable transactional database. We model its compiled output as follows.

\begin{definition}[Publication epoch]
A publication epoch is
\begin{equation}
 \begin{aligned}
 P_e=\langle& datasource,schema,snapshot\_bundle,\\
             & catalog,dictionary\rangle,
 \end{aligned}
 \label{eq:publication-epoch}
\end{equation}
where \emph{snapshot\_bundle} maps every stable role to its immutable reporting
publication, \emph{catalog} binds the bundle's schema, policy, and lineage,
and \emph{dictionary} is the set of ordinal dictionaries. We write $h_e$
for the digest of a canonical descriptor of these five components. In the prototype the
signed Catalog SHA transitively commits the datasource/schema, snapshot ID,
and manifest/dictionary/sidecar digests. The upstream synchronization cutoff
is a trusted ETL premise and co-versioned routing metadata; BDG does not
cryptographically enforce it as a separate manifest field.
A new synchronization creates a new $P_{e+1}$; it never mutates $P_e$.
\end{definition}

Any deployment alias such as \code{latest publication} must resolve to the
concrete Catalog digest whose transitive binding instantiates $P_e$ in the
authorization snapshot presented for approval; that binding becomes final
when approval succeeds. The prototype
has no mutable runtime alias: it eagerly writes the resolved Catalog digest into the
draft and approval revalidates it, so a deployer that requires the newest epoch
after a rollover must cancel and reissue the draft rather than rewrite it. In
particular, \emph{``latest'' is resolved at approval time, never at query time}. Let
$\mathsf Q(T)$ contain every query issued by an approved root
$T$ or any delegated descendant. Then
\begin{equation}
 \begin{aligned}
 \operatorname{publication}(T)&=P_e,\\
 \forall q\in\mathsf Q(T),\quad \operatorname{publication}(q)&=P_e.
 \end{aligned}
 \label{eq:publication-binding}
\end{equation}
The Catalog transitively binds the grant and FactID environment to that epoch;
ledger state, replay metadata, result evidence, audit events, and receipts
carry the corresponding publication and dictionary bindings. Execution,
settlement, and replay fail closed if they differ. Consequently an active root
cannot switch publications, even after the next cut becomes active for new
approvals.

\subsection{Facts and Task State}

\begin{definition}[Approved task]
\label{def:task}
An approved root task is the immutable authorization boundary
\begin{equation}
 T=(P,S,B,C), \qquad B=(B_R,B_D,B_O),
 \label{eq:task-tuple}
\end{equation}
where $P$ is the signed policy grant over the principal, data products,
fields, and scopes; $S$ is the immutable publication/snapshot binding from
Eq.~\eqref{eq:publication-binding}; $B$ gives the release, positive-output
dependency-footprint, and query-outcome ceilings; and $C$ is the signed set of
semantic and execution constraints.  In particular, $C$ binds the effect
profile and closed QueryPlan language, type/collation versions, semantic-View
contracts, delegation rules, replay identity, and result handling.  The
monotone accounted ledger $K(T)$ is mutable protocol state and is deliberately
\emph{not} a component of the approved tuple.
\end{definition}

The release/dependency algebra treats a FactID as a semantic object and its SHA-256 as only a database
index.  Its semantic environment is
$\Pi=\langle pg,\mathcal T,UTC,\mathcal C,D,h_C\rangle$: a PostgreSQL major
version, admitted type domain, timezone, exact deterministic collation
name/version map, immutable snapshot map, and catalog/lineage digest.  A
judgment is defined only for an \emph{admissible} $\Pi$: source schemas and
entity keys are attested, every collatable field has a deterministic collation,
and volatile expressions are absent.  Let $\nu$ be a catalog-owned source
namespace (not a view alias), $s$ an immutable snapshot, $e$ a canonical stable
entity key, $a$ a role-qualified field ID, $\tau\in\mathcal T$, and
$C_\tau(v)$ its typed canonical value.  Base identities are

\begin{align}
 f_{row}&=\langle\pi,\nu,s,e\rangle,\\
 f_{cell}&=\langle\pi,\nu,s,e,a,\tau,C_\tau(v)\rangle .
 \label{eq:fact}
\end{align}

A derived identity is
$f_d=\langle\pi,\mathcal B,k_o,N_\pi(x),\tau,C_\tau(v),CW(W)\rangle$,
where $\mathcal B=\operatorname{sort}\{(\nu,s)\}$ is the relation's snapshot
bundle, $k_o$ is the canonical output-row entity key, $N_\pi(x)$ erases aliases
and normalizes the supported expression, and
$W:\facts_{base}\rightharpoonup\mathbb N^+$
is a finite-support witness multiset (the empty support is allowed).  The product identity is not a caller-supplied
name: it is exactly the namespace projection of $\mathcal B$.  The witness
commitment $CW(W)$ length-prefixes the lexically sorted
$(\operatorname{FactHash}(f),W(f))$ pairs; the empty multiset has a separate
token. The durable key is
$\mathrm{SHA256}(d_R\|\operatorname{Canon}(f))$, where $d_R$ is the
release/dependency domain separator.
Control PostgreSQL stores $\operatorname{Canon}(f)$ and compares it on every
hash conflict; a same-hash, different-payload row aborts the transaction.
Predicate atoms and composite outcomes use disjoint tagged kinds under the
outcome domain separator $d_O$.

Let $N(q)$ be the accepted query normal form, $h_N$ its SHA-256, $m$ the
visible row count, $h_y$ the canonical result-observation commitment, and
$h_c$ the predicate-context commitment to the approved Catalog, immutable
publication/lineage, stable roles, and resolved expressions. Atomization
normalizes each accepted literal occurrence by PostgreSQL type, collation
name/version, operator, and canonical literal value. After exact
deduplication, let $k_a=\code{PREDICATE\_ATOM}$ and define semantic atom
objects before their physical keys:
\begin{equation}
 \begin{aligned}
 a_i&=\langle k_a,\pi,h_c,p,r,f,e,\tau,\kappa,op,v\rangle,\\
 A(q)&=\{a_i\mid a_i\in\operatorname{Atomize}(q)\}.
 \end{aligned}
 \label{eq:predicate-atoms}
\end{equation}
Here $p,r,f,e$ are the semantic Product, stable role, public FieldID, and resolved-expression
digest; $\tau,\kappa,op,v$ are type, collation, operator, and canonical
literal. For any outcome Fact $f$, its physical key is
$\operatorname{FactHash}_O(f)=H(d_O\|\operatorname{Canon}(f))$.
Let $h_A$ commit the sorted $\operatorname{FactHash}_O$ values of $A(q)$ and
$k_c=\code{COMPOSITE\_OUTCOME}$. BDG creates one semantic composite object
\begin{equation}
 \begin{aligned}
 c_q&=\langle k_c,\pi,\operatorname{profile}(N),h_N,h_y,m,h_c,h_A,|A(q)|\rangle,\\
 \facts_O(q)&=A(q)\cup\{c_q\},\\
 M_O(q)&=\{\operatorname{FactHash}_O(f)\mid f\in\facts_O(q)\}.
 \end{aligned}
 \label{eq:outcome-fact}
\end{equation}
Thus repeated literals and supported rewrites reuse atom identities, while the
composite commits to the complete normalized query, exact result observation,
and the complete atom set. The Merkle radix set stores $M_O(q)$; Control
PostgreSQL stores each canonical Fact payload and fails closed on a same-hash,
different-payload collision. Empty results and scalar zero remain explicit.
The signed grant bounds raw literal occurrences, unique atoms, one atom
payload, and total atom payload before settlement.

\begin{theorem}[Fact identity well-definedness]
\label{thm:fact-identity}
For every value in the supported PostgreSQL type domain, canonical encoding
is deterministic and injective over the typed semantic payload (that is, over
PostgreSQL semantic-value equivalence, not raw float NaN bit patterns).
\end{theorem}
\emph{Proof in the supplement.}

\begin{definition}[Exposure effect]
For query $q$ over snapshot $D_s$, the exposure effect
$\effect(q,D_s)=\langle \facts_R,\facts_D,\facts_O\rangle$ contains accounted
result facts (retaining the wire label \code{release})
$\facts_R$ and positive-output dependency-footprint facts $\facts_D$ under a
versioned profile $\pi$.  The latter are the conservative base facts selected
by the inductive rules below for successfully derived selected output rows and
cells; they are not claimed to be minimal causal provenance or all physical reads.
$\facts_O=A(q)\cup\{c_q\}$ contains the predicate footprint and composite
query/result identity from Eqs.~\eqref{eq:predicate-atoms}--\eqref{eq:outcome-fact}.
\end{definition}

For a successful $q$, settlement commits the complete candidate Result set,
whereas publication is later and recoverable:
$F_R^{\mathrm{available}}(q)\subseteq F_R^{\mathrm{accounted}}(q)
=F_R^{\mathrm{candidate}}(q)$. Download is untracked, so accounting only
upper-bounds availability and actual observation; it asserts neither occurred.

\begin{definition}[Task-scoped cumulative exposure]
\label{def:task-exposure}
Let $Q=\langle q_1,\ldots,q_n\rangle$ be a finite query-attempt history for a
root and its descendants, and let $Q^+\subseteq Q$ contain exactly the queries
that successfully settle under $T$. For $X\in\{R,D,O\}$,
$\facts_X(q,S)$ denotes the component obtained on the dataset and profile
transitively bound by $S$ and $C$. The task exposure is
\begin{equation}
 \begin{aligned}
 E(T,Q)&=\langle E_R(T,Q),E_D(T,Q),E_O(T,Q)\rangle,\\
 E_R(T,Q)&=\bigcup_{q\in Q^+}\facts_R(q,S),\\
 E_D(T,Q)&=\bigcup_{q\in Q^+}\facts_D(q,S),\\
 E_O(T,Q)&=\bigcup_{q\in Q^+}\facts_O(q,S).
 \end{aligned}
 \label{eq:task-exposure}
\end{equation}
The components are respectively accounted result exposure (wire label
\code{release}), positive-output dependency
footprint, and query-outcome exposure. Failed or rejected attempts contribute
no set because BDG releases and commits none of their effects; this model
does not account the rejection bit. We abbreviate the singleton history by
$E(T,q)$.
\end{definition}

For every root task, the ledger service separately stores previously accounted
sets $K(T)=\accounted_T=\langle\accounted_T^R,\accounted_T^D,
\accounted_T^O\rangle$ and the approved limits
$B=\langle B_R,B_D,B_O\rangle$. Settlement computes

\begin{align}
 \Delta_T^R(q) &= \facts_R(q,D_s)\setminus\accounted_T^R,\\
 \Delta_T^D(q) &= \facts_D(q,D_s)\setminus\accounted_T^D,\\
 \Delta_T^O(q) &= \facts_O(q,D_s)\setminus\accounted_T^O.
 \label{eq:delta}
\end{align}

BDG measures cardinality independently in each dimension. A query may settle
only if
$|\accounted_T^R|+|\Delta_T^R|\leq B_R$ and
$|\accounted_T^D|+|\Delta_T^D|\leq B_D$ and
$|\accounted_T^O|+|\Delta_T^O|\leq B_O$.

\subsection{Exposure Profiles as Clearance Manifests}
\label{sec:clearance-profile}

\begin{definition}[Profile-relative clearance exactness]
\label{def:profile-relative-exactness}
For an approved $T=(P,S,B,C)$, $C$ binds one versioned Exposure Profile $\pi$.
For any admissible $\Pi$ and successful query in the closed language, write
$\facts_X^\pi(q)$ for the existing component $\facts_X(q,S)$ with its profile
binding made explicit. BDG exactly computes the canonical Result, Dependency,
and Outcome sets $\facts_R^\pi(q),\facts_D^\pi(q),\facts_O^\pi(q)$ and their
componentwise novelty
\[
 \Delta_T^X(q)=\facts_X^\pi(q)\setminus\accounted_T^X,
 \qquad X\in\{R,D,O\}.
\]
This is governance/accounting exactness under the signed contract and closed
semantics. FactIDs are governance accounting identities, not estimates of
semantic information content. The definition does not compute total semantic
information gain, differential-privacy loss, an agent knowledge state, or a
complete side-channel account. BDG does not estimate total information learned
by an agent or measure knowledge leakage; it prevents unaccounted governed
release under a task-bound, versioned exposure profile.
\end{definition}

The six obligations separate assurance layers: O1--O4 are semantic/theorem
claims, O5 combines separate bounded models with transaction tests, and O6 is a
binding obligation. No bounded model or test alone proves the implementation.

\begin{enumerate}
\item[\textbf{O1}] \textbf{Output coverage.} For successful result bag $R$ and
requested fields $V$, every selected cell $(t,a)\in R\times V$ satisfies
$\operatorname{mat}(R,t,a)\in\facts_R(R,V)$ by Eq.~\eqref{eq:observe}.
Normalization may merge equal identities, so coverage is not row count;
\code{SELECT id} and \code{SELECT id,revenue} differ.
\item[\textbf{O2}] \textbf{Positive dependency coverage.}
$\facts_D^\pi$ is exactly the declared inductive footprint, including retained
predicate fields, join-key annotations, group keys, and complete aggregate
arguments; it excludes rejected rows and non-output pages under this profile.
\item[\textbf{O3}] \textbf{Conservation.} The listed normal-form rewrites,
projection splits, complete page partitions, idempotent overlaps/retries, join support,
and root-ledger delegation cannot reduce cumulative charge. This covers the
stated aliases and join parenthesizations, not arbitrary SQL equivalence.
\item[\textbf{O4}] \textbf{Probe capacity.} Each success creates one composite
and canonical predicate atoms; exact replay reuses them, while a changed
canonical predicate component or normalized query/result observation changes the corresponding
identity except for collision. Zero/empty results remain outcomes. Cardinality
is governance capacity, not entropy; one atom is not one bit of privacy loss.
\end{enumerate}

\begin{property}[O5: No unaccounted governed release]
\label{prop:no-unaccounted-release}
Let $\mathsf{AVAILABLE}(q)$ mean that $q$'s canonical artifact has reached the
\code{AVAILABLE} state. For every modeled query and $X\in\{R,D,O\}$,
\[
 \mathsf{AVAILABLE}(q)\Longrightarrow
 \facts_X^\pi(q)\subseteq\accounted_T^X
 \ \wedge\ |\accounted_T^X|\leq B_X.
\]
\end{property}
Execution and private staging are not release. Settlement may leave an artifact
\code{PENDING}, so the converse is false; rejection cannot create
\code{AVAILABLE}. Evidence combines separate bounded
\code{ArtifactPublication.tla}/\code{ExposureLedger.tla} safety with Control-PG
fault-injection, receipt, and availability tests, not a mechanized composition.

\textbf{O6: Profile binding.} $C$ binds effect/normal-form profiles,
type/collation, View contract, replay identity, and result handling. Derivation,
settlement, and replay revalidate one task/Catalog/publication/dictionary
context, which audit/receipt evidence also binds; changes cannot reuse the old
semantic replay. The receipt directly carries the profile version and binds
the full environment transitively through the signed Grant and the receipt's Catalog,
observation, dictionary-set, and component-set digests; there is no
\code{profile_digest} field.

\textbf{Three-way reconciliation.} BDG links (i) the effect manifest---three
candidate sets, observation, profile, and publication; (ii) root-ledger heads,
novelty, bounds, and settlement; and (iii) artifact hashes, \code{PENDING}
intent, receipt, canonical verification, and availability audit. These are not
independent truths: \code{AVAILABLE} must identify the same settled observation
and intent. Hash/binding mismatch or missing audit fails closed; neither the
receipt alone nor an availability event without settlement suffices.

\begin{theorem}[Outcome separation and replay]
\label{thm:outcome-separation}
For successful queries in one predicate context, exact replay and supported
equivalent rewrites produce the same atom set and composite identity and hence
zero incremental Outcome charge. Changing one canonical predicate component
changes that atom except with a SHA-256 collision; changing the complete normal
form or result observation changes the composite except with a collision.
Consequently related probes reuse unchanged atoms but charge each novel atom
and novel composite exactly once, including for zero/empty answers.
\end{theorem}
\emph{Proof in the supplement.}

\subsection{Closed Typed Query Language}

Operational multi-source SQL first lowers to
$G_J=\langle V_J,E_J,\Theta_J\rangle$: $2$--$16$ distinct Catalog stable-role
nodes and connected equality edges. Stable-role ordering and a deterministic
fold erase aliases and accepted parenthesization, so the same connected graph
has one core term. Repeated roles, self edges, duplicate equalities, and type or
collation disagreement reject; the operational bounds and construction are
supplemental.

The complete core syntax is
\begin{align*}
e ::= {}& \operatorname{Scan}[\nu,s,r,\Gamma]
 \mid \sigma_{p;F}(e) \mid \pi_A(e) \mid e\bowtie_{\Theta}e \\
 &\mid e\cup_\delta e \mid \gamma_{G;\mathcal A}(e)
 \mid \operatorname{Page}_{O,K,o,l}(e),\\
p ::= {}& b \mid p\wedge b,\qquad b ::= a\;op\;c,\\
op\in {}&\{=,\ne,<,\le,>,\ge\}
 \cup\{\code{LIKE},\code{IN},\code{NOT IN}\},
\end{align*}
where $F$ is exactly the fields read by $p$, $\Theta$ is a nonempty
conjunction of equalities, $\cup_\delta$ is union-distinct, and
$\mathcal A\subseteq\{\code{COUNT(*)},\code{COUNT},\code{SUM},\code{MIN},
\code{MAX}\}$.  No implicit SQL construct is hidden in $e$: outer joins,
difference, negation beyond the listed scalar predicates, windows, recursion,
subqueries, volatile functions, and \code{UNION ALL} are not terms.

The partial judgment $\Pi\vdash e:\Gamma$ enforces child-local fields,
role-disjoint typed joins, identical distinctable union schemas, typed grouping,
and a proven total page order. Undefined premises reject. Complete syntax,
typing, and resource guards are supplemental.

The nested-View front end lowers a bounded acyclic DAG of projection/rename,
inner equijoins, literal conjunctions, and optional grouping into this core. It
admits one aggregate barrier and rejects richer SQL or unsafe dependencies; no
general PostgreSQL View-equivalence result is claimed.

Predicates use PostgreSQL three-valued logic and retain only true rows, whereas
grouping/distinct use typed \code{IS NOT DISTINCT FROM}. The closed canonical
domain fixes integer/float widths, exact numeric and temporal encodings,
deterministic collation name/version, \code{jsonb} structural equality, and
PostgreSQL aggregate result types. Non-associative
floating SUM, unsupported casts, and overflow are undefined and settle
nothing; the complete type domain and encoders are supplemental.

\subsection{Annotated Bags and Complete Output Keys}

A relation is a typed PostgreSQL bag with unique occurrence keys and optional
proven total order. Rows and cells carry support $S$, positive witness
multiset $W$, canonical lineage, and optional materialized release identity.
Every operator preserves
\begin{equation}
 \operatorname{support}(W_r)=S_r,\qquad
 \operatorname{support}(W_a)=S_a.                 \label{eq:anninv}
\end{equation}
Same-proof composition unions support and adds multiplicities; alternative
proofs union support and take pointwise maximum. Thus alternatives are
idempotent while join fanout remains visible.

Let
\begin{equation}
 \operatorname{RID}(R,t)=H(\code{relation-row},N(\Gamma),\mathcal B,t.k).
 \label{eq:rid}
\end{equation}
$H$ is typed, length-delimited, and domain-separated. Scan uses the Catalog
entity key; unary operators preserve keys; join, union-distinct, and group bind
their complete canonical child/class/group identities. Derived Facts also bind
source/snapshot, expression, value, and witness. Complete key construction and
collision checks are supplemental.

\subsection{Operator Evaluation and Effect Extraction}

Evaluation is the partial judgment $\Pi;D\vdash e\Downarrow R$; ``partial''
means that a failed premise yields no relation, effect, settlement, or release.
For compactness, $\alpha_r(t)=(S_r,W_r)$,
$\alpha_a(t)=(S_a,W_a)$, $\operatorname{aug}_F(t)$ replaces
$\alpha_r(t)$ by $\alpha_r(t)\oplus\bigoplus_{a\in F}\alpha_a(t)$, and cell
maps are otherwise copied.  In the derived rules a cell is written as the
5-tuple $c_a=\langle v_a,\tau_a,\alpha_a,x_a,\rho_a\rangle$: value, type, the
annotation pair $\alpha_a=(S_a,W_a)$ that expands to support and witness, the
normalized lineage expression, and the optional materialized release fact.
E-Scan alone displays the fully expanded base-cell 6-tuple; every other rule
constructs each output cell explicitly, so representation closure does not rely
on prose. Table~\ref{tab:effect-summary} retains the review-relevant accounting
choices; the complete inference rules, auxiliary functions, NULL/empty-input
cases, and page bounds are in the supplementary material.

Finally, define materialization and the effect---they are not an implementation
afterthought:
\begin{align}
\operatorname{new}(R,t,a)&=
 f_d(\mathcal B,t.k,N(x_a),\tau_a,v_a,W_a),\\
\operatorname{mat}(R,t,a)&=
\begin{cases}
\rho_a,&\operatorname{valid}(\rho_a,R,t,a),\\
\operatorname{new}(R,t,a),&\text{otherwise},
\end{cases}\\
\facts_R(R,V)&=\{\operatorname{mat}(R,t,a)\mid t\in R,\ a\in V\},\\
\facts_D(R,V)&=\bigcup_{t\in R}S_r(t)\ \cup
                \bigcup_{t\in R,a\in V}S_a(t),\\
\rieffect_\Pi(e,D,V)&=\operatorname{normalize}
  \langle\facts_R(R,V),\facts_D(R,V)\rangle.       \label{eq:observe}
\end{align}
Here $\Pi;D\vdash e\Downarrow R$, and $\operatorname{valid}$ checks value,
type and bundle, plus support for a base fact or expression/witness for a
derived fact, against the pre-existing release fact.
Thus query bags and witness multiplicity are retained during composition, while
the two base ledgers are sets.  Equation~\eqref{eq:observe} is the declared
positive-output dependency-footprint profile: it is exact with respect to these
inductive rules, not with respect to arbitrary causal provenance or physical
source access.  Empty answers have an empty base effect except for the single
visible row of a global aggregate; BDG nevertheless adds the tested predicate
atoms and one composite outcome.

\begin{theorem}[Representation closure and partial-function semantics]
\label{thm:representation-closure}
For every admissible $\Pi$, typed finite $e$, and immutable $D$, evaluation has
at most one result.  If $\Pi;D\vdash e\Downarrow R$, $R$ satisfies
Eq.~\eqref{eq:anninv}, has canonical schema/bundle and unique row keys, and is a
valid input to every well-typed parent rule.
\end{theorem}
\emph{Proof in the supplement.}

\begin{theorem}[Dependency determinism]
\label{thm:dependency-determinism}
Fixed admissible $\Pi$, typed $e$, snapshot map $D$, and visible field set $V$
uniquely determine the positive-output dependency-footprint FactSet $\facts_D$, and hence
$\rieffect_\Pi(e,D,V)$, whenever evaluation succeeds.
\end{theorem}
\emph{Proof in the supplement.}

Group-key, union-distinct, and aggregate-input completeness statements and

\subsection{Conservation Properties}

The following properties apply only to the operators and rewrites stated here.
They are not claims about all semantically equivalent SQL.

The supplement proves deterministic/idempotent Fact-set normalization and the
restricted selection--projection invariance used by the rewrite tests.

\begin{definition}[Profile-indexed typed normal form $NF_{\Pi,\pi}$]
\label{def:nf}
$NF_{\Pi,\pi}$ maps accepted, well-typed inputs to canonical terms under the
normal-form profile fixed by the task contract. Multi-source SQL
replaces aliases by Catalog stable roles, canonicalizes the accepted join
graph, and recursively orders all commutative components by typed stable
identity. Equality is syntactic; the complete ordering, scalar domains, and
rejected constructs are supplemental. The task contract binds exactly one
normal-form profile; no alternative is selected at query time.
The complete typed digest is the query-semantic component of replay/outcome
identity; authorization and settlement additionally bind grant, policy, and
effect context. Query normalization is distinct from final-ledger Fact-set
$\operatorname{normalize}$.
\end{definition}

\begin{theorem}[Typed normal-form soundness]
\label{thm:nf-soundness}
For admissible $\Pi$, fixed profile $\pi$, immutable snapshot map $D$, $q_1,q_2$ in the closed
algebra or accepted graph-lowerable SQL fragment, and the same visible field
set $V$,
\[
 NF_{\Pi,\pi}(q_1)=NF_{\Pi,\pi}(q_2)\Longrightarrow
 \effect_\Pi(q_1,D,V)=\effect_\Pi(q_2,D,V).
\]
This is not completeness for arbitrary equivalent SQL: normalization neither
invents nor removes transitive/redundant equalities.
\end{theorem}
\emph{Proof in the supplement.}

For a fixed approved task, let $\pi_T$ be the normal-form profile bound in
$C$ and define the canonical replay descriptor
\begin{equation}
 \operatorname{RK}_T(q)=\langle P,S,C,\pi_T,NF_{\Pi,\pi_T}(q),
     \operatorname{params}_\Pi(q),\operatorname{encver}\rangle,
 \label{eq:replay-descriptor}
\end{equation}
where every component uses the typed, length-delimited encoding already bound
by the Grant and Catalog. The implementation indexes a digest of this
descriptor but verifies the bound metadata before accepting a hit.

Descriptor equality fixes the approved policy, publication, effect/View
contracts, typed parameters, and normal form; hence it fixes all three effect
sets and exact replay has zero novelty. The converse is not claimed outside the
stated normalization rules.

Let $\operatorname{Expand}_C(v)=(e,\mu,\beta_v)$ denote successful compilation
of a semantic-View root $v$ into a closed core term $e$, with $\mu$ mapping its
ordered public fields to stable terminal FieldIDs. The binding $\beta_v$
commits the root Product/public-field identity, resolved expressions, signed
View contract, and predicate context. Compilation defines the View query
normal form from $e$ while retaining $\beta_v$ in $C$.

For successful $\operatorname{Expand}_C(v)=(e,\mu,\beta_v)$, induction over the
accepted acyclic View DAG preserves the typed visible bag and all three effect
sets when the internal query retains $\beta_v$. Exact guards and the proof are
supplemental; a direct terminal query can carry different Outcome FactIDs.

\begin{theorem}[Base-ledger split/page/join conservation]
\label{thm:base-conservation}
Merging release/dependency observations for disjoint projections or a complete
page partition equals observing the combined result. Overlapping pages and
repeated terminal observations charge each release/dependency FactID at most
once; join fanout changes witness multiplicity but not the union of dependency
support. Composite facts remain per normalized query/result outcome;
predicate atoms are reused exactly when their canonical footprint components
agree, so a family of page or threshold questions does not collapse wholesale.
\end{theorem}
\emph{Proof in the supplement.}

Besides the rewrites above, the profile binds namespace, snapshot, lineage digest,
canonical SQL types, collation
names/versions, PostgreSQL three-valued bag semantics, UTC, and exact numeric
mode. It deliberately performs no outer-join, arithmetic, window, subquery, or
general SQL equivalence reasoning.

\section{Online Accounting}
\label{sec:online}

Formal semantics and the independent oracle cover scan/select/project, group
with four aggregates, inner equijoin, union-distinct, and page. Online lowering
admits one product, a connected 2--16-source equi-join graph, or two-branch
union-distinct, optionally grouped. The SQL-AST path covers the first two;
the semantic-View path first eliminates a bounded nested DAG into the same
first-two forms. Union is structured-plan only and pagination is one-product only. Paired
PostgreSQL tests derive effects for hidden keys, join fanout, union members,
aggregates, and page withholding; ``online'' does not mean arbitrary SQL.

\subsection{Canonical Join and Semantic-View Lowering}

For joins, the PostgreSQL AST and Catalog types feed the canonical $G_J$
builder, which emits existing \code{JoinMany} and the deterministic binary
SQL/effect fold. Accepted topology and parenthesization are otherwise
unrestricted within the bound; unsupported joins, set trees, and pagination
fail closed. Callers cannot supply roles, SQL fragments, FactIDs, or
provenance.

For semantic Views, one catalog snapshot checks exact definitions,
type/collation interfaces, and dependency edges, expands safe acyclic Views to
Catalog-mapped materialized leaves, and emits the same core. Four digests bind
root definition, dependency closure, canonical plan, and public interface into
the Grant and query. Recompilation plus a same-snapshot connector check detects
drift and requires a new approval. Execution resolves stable outputs and
least-privilege terminal scopes before reservation. Expansion guards and
lowering rules are supplemental.

\subsection{Snapshot Publication and Ordinal Compilation}

The publication compiler turns each frozen snapshot into immutable per-row/per-field segments,
sorting full Fact hashes and assigning 32-bit ordinals. A sidecar maps attested
entity keys to ordinals; the hot artifact keeps this map and verified hashes,
while canonical payloads remain content addressed and cold. One manifest binds
snapshot, schemas, sidecar, dictionaries, versions, type/collation contracts,
and digests; any collision or count/canonicality mismatch blocks publication.

The online compiler emits visible SQL and an ordinal companion in one read-only
\code{REPEATABLE READ} transaction. The visible
result is buffered; the ordered companion retains every dependency required by
join, union, group, and aggregate rules.

The engine keeps current-group support, sparse extra multiplicities, and query
bitmaps. A k-way hash merge reproduces the algebraic witness commitment;
Release/dependency use segmented Roaring bitmaps, while Outcome hashes enter
an exact Merkle radix set. Invalid handles, manifests, encodings, overflow, or
truncation fail closed. The materialized algebra remains the oracle.

For each segment, publication defines a FactID--ordinal bijection $D_j$;
portable Roaring compression changes representation, not membership
\cite{chambi2016roaring}.

\begin{theorem}[Exact bitmap refinement]
\label{thm:bitmap-refinement}
For canonical bitmaps $A$ and $B$ in one dictionary segment,
$\operatorname{Decode}(A\mathbin{\mathrm{OR}}B)=
\operatorname{Decode}(A)\cup\operatorname{Decode}(B)$,
$\operatorname{Decode}(A\mathbin{\mathrm{ANDNOT}}B)=
\operatorname{Decode}(A)\setminus\operatorname{Decode}(B)$, and
$\operatorname{popcount}(A)=|\operatorname{Decode}(A)|$. For every successful
query in the closed online algebra, decoding the streamed bitmap components
yields exactly the release and dependency components of $\effect(q,D_s)$.
\end{theorem}
\emph{Intuition.} Bijective decoding turns OR, ANDNOT, and popcount into exact
set operations; induction over the closed algebra then substitutes ordinals
for singleton facts without changing support or witness commitments. The full
proof is in the supplement.

For Outcome, hash prefixes route immutable, content-addressed leaves and
blocks, but membership always compares the full SHA-256 value. Physical
leaf/block encodings are supplemental.

\begin{theorem}[Exact incremental Outcome-set refinement]
\label{thm:outcome-radix-refinement}
Let $K_O$ be a valid Outcome root and $C_O$ a canonical candidate. Loading every
leaf family whose 16-bit prefix occurs in $C_O$, performing full-hash exact
difference/union within those families, rebuilding only their containing
blocks, and reusing all other references yields
$\operatorname{Decode}(K'_O)=\operatorname{Decode}(K_O)\cup C_O$ and charges
$C_O\setminus\operatorname{Decode}(K_O)$ exactly. Any changed member, count,
prefix, chunk, block, or root manifest changes a verified digest except with a
SHA-256 collision.
\end{theorem}
\emph{Intuition.} Prefix routing partitions the full-hash universe; therefore
an inserted candidate can affect only its own partitions. Exact comparison is
still over all 256 hash bits, while the Merkle path authenticates reused
partitions. The refinement does not use truncated hashes as membership keys.

\subsection{Atomic Ledger Settlement and Fail-Closed Artifact Publication}

For one successful query, the enforcement layer performs the following steps
(Fig.~\ref{fig:architecture-settlement}b):

\begin{enumerate}\setlength{\itemsep}{0pt}
\item Reauthorize and reserve resources; semantic replay lookup follows signed
grant/publication binding.
\item On a miss, execute visible and ordinal statements in one Business-PG
snapshot, derive all three effects, and stage encrypted Parquet. A hit loads an
already committed observation/materialization. Staging is never AVAILABLE.
\item In one Control-PG transaction, compute exact bitmap/full-hash novelty
against the root head, reject any $B_X$ excess, and CAS all three manifests;
conflicts reread and recompute every dimension.
\item The same transaction settles resources, observation/effects, PENDING
intent, terminal/registration audit, and the signed receipt.
\item Verify promotion to the canonical object, then co-commit AVAILABLE and
\code{QUERY\_RESULT\_CONSUMED} in a second transaction before returning the ID.
\end{enumerate}

Only root heads are mutable. Pre-settlement failure rolls back heads,
observations, PENDING intent, audits, cache, and receipt; any leftover staging
object stays unavailable. After settlement, promotion failure neither refunds
nor re-executes: recovery verifies the canonical digest and resumes the
charged/PENDING artifact idempotently. Within its bound context,
$(\code{root_task_id},\code{observation_sha256})$ then identifies zero-novelty
replay without rescanning effects.

The boundaries remain distinct: \emph{accounted} means settlement committed,
\emph{available} means canonical promotion plus consumption audit, and
\emph{observed} means an untracked download. Thus
$\mathsf{Observed}\subseteq\mathsf{Available}\subseteq\mathsf{Accounted}$ and
$\mathsf{Available}\Rightarrow\mathsf{Settled}$, but not conversely.

Unlike request idempotence, semantic replay binds task/grant, typed normal
form/parameters, Catalog/schema/publication/dictionaries, and all profile and
encoding versions. A hit skips Business/provenance SQL but reauthorizes,
charges resources, audits, receipts, and re-encrypts; any mismatch or failed
verification takes the novel path. Because $P_{e+1}$ changes publication
bindings, new tasks cannot hit $P_e$ entries, which remain only for retained
$P_e$ roots.

\subsection{Receipts and Failure Semantics}

A signed Ed25519 settlement receipt binds accounting evidence, result/object
metadata and hashes, the expected \code{PENDING} intent, and registration audit;
it exposes no raw values or FactIDs. Availability separately requires the
hash-chained \code{QUERY\_RESULT\_CONSUMED} inclusion. The normal path
co-commits the receipt; a recovered attestation may postdate settlement, but
both authenticate only the same PENDING intent. Signed Grant/query View binding
and a dedicated receipt domain prevent replay across that identity.

Failures before connector invocation release reservations. Over-budget
settlement creates no canonical object or AVAILABLE row; transient private
staging remains unavailable. Ambiguous connector outcomes charge ordinary
resources but no exposure without settlement. Terminal replay returns the first
status, may resume PENDING promotion, and never repeats Business execution.

Withholding the buffer does not hide the decision bit. Whether settlement
accepts a query reveals whether its data-dependent novel Effect fits the
remaining budgets, and a rejected Effect is not committed to any ledger
dimension. Thus rejection can act as an uncharged threshold oracle. The current
protocol is not a simulatable auditor and makes no denial-noninterference claim.

\section{Delegation}
\label{sec:delegation}

\subsection{Root-Family Conservation}

A child authorization signs both \code{root_task_id} and
\code{parent_task_id}. Its human subject, catalog, datasource, schema, and
profile remain fixed, while products, columns, scopes, sensitivity, expiry, and
all budget dimensions may only narrow. Every execution revalidates the signed
parent grant and active ancestor chain.

View-bound descendants inherit the parent's complete original contract set;
their approved subset cannot add or replace a contract, so narrowing is not an
implicit semantic rebind.

All descendants resolve to one root ledger. If a parent and child request the
same fact, only the first successful settlement accounts it. Revoking the root
blocks new descendant queries, while an already terminal request ID remains
readable. Consequently, creating workers or task nodes cannot create fresh
exposure capacity. A child that signs a lower exposure ceiling may add novel
facts only while the shared family total remains within that ceiling; a
zero-novelty replay remains admissible.

This conservation scope stops at the root boundary. A second root task for the
same principal has an independent ledger and therefore a fresh budget if a
human approves it. The prototype has no principal-, tenant-, or organization-
wide exposure ledger, so neither delegation monotonicity nor the theorem below
prevents cross-root accumulation.

The boundary also stops at a publication epoch. The ledger subject is the pair
$(T,P_e)$, not a permanent model of the user's knowledge. A new $P_{e+1}$ is
available only to a newly approved root with a new ledger; an existing root
continues against $P_e$ through a retained version route (or fails closed if
that route is unavailable), and its ledger is neither copied nor migrated. Because
snapshot identity is part of FactID identity, unchanged business content may
be accounted again after independent approval in $P_{e+1}$. This conservative
choice deliberately avoids cross-publication deduplication. Such accounting
would require a principal- or tenant-wide semantic identity and policy, outside
the task-scoped guarantee.

\begin{theorem}[Atomic root-family budget safety]
\label{thm:root-family-safety}
For an approved task $T=(P,S,B,C)$ and any committed query history $Q$, each
$X\in\{R,D,O\}$ in the decoded root head satisfies
\[
 K_X(T)=E_X(T,Q),\qquad |K_X(T)|\le B_X.
\]
This statement is independent of whether $K_X$ is materialized as FactID rows
or represented by immutable dictionary bitmaps.
\end{theorem}
\emph{Proof sketch.} Induct on committed settlements. The initial head and
$E(T,\langle\rangle)$ are empty. For the next successful query, exact set
difference computes novelty against the inductive head; one transaction checks
all three cardinalities and one CAS publishes
$K_X(T)\leftarrow K_X(T)\cup E_X(T,q)$. A conflicting transaction retries from
the newly published head, and a rejected or failed attempt changes no head.
Every descendant resolves to this same head. Thus the committed head equals the
componentwise union in Eq.~\eqref{eq:task-exposure}, and the pre-commit checks
preserve every component bound. The representation-refinement details are in
the supplement.

\section{System Realization}
\label{sec:system}

The Go prototype uses separate Control and Business PostgreSQL 16 databases.
Its Catalog declares reporting Views, mandatory scopes, immutable publications,
entity keys, operations, approval routes, and profiles. Terminal Products bind
source, schema, snapshot, ordinal artifacts, and digests; semantic-View Products
carry the four-digest contract and must close on governed materializations.
Startup and per-query attestation verify these bindings. Each service instance
is Catalog-bound, so rollover routes old roots to retained $P_e$ instances and
new approvals to $P_{e+1}$; active tasks never change in place.

MCP tools cover Product discovery, task approval/execution/delegation, View
rebind, budgets, results, and receipts; an external adapter signs Grants.
Direct SQL is lowered to the same canonical plan under every grant and fails
closed when it cannot be, so no path executes agent-authored text; a
resource-only grant differs in accounting, not in accepted syntax. Control PostgreSQL persists versioned set metadata, a
three-dimensional root head, observations, and monotonic View bindings;
canonical payloads remain cold. Results use AES-GCM, audits a hash chain, and
high-cardinality work an isolated semaphore and encrypted spill path.

Reference-safe retention and reclamation are specified in the supplement;
stored ledger identities are never silently reinterpreted.

\textbf{Threat and governance boundary.}
The agent, plans, retries, pages, and delegation are untrusted. BDG trusts
authenticated identity and organizational-attribute assertions; approval,
Catalog, and Exposure-Profile authorities; the immutable publication pipeline;
Business PostgreSQL execution semantics; the enforcement service and Control
database; and cryptography, key-management configuration, and object-store
access control. Crashes, concurrency, stale bindings, replay, and promotion
failure are in scope; compromised or malicious trusted authorities, direct
bypass, colluding independent roots, and external-tool leakage are not. BDG
enforces an approved organizational policy; it does not autonomously determine
whether that policy is appropriate.

\textbf{Governance responsibility.}
Data owners decide business purpose and releasable scope; security and privacy teams define sensitive
fields and prohibited combinations; IAM/HR and OA/BPM attest identity,
organization, and approval chains. DBAs and data engineers validate tables,
Views, stable keys, types, collations, and performance mappings; BDG validates
structure, versions, and supported semantics, then compiles and enforces the
signed contract; auditors reconcile approval, settlement, receipt, and
AVAILABLE evidence. Thus DBAs validate database facts, owners decide
permission, security defines boundaries, and BDG enforces the supported signed
portion; broader flow policy remains a separate DFC or equivalent
responsibility.

\section{Three-Layer Assurance}
\label{sec:formal}

Paper theorems establish representation-independent Fact identity,
deterministic effects, exact novelty, and root-family conservation for the
closed algebra; they do not prove the parser or implementation. Four separate
bounded TLC models \cite{lamport2002specifying} check abstract root settlement,
FactSet/bitmap correspondence, exact Outcome-set settlement with collision
fail-closed safety, and PENDING/AVAILABLE recovery. They start after compilation
and abstract away SQL syntax, PostgreSQL rows, concrete hashes/signatures,
networking, and ciphertext.
Executable Go/PostgreSQL differential, concurrency, tamper, and fault-injection
tests check implementation correspondence, including radix partitioning and
object reuse. The supplement maps these layers and their gaps. We claim bounded
model checking plus implementation evidence, neither a combined mechanized
refinement nor a formally verified system.

\section{Limitations and Threats to Validity}
\label{sec:limits}

\textbf{Semantic and subject scope.} Outcome atoms and composites are governance
units, not bits or an inference decomposition. BDG omits rejected rows,
non-output groups/pages, rank-only inputs, timing, correlations, background
knowledge, and physical reads; it provides neither minimal causality nor
differential privacy. Refusal leaks an uncharged threshold bit. Every approved
root or publication has fresh capacity absent external principal/tenant policy;
BDG does not deduplicate durable knowledge.

\textbf{Query and identity scope.} Evidence uses frozen, manifest-proven
publications, not mutable transactional sources or active-root migration. The
stated Product/join/union/View fragment is closed; richer joins, sets, paging,
negation, recursion, and subqueries fail closed, while materialized Views are
opaque leaves. Stable keys and publications remain trusted administrator
declarations. View drift is checked at request, approval, and execution rather
than continuously; rebind is not general equivalence or enterprise-scale
discovery.

\textbf{Governance and deployment scope.} Profile correctness is trusted. BDG
validates structural and version bindings for administrator-attested identities,
plus supported semantics and settlement; it does not decide policy
appropriateness. Its single primary database path and demo approval adapter
provide no production Data Lake/IAM/workflow/SIEM study, integration-cost
measurement, or practitioner study of budget calibration of the kind
marketplace-integrated agents have reported \cite{tonnarelli2026dataproductmcp};
multi-engine connectors and Policy Studio remain future work.
Archived V4 used \RQFourVFourBuildRuns{} build; every run reported here is
single-host. The radix results establish touched-branch I/O shape, not million-scale latency,
sustained contention, distributed behavior, or live-agent performance.

\section{Conclusion}

\system provides profile-relative exact accounting of modeled Result,
Dependency, and Outcome sets within one publication-bound root family. Paper
theorems, separate bounded TLA+ models, and executable tests support the scoped
safety claim: no governed artifact becomes \code{AVAILABLE} before atomic
root-family settlement, although a settled artifact may remain \code{PENDING}.
This is not an account of total knowledge or privacy loss; arbitrary SQL,
mutable transactional sources, cross-publication accounting, and multi-host
latency remain outside scope.

BDG is a task-to-data release layer for existing enterprise data estates, not
another lake or agent framework. It makes governed reporting Products usable
by adaptive agents without broad, persistent database identities.

BDG turns governed data at rest into governed agent capability in use. It does
not determine the correct organizational policy; it makes an approved policy
enforceable as autonomous querying unfolds.

Accounting for Autonomous Database Agents}

\author{Anonymous Author(s)%
\thanks{The artifact includes a controlled local PostgreSQL performance
campaign and a three-scale TPC-H-derived Join--Group campaign. Results remain

\begin{abstract}
Autonomous database agents issue adaptive query sequences and delegate
subtasks. Per-query access control does not bound how many distinct metered
facts a task accumulates across rewrites, pages, retries, and delegation. We
present TaskGate, a prototype for task-bound exposure accounting. Versioned
identities bind product, snapshot, entity, field, and value. Each approved root
task maintains separate release and positive-output-dependency ledgers, so a
small aggregate cannot hide a large conservative footprint.
The online path compiles single-product plans and bounded two-input inner joins
and union-distinct plans into one authorized visible query and a provenance
companion in a shared read-only snapshot, buffers the result, derives both fact
sets, and atomically charges only facts novel to the root ledger before release.
Dependency identities remain server-side evidence; delegation shares the same
ledger. We give compositional semantics for a positive relational fragment
with grouping and four aggregates and check a finite ledger model. An
independent oracle validates \RQOneCases{} cases. Across
\RQTwoExposureRewrites{} closed-language rewrites, release and dependency sets
and incremental charges have \RQTwoExposureMismatches{} mismatches.  Real
PostgreSQL~16 paired-query tests cover join operand exchange, union member
completeness and hidden distinct fields, and downstream grouping. In
three local trials and \RQFourObservations{} operations, a warm full-path
history hit has \RQFourFullOneMedian{}-ms median and
\RQFourFullOneTail{}-ms p95 latency at one worker---\RQFourFullOneRatio{}$\times$
the direct-query median. The mixed ramp measures both novel and hit paths and
records physical ledger bytes. A separate production-settlement campaign grows
the ledger to \RQFourStorageMaxRows{} immutable PostgreSQL rows
(\RQFourStorageTenThousandAllocated{}~MiB allocated); a replay adds zero facts.
A public-endpoint Join--Group campaign reaches \RQFourScaleMaxJoined{} joined
rows and \RQFourScaleMaxFacts{} dependency facts. At that point, novel and
replay requests take \RQFourScaleHighNovelS{} and
\RQFourScaleHighReplayS{}~s median and gateway memory peaks at
\RQFourScaleGatewayGiB{}~GiB, establishing completion at the target fact scale
while exposing a severe latency and memory boundary.
\end{abstract}

\section{Introduction}
\label{sec:introduction}

\IEEEPARstart{D}{atabase} authorization answers whether a principal may execute
a particular operation. An autonomous agent creates a second problem: during a
single human-approved task it can adaptively issue many individually legal
queries. It can split a projection, overlap pages, retry with a new request
identifier, ask an equivalent query, or delegate a narrower subtask. Per-query
authorization and row limits do not state how much distinct data the resulting
root ledger has already accounted. This is not a model of the agent's knowledge.

Counting queries is insensitive to answer size. Counting returned rows makes a
one-row aggregate appear cheap even when it depends on millions of source rows.
Counting bytes or cells varies with encoding and query shape. Monetary query
pricing has developed formal anti-arbitrage objectives
\cite{koutris2012query,deep2017qirana,peng2025aria}, while provenance explains
where results came from \cite{green2007provenance,amsterdamer2011aggregate}.
Our question is narrower and operational: how can a human authorization create
a stateful, explicit-disclosure budget that remains conserved while database
agents query and delegate?

\system treats the root task as the budget subject. A result has two effects.
\emph{Release exposure} identifies values actually delivered.
\emph{Positive-output dependency} is a contract-defined conservative footprint
of base facts participating in the successful derivation of delivered output.
It is neither minimal causal provenance nor the complete physical read set.
This second dimension prevents a count from being accounted as one input fact
merely because it returns one cell. Both effects are sets, so a fact already
recorded in the root-family ledger has zero incremental charge.

The system follows a withhold-before-settlement discipline:

\begin{center}
\small
\code{reserve -> execute/buffer -> derive -> settle -> release}.
\end{center}

The visible query and its provenance companion observe one PostgreSQL snapshot.
The gateway releases neither until a control-database transaction has inserted
novel facts, checked both root limits, settled resource use, stored the encrypted
result, and persisted audit and receipt evidence. A failed limit check rolls the
transaction back while the business execution remains separately measurable.

TaskGate is a direct successor to SessionBound
\cite{wu2026sessionbound}. SessionBound already turns task approval into a
short-lived database session with signed tokens, SQL/view/scope boundaries,
query and disclosure budgets, and allow/deny receipts. We treat that substrate
as prior work and do not claim those mechanisms here. Relative to it, this
paper makes five implementation-backed contributions:

\begin{enumerate}
\item A versioned, typed FactID and dual set semantics separating delivered
release facts from positive-output dependencies in a restricted relational
algebra.
\item A same-snapshot provenance companion for one-product plans and bounded
two-scan inner equijoins/union-distinct, including grouping and four aggregates.
\item Exact novel-set settlement: atomically charge
$E_q\setminus\accounted_T$, withhold on either limit, and make semantic replay
zero-charge rather than merely incrementing a per-query counter.
\item Signed, monotonic root-family delegation whose descendants share one
dual ledger, preventing task-tree fan-out from multiplying exposure capacity.
\item New formal properties and evidence for these mechanisms: dual-budget
safety, exact/non-overlapping novel charge, no pre-settlement delivery, and
task-family non-amplification; algebraic/rewrite tests, a finite TLA+ ledger
model, and full-path PostgreSQL experiments through one million dependency
facts.
\end{enumerate}

The implementation does \emph{not} claim arbitrary SQL equivalence, differential
privacy, inference control, principal-wide accounting, or denial-oblivious
auditing. The online multi-input grammar is intentionally bounded: two scan
leaves, an inner conjunctive equijoin or same-product union-distinct, and no
nested set/join tree or multi-input pagination. A newly approved root creates a
distinct ledger. These boundaries are part of the result, rather than hidden
behind a broad ``SQL support'' label.

\section{Context and Related Work}
\label{sec:related}

\subsection{Closest Systems and Incremental Novelty}

SessionBound is the immediate architectural predecessor
\cite{wu2026sessionbound}. It already contributes the control-plane path from
business task templates and approval to signed task tokens, and a PostgreSQL
runtime enforcing safe views, row scope, denied fields, operation/query and
disclosure budgets, plus receipts. Its disclosure units may be rows, bytes, or
unique entity identifiers. TaskGate therefore does not present task approval,
SQL mediation, cumulative disclosure budgets, or receipts as new. It changes
the accounted object and settlement semantics: values and successful
derivations become stable FactID sets; release and positive-output dependencies
have separate ledgers; the answer and evidence are obtained in one snapshot;
only exact set difference is charged; and all delegated descendants settle one
root-family ledger.

GAAP is the closest system at the agent data-flow layer
\cite{stanley2026gaap}. It places private data and permissions outside the
untrusted model, analyzes agent-generated code with information-flow control,
uses trusted tool annotations, and records disclosures to external entities in
a persistent log. That log propagates taint across calls and tasks, addressing
indirect cross-service disclosure that TaskGate explicitly does not solve.
Conversely, GAAP does not define a SQL value-level FactID algebra, distinguish
delivered database values from positive-output dependencies, co-execute a
PostgreSQL provenance companion, or settle an exact per-root novel FactSet.
Table~\ref{tab:closest-systems} states the boundary without treating different
threat models as an overall ranking.

\subsection{History-Based Query Auditing and Inference Control}

Database auditing has long treated a query log, rather than an isolated query,
as the security object. Hippocratic-database auditing reconstructs which logged
queries accessed protected data \cite{agrawal2004hippocratic}, while batch SQL
auditing asks whether a sequence of answers determines a forbidden view
\cite{motwani2008auditing}. Online auditors decide whether to answer the next
query: early work studies Boolean attributes \cite{kleinberg2003auditing},
simulatable auditing prevents the accept/deny bit itself from leaking the secret
\cite{kenthapadi2005simulatable}, and robust auditing analyzes partial versus
full disclosure under aggregate queries \cite{nabar2006robustness}.

The broader inference-control literature models integrity constraints,
inference channels, and accumulated disclosures \cite{brodsky2000secure}, and
surveys attacks that combine answers with external knowledge
\cite{farkas2002inference}. Query--view disclosure analysis further formalizes
collusion and partial information release \cite{miklau2004formal}. These results
rule out a broad ``history makes querying safe'' claim. \system is deliberately
narrower: it neither models an adversary's prior knowledge nor protects against
negative answers, denial leakage, or implicit logical inference. It meters a
contract-declared set of positive facts, and its history is one signed root task
and all descendants rather than a global user history. Simulatable or
knowledge-aware inference control is complementary and could sit outside the
gateway.

\subsection{Query Pricing and Privacy Accounting}

Query-based pricing derives monetary prices from priced views and studies
arbitrage induced by query determinacy \cite{koutris2012query}. QIRANA extends
scalable, history-aware pricing to a broad SQL class including aggregation
\cite{deep2017qirana}; ARIA uses tuple information gain for linear-time pricing
of SPJA and simple aggregate queries \cite{peng2025aria}. Thus attribute
weighting, history-aware charging, and rewrite resistance are not new by
themselves. \system instead treats price as an admission budget over explicit
contract facts, scopes state to a task family, and withholds delivery when the
atomic settlement fails.

History also matters in differential privacy systems. CacheDP reuses past noisy
answers to reduce privacy spending \cite{mazmudar2022cachedp}, and DProvDB tracks
privacy loss by analyst provenance \cite{zhang2023dprovdb}. These systems reason
about randomized mechanisms and privacy composition
\cite{dwork2014foundations}. \system releases exact answers and therefore offers
no $\epsilon$-DP guarantee; its budget bounds only facts recognized by the
active exposure profile.

\subsection{Provenance Foundations and Systems}

Why- and where-provenance identify contributing data and output locations
\cite{buneman2001why}, while lineage traces warehouse outputs back through
transformations \cite{cui2001lineage}; Cheney et al. survey the resulting
database-provenance design space \cite{cheney2009provenance}. Semiring
provenance provides compositional annotations for positive relational queries
\cite{green2007provenance}, and aggregation requires value-level treatment
beyond tuple annotations \cite{amsterdamer2011aggregate}.

Provenance is also an implemented database capability. Perm and GProM compile
provenance questions through query rewriting \cite{glavic2009perm,arab2018gprom};
ProvSQL adds provenance and probability to PostgreSQL
\cite{senellart2018provsql}; and Smoke integrates fine-grained lineage into
operators for interactive performance \cite{psallidas2018smoke}. \system claims
neither a new provenance algebra nor a general provenance engine. It specializes
provenance to two set-valued effects---facts explicitly released and a
conservative operator-input footprint for their successful positive
derivations---then requires answer/effect co-generation in
one snapshot and atomic settlement before release.  The online profile includes
bounded inner-equijoin and union-distinct multiplicity; outer joins, negation,
and general recursive SQL remain outside it.

\subsection{Usage Control, Delegation, and Quotas}

Usage control extends authorization across an ongoing use and permits mutable
attributes and obligations \cite{park2004ucon}; execution-history access
control likewise makes past actions part of authorization
\cite{abadi2003history}. Delegation has mature logical and role-based
foundations \cite{li2003delegation,barka2000delegation}, while macaroons provide
cryptographic attenuation through contextual caveats
\cite{birgisson2014macaroons}. Consumable credentials encode bounded use in
linear logic \cite{bowers2007consumable}; distributed storage quotas use
reconcilable vouchers \cite{pollack2007quota}; and PERMIS combines delegated
authorization with history-sensitive cumulative-resource decisions
\cite{chadwick2008permis}.

Consequently, neither token attenuation, delegation depth, consumable authority,
nor quota accounting is claimed independently. \system's narrower systems claim
is that every descendant settles the same semantic disclosure effect against a
single root-task exposure ledger, so delegation cannot mint a fresh disclosure
budget. The prototype uses centralized transactional settlement; distributed
vouchers and reconciliation would require an additional safety argument.

\subsection{Database Policy Enforcement and Agents}

Database-backed policy systems rewrite or validate queries against application
policy \cite{mehta2017qapla,zhang2022blockaid}. Natural-language database work
initially emphasized text-to-SQL accuracy on cross-domain schemas
\cite{yu2018spider} and then larger realistic databases
\cite{li2023bird}. AgentBench includes database operation among interactive
agent environments \cite{liu2024agentbench}; D-Bot applies a multi-agent system
to database diagnosis \cite{zhou2024dbot}; and Spider~2.0 evaluates enterprise
workflows involving multiple queries, metadata, and dialects
\cite{lei2025spider2}. Recent security work aligns natural-language interfaces
with database access policy \cite{liu2026safenlidb}, measures indirect prompt
injection against tool-using agents \cite{debenedetti2024agentdojo}, and applies
runtime data-flow control to agents \cite{summers2026dataflow}.

These systems motivate treating generated SQL and agent tools as untrusted, but
they pursue complementary targets: generation quality, operational assistance,
per-request policy, prompt-injection resilience, or information-flow labels.
\system places the model outside the trusted computing base and focuses on
cumulative, explicit database disclosure across retries, pagination, supported
rewrites, and delegation.

\textbf{Novelty boundary.} History, inference control, pricing, provenance,
query mediation, delegation, quotas, task-bound SQL sessions, receipts, and
persistent agent disclosure logs are established by the literature above.
Relative to SessionBound, the claim is precisely FactID dual-set semantics,
same-snapshot provenance, exact novel-set settlement, shared root-family
delegation, and the corresponding formal properties and experiments. Relative
to GAAP, the contribution is database-specific semantic accounting rather than
general cross-task IFC. This boundary is narrower than SQL noninterference or
GAAP's confidentiality goal and stronger than stateless authorization for the
modeled positive-disclosure threat.

\section{Exposure Model}
\label{sec:model}

\subsection{Facts and Task State}

V2 treats a FactID as a semantic object and its SHA-256 as only a database
index.  Its semantic environment is
$\Pi=\langle pg,\mathcal T,UTC,\mathcal C,D,h_C\rangle$: a PostgreSQL major
version, admitted type domain, timezone, exact deterministic collation
name/version map, immutable snapshot map, and catalog/lineage digest.  A
judgment is defined only for an \emph{admissible} $\Pi$: source schemas and
entity keys are attested, every collatable field has a deterministic collation,
and volatile expressions are absent.  Let $\nu$ be a catalog-owned source
namespace (not a view alias), $s$ an immutable snapshot, $e$ a canonical stable
entity key, $a$ a role-qualified field ID, $\tau\in\mathcal T$, and
$C_\tau(v)$ its typed canonical value.  Base identities are

\begin{align}
 f_{row}&=\langle\pi,\nu,s,e\rangle,\\
 f_{cell}&=\langle\pi,\nu,s,e,a,\tau,C_\tau(v)\rangle .
 \label{eq:fact}
\end{align}

A derived identity is
$f_d=\langle\pi,\mathcal B,k_o,N_\pi(x),\tau,C_\tau(v),CW(W)\rangle$,
where $\mathcal B=\operatorname{sort}\{(\nu,s)\}$ is the relation's snapshot
bundle, $k_o$ is the canonical output-row entity key, $N_\pi(x)$ erases aliases
and normalizes the supported expression, and
$W:\facts_{base}\rightharpoonup\mathbb N^+$
is a finite-support witness multiset (the empty support is allowed).  The product identity is not a caller-supplied
name: it is exactly the namespace projection of $\mathcal B$.  The witness
commitment $CW(W)$ length-prefixes the lexically sorted
$(\operatorname{FactHash}(f),W(f))$ pairs; the empty multiset has a separate
token.  The durable key is
$\mathrm{SHA256}(\texttt{TASKGATE-FACT-V2\textbackslash0}\|\operatorname{Canon}(f))$.
Control PostgreSQL stores $\operatorname{Canon}(f)$ and compares it on every hash conflict;
a same-hash, different-payload row aborts the transaction. V1 and V2 tagged
payloads are disjoint and one root ledger fixes exactly one profile.

\begin{theorem}[Fact identity well-definedness]
For every value in the V2 supported PostgreSQL type domain, canonical encoding
is deterministic and injective over the typed semantic payload (that is, over
PostgreSQL semantic-value equivalence, not raw float NaN bit patterns).
\end{theorem}
\begin{proof}
Each scalar encoder is a canonical representative of its typed equivalence
class: bounded integers use signed decimal, exact numerics reduced rationals,
floats fixed-width hexadecimal with canonical NaN and zero, temporal values
PostgreSQL microseconds (UTC for \code{timestamptz}), and NULL a disjoint token.
Every tuple component is type tagged and length delimited; every list is count
prefixed and sorted where its mathematical carrier is a set.  Decoding first
recovers the unique tag and component boundaries, then the unique scalar
representatives.  Therefore equal encodings imply equal typed payloads, and
determinism follows from the unique representative and ordering functions.
\end{proof}

\begin{definition}[Exposure effect]
For query $q$ over snapshot $D_s$, the effect
$\effect(q,D_s)=\langle \facts_r,\facts_i\rangle$ contains release facts
$\facts_r$ and positive-output dependency facts $\facts_i$ under a versioned
profile $\pi$.  The latter are the conservative base facts selected by the
inductive rules below for successfully derived delivered rows and cells; they
are not claimed to be minimal causal provenance or all physical reads.
\end{definition}

Every root task $T$ stores previously accounted sets
$\accounted_T=\langle\accounted_T^r,\accounted_T^i\rangle$ and limits
$B_T=\langle B_T^r,B_T^i\rangle$. Settlement computes

\begin{align}
 \Delta_T^r(q) &= \facts_r(q,D_s)\setminus\accounted_T^r,\\
 \Delta_T^i(q) &= \facts_i(q,D_s)\setminus\accounted_T^i.
 \label{eq:delta}
\end{align}

V2 measures cardinality independently in each dimension. A query may settle
only if
$|\accounted_T^r|+|\Delta_T^r|\leq B_T^r$ and
$|\accounted_T^i|+|\Delta_T^i|\leq B_T^i$.

The word ``accounted'' is intentional. Release facts describe delivered values,
but dependency FactIDs remain internal to the gateway; the agent receives
only result data, counts, and receipt digests. Hence $\accounted_T^i$ is not a
set of facts known by the agent, and neither component is a complete epistemic
or privacy-loss state.  The wire and storage label \code{influence} is retained
for compatibility; under the V2 profile it denotes positive-output dependency,
not causal influence.

\subsection{Closed Typed Query Language}

The complete core syntax is
\begin{align*}
e ::= {}& \operatorname{Scan}[\nu,s,r,\Gamma]
 \mid \sigma_{p;F}(e) \mid \pi_A(e) \mid e\bowtie_{\Theta}e \\
 &\mid e\cup_\delta e \mid \gamma_{G;\mathcal A}(e)
 \mid \operatorname{Page}_{O,K,o,l}(e),\\
p ::= {}& b \mid p\wedge b,\qquad b ::= a\;op\;c,\\
op\in {}&\{=,\ne,<,\le,>,\ge\}
 \cup\{\code{LIKE},\code{IN},\code{NOT IN}\},
\end{align*}
where $F$ is exactly the fields read by $p$, $\Theta$ is a nonempty
conjunction of equalities, $\cup_\delta$ is union-distinct, and
$\mathcal A\subseteq\{\code{COUNT(*)},\code{COUNT},\code{SUM},\code{MIN},
\code{MAX}\}$.  No implicit SQL construct is hidden in $e$: outer joins,
difference, negation beyond the listed scalar predicates, windows, recursion,
subqueries, volatile functions, and \code{UNION ALL} are not terms.

The typing judgment $\Pi\vdash e:\Gamma$ is generated only by the following
rules (undefined premises mean rejection):

\small
\begin{gather*}

      \quad \Pi;\Gamma\vdash p:\mathbb B_3}

Here $\mathbb B_3=\{\mathsf T,\mathsf F,\mathsf U\}$ is PostgreSQL
three-valued logic.  Equality with either operand NULL is $\mathsf U$;
$\mathsf F\wedge x=\mathsf F$, $\mathsf T\wedge x=x$, and
$\mathsf U\wedge\mathsf U=\mathsf U$.  Selection retains only $\mathsf T$.
By contrast, grouping and distinct use the typed equivalence
$v\equiv_\tau w$ defined by \code{IS NOT DISTINCT FROM}, so NULL is equivalent
to NULL.  Predicate evaluation and ordering are PostgreSQL functions fixed by
$pg$ and $\mathcal C$, not Go approximations.

The closed scalar domain $\mathcal T$ contains exactly the canonical types
\code{smallint}, \code{integer}, \code{bigint}, \code{numeric}, \code{real},
\code{double precision}, \code{boolean}, \code{bytea}, \code{date},
\code{time without time zone}, \code{timestamp without time zone},
\code{timestamp with time zone}, \code{uuid}, \code{text}, \code{character},
\code{character varying}, and \code{jsonb}, with PostgreSQL
aliases mapped to these canonical names.  Integers retain their
16/32/64-bit ranges; exact numerics are encoded as reduced rationals and never
accepted through a binary-float conversion; floats use their IEEE width and
canonicalize NaN, infinities, and negative zero.  Temporal values have
PostgreSQL microsecond precision, \code{timestamptz} is UTC, and
\code{time with time zone} is excluded.  Text equality/order binds exact
deterministic collation name and actual version.  The text-preserving
\code{json} type is excluded: PostgreSQL retains insignificant whitespace,
object-key order, duplicate keys, and numeric lexical forms, while \code{jsonb}
has structural canonical equality \cite{postgres16json}.  Aggregate result
types are exactly PostgreSQL's:
\code{COUNT}$\to$\code{int8}, \code{SUM(int2/int4)}$\to$\code{int8},
\code{SUM(int8)}$\to$\code{numeric}, \code{SUM(numeric)}$\to$\code{numeric},
and \code{MIN/MAX}$\to$the input type.  \code{SUM(real)} and
\code{SUM(double precision)} are not admitted: IEEE-754 addition is
non-associative, so a floating-point SUM depends on the physical aggregation
order, which the typed bag and the normal form do not fix.  Any cast,
arithmetic, aggregate, witness-multiplicity, or canonical-range overflow makes
evaluation undefined and the gateway releases and settles nothing.

\subsection{Annotated Bags and Complete Output Keys}

A relation is $R=\langle\Gamma,\mathcal B,M,\prec?\rangle$, where $M$ is a
finite PostgreSQL bag implemented by unique row keys.  Equal value tuples remain
distinct bag occurrences when their keys differ; only union-distinct and group
quotient occurrences into classes.  An optional $\prec$ records a proven total
order.  A row is
$t=\langle k,\{a\mapsto c_a\},S_r,W_r,O_r\rangle$ and a cell is
$c_a=\langle v,\tau,S_a,W_a,x_a,\rho_a?\rangle$.  $S$ is a finite set of
snapshot-covered base facts, $W$ a finite multiset with positive stored
multiplicities (possibly empty), $x$ a canonical
data-independent lineage expression, and $\rho$ an optional already
materialized release fact.  Every operator preserves
\begin{equation}
 \operatorname{support}(W_r)=S_r,\qquad
 \operatorname{support}(W_a)=S_a.                 \label{eq:anninv}
\end{equation}
For annotations define same-proof composition
$\bigoplus_i(S_i,W_i)=(\bigcup_iS_i,\sum_iW_i)$ and alternative-proof
composition
$\bigsqcup_i(S_i,W_i)=(\bigcup_iS_i,\max_iW_i)$, with pointwise multiset
sum/max.  Thus $A\bigsqcup A=A$, while join fanout remains in $\bigoplus$.

\subsection{Operator Evaluation and Effect Extraction}

Evaluation is the partial judgment $\Pi;D\vdash e\Downarrow R$; ``partial''
means that a failed premise yields no relation, effect, settlement, or release.

$\alpha_a(t)=(S_a,W_a)$, $\operatorname{aug}_F(t)$ replaces

normalized lineage expression, and the optional materialized release fact.

The auxiliary functions in Fig.~\ref{fig:evaluation} are total on typed
premises.  $\equiv_\Gamma$ is componentwise \code{IS NOT DISTINCT FROM}.
For a union class, its typed-tuple key is Table~\ref{tab:rowkeys}; support uses
set union.  An identical annotated branch is collapsed only when its complete
typed tuples are already known to be duplicate-free, so
$R\cup_\delta R=R$ for such a set-valued $R$, also inside a downstream
context.  A Scan is conservatively bag-valued: if it contains duplicate full
tuples, duplicate elimination still runs.  For remaining operands, within one candidate member,
$\beta_\Gamma$ uses same-proof
composition over its row and every schema field used for typed-tuple
equivalence; alternative members use pointwise maximum.  Thus hidden
duplicate-elimination fields remain in the row dependency.  An existing cell
release fact is retained iff every member materializes to that identical
FactID.  Otherwise
$\rho=\bot$ and the cell expression is the sorted, idempotent
$N(\code{union}(x_1,x_2))$.  This makes both operand exchange and
the admissible set-valued $R\cup_\delta R$ identity exact, including in a
downstream operator.

$\operatorname{Part}_G(R)$ uses $\equiv_\tau$ on group fields.  If
$G\ne\varnothing$, empty input has no classes; if $G=\varnothing$, there is
exactly one class even for empty input.  The argument annotation of an
aggregate cell $(f,a')$ is $\alpha_{\arg(a')}(t)=\alpha_r(t)$ for
\code{COUNT(*)} and the argument-cell annotation $\alpha_a(t)$ for
\code{COUNT(a)}, \code{SUM(a)}, \code{MIN(a)}, and \code{MAX(a)}, including a
NULL fact and every non-extreme \code{MIN/MAX} input, while PostgreSQL ignores
NULL when computing the scalar.  These are conservative operator-input
dependencies, not claims of causal influence.  Hence an
empty global aggregate returns \code{COUNT}=0 and \code{SUM/MIN/MAX}=NULL with
empty witness.  \code{SUM} is admitted only over the exact/integer fragment
$\{\code{smallint},\code{integer},\code{bigint},\code{numeric}\}$: because
IEEE-754 addition is non-associative, \code{SUM(real)} and
\code{SUM(double precision)} are undefined in the closed language and fail
closed, so the aggregate value is independent of any physical aggregation order
the typed bag does not fix.  A keyed group must correspond one-to-one with all
positive input classes; the gateway accepts only a complete aggregate-result
oracle from the same snapshot.

The page comparator is PostgreSQL lexicographic order under $\mathcal C$:
ascending defaults to NULLS LAST, descending to NULLS FIRST.  The compiler
appends Catalog entity keys (or every group key) ascending until $O{+}K$ is a
proven total order; a global aggregate has at most one row.  SQL executes this
same order before the algebra marks it canonical.  $l=0$ is the structured-plan
sentinel for no limit.  Page copies annotations and intentionally does not
charge non-output rows, ordering fields, or rank information.  It is therefore
not a complete top-$k$ or physical-read dependency; the negative/order boundary
is stated in Sec.~\ref{sec:limits}.

Finally, define materialization and the effect---they are not an implementation
afterthought:
\begin{align}
\operatorname{new}(R,t,a)&=
 f_d(\mathcal B,t.k,N(x_a),\tau_a,v_a,W_a),\\
\operatorname{mat}(R,t,a)&=
\begin{cases}
\rho_a,&\operatorname{valid}(\rho_a,R,t,a),\\
\operatorname{new}(R,t,a),&\text{otherwise},
\end{cases}\\
\facts_r(R,V)&=\{\operatorname{mat}(R,t,a)\mid t\in R,\ a\in V\},\\
\facts_i(R,V)&=\bigcup_{t\in R}S_r(t)\ \cup
                \bigcup_{t\in R,a\in V}S_a(t),\\
\effect_\Pi(e,D,V)&=\operatorname{normalize}
  \langle\facts_r(R,V),\facts_i(R,V)\rangle.       \label{eq:observe}
\end{align}
Here $\Pi;D\vdash e\Downarrow R$, and $\operatorname{valid}$ checks value,
type and bundle, plus support for a base fact or expression/witness for a
derived fact, against the pre-existing release fact.
Thus query bags and witness multiplicity are retained during composition, while
the two final ledgers are sets.  Equation~\eqref{eq:observe} is the declared
positive-output dependency profile: it is exact with respect to these
inductive rules, not with respect to arbitrary causal provenance or physical
source access.  Empty answers have the empty effect except for the single
visible row of a global aggregate.

\begin{theorem}[Representation closure and partial-function semantics]
For every admissible $\Pi$, typed finite $e$, and immutable $D$, evaluation has
at most one result.  If $\Pi;D\vdash e\Downarrow R$, $R$ satisfies
Eq.~\eqref{eq:anninv}, has canonical schema/bundle and unique row keys, and is a
valid input to every well-typed parent rule.
\end{theorem}
\begin{proof}
By structural induction on $e$.  Scan is fixed by $D$ and constructs singleton
support/witness pairs.  Select's three-valued predicate and dependency set are
fixed by $\Pi$; Select, Project, and Page only take a deterministic subbag or
copy annotations.  Join enumerates a uniquely determined bag of matching key
pairs; disjoint schemas, Eq.~\eqref{eq:rid}, and the pair key make each output
usable by another Join.  Union first collapses an identical annotated branch
only under the duplicate-free full-tuple premise, then has unique typed-tuple
equivalence classes and uses deterministic
same-proof union/addition within a candidate and alternative union/max across
candidates; E-Union constructs each output cell
$\langle v_a,\tau_a,\bigsqcup\alpha_a,N(\code{union}(x)),\rho_a\rangle$ from
those classes.  Group has unique not-distinct classes, the explicitly defined
empty class, deterministic exact/numeric sum folds (floating-point SUM is
excluded from the closed language, so no order-dependent fold arises), and one
complete PostgreSQL result per class; E-Group composes every group-key input
into the row annotation and constructs both group-key and aggregate cells from
that result.  Set union with multiset sum or max preserves equal
support.  Total order makes Page's slice unique.  Each case constructs the
claimed invariant, and the validator converts any range, collision, schema,
oracle, or multiplicity violation into no derivation.
\end{proof}

\begin{theorem}[Dependency determinism]
Fixed admissible $\Pi$, typed $e$, snapshot map $D$, and visible field set $V$
uniquely determine the positive-output dependency FactSet $\facts_i$, and hence
$\effect_\Pi(e,D,V)$, whenever evaluation succeeds.
\end{theorem}
\begin{proof}
The preceding theorem gives a unique $R$.  Equation~\eqref{eq:observe} ranges
over its unique keyed occurrences and fields.  $C_\tau$, expression
normalization, bundle/key construction, witness commitment, Fact
materialization, and final set normalization are deterministic functions.
Therefore both finite Fact sets, and hence their ordered canonical encodings,
are unique.
\end{proof}

\begin{property}[Group-key completeness]
For every delivered group $Q$, member $t\in Q$, and group field $g\in G$,
$S_g(t)\subseteq\facts_i$, including when $g\notin V$.
\end{property}
\begin{proof}
E-Group includes $\bigoplus_{g\in G}\alpha_g(t)$ in the output row annotation.
Projection preserves that row annotation, and Eq.~\eqref{eq:observe} includes
every delivered row's $S_r$ independently of $V$.
\end{proof}

\begin{property}[Distinct-dependency completeness]
For every delivered union-distinct class $Q$, candidate $t\in Q$, and schema
field $a\in\Gamma$, $S_a(t)\subseteq\facts_i$, including when $a\notin V$.
\end{property}
\begin{proof}
E-Union first composes every schema-field annotation into $\beta_\Gamma(t)$,
then alternative-composes all candidates into the output row annotation.
Alternative max changes multiplicity but its support is the union, which
Eq.~\eqref{eq:observe} includes.
\end{proof}

\begin{property}[Conservative aggregate input]
Every delivered aggregate cell includes its complete declared logical input:
all member row annotations for \code{COUNT(*)}, and every member argument cell
for \code{COUNT(a)}, \code{SUM(a)}, \code{MIN(a)}, and \code{MAX(a)}.  NULL and
non-extreme \code{MIN/MAX} inputs are not omitted.
\end{property}
\begin{proof}
This is the aggregate-cell clause of E-Group followed by
Eq.~\eqref{eq:observe}.  PostgreSQL's scalar fold may ignore NULL or retain only
an extreme value, but the V2 dependency rule deliberately ranges over the
complete argument bag.
\end{proof}

\subsection{Conservation Properties}

The following properties apply only to the operators and rewrites stated here.
They are not claims about all semantically equivalent SQL.

\begin{property}[Normalization]
Fact-set normalization is deterministic, idempotent, and commutative under
merge.
\end{property}
\begin{proof}
By Fact identity well-definedness, a validated canonical payload has one map
key; a same-digest unequal payload aborts rather than merges.  Normalization is
therefore finite-set insertion followed by lexical canonical-payload order.
Idempotence and commutativity follow from $A\cup A=A$ and $A\cup B=B\cup A$;
the fixed serialization order gives the same bytes in each case.
\end{proof}

\begin{theorem}[Restricted projection/selection invariance]
For $F\cup V\subseteq A$, selection followed by projection and projection
followed by selection have the same visible effect:
\[
 \effect_\Pi(\pi_A(\sigma_{p;F}e),D,V)=
 \effect_\Pi(\sigma_{p;F}(\pi_Ae),D,V).
\]
Reordering $A$ also preserves this normalized terminal effect.
\end{theorem}
\begin{proof}
Because $F\subseteq A$, both selection predicates read identical typed cells
and retain exactly the rows whose truth value is $\mathsf T$.  By E-Select each
retained row receives the same
$\alpha_r(t)\oplus\bigoplus_{a\in F}\alpha_a(t)$; by E-Project both retain the
same keys and cells in $A$.  Equation~\eqref{eq:observe} over $V\subseteq A$
therefore yields identical release and dependency sets.  Field traversal order
is absent from Fact payloads and removed by set normalization.
\end{proof}

\begin{definition}[Typed normal form $NF_\Pi$]
\label{def:nf}
$NF_\Pi$ is the total map from well-typed terms $e$ to canonical terms induced
by the following structure-recursive rewrites, each of which either preserves
$\effect_\Pi$ or is the identity: erase SQL aliases and derived-expression
display names; sort conjunction literals in $p$, dependency fields $F$,
projection lists, group keys $G$, and aggregate families $\mathcal A$ by their
stable role-qualified field IDs and canonical expressions; sort join operands
and equality predicates by their child digests; sort union operands by digest
and collapse an identical duplicate branch only when the child normal form
proves full-tuple distinctness, so $e\cup_\delta e\equiv e$ for that
set-valued $e$; sort
relation-level union operands before any enclosing operator; and map a stable
page suffix to its catalog-canonical spelling (entity-key or all-group-key
suffix).  $NF_\Pi(q_1)=NF_\Pi(q_2)$ iff the two canonical terms are syntactically
identical.  The artifact realizing $NF_\Pi$ is
\texttt{taskgate-query-normal-form-v3}, and it performs no outer-join,
arithmetic, window, subquery, or general SQL equivalence reasoning.  This
query-level normalizer is distinct from the Fact-set $\operatorname{normalize}$
of Property~(Normalization), which acts on the final ledgers.
\end{definition}

\begin{theorem}[Typed normal-form soundness]
For admissible $\Pi$, immutable snapshot map $D$, typed $q_1,q_2$, and the
same visible field set $V$,
\[
 NF_\Pi(q_1)=NF_\Pi(q_2)\Longrightarrow
 \effect_\Pi(q_1,D,V)=\effect_\Pi(q_2,D,V).
\]
This implication is not a completeness claim for arbitrary equivalent SQL.
\end{theorem}
\begin{proof}
The typed normalizer can erase only aliases, conjunction/set traversal order,
join operand and predicate order, union operand order, an identical duplicate
union branch whose child is proven full-tuple distinct, and alternate spelling
of the same stable page suffix. A Scan carries no such proof; Union and Group
produce it, Select/Page preserve it, and Project preserves it only for an
unchanged schema. Alias is
absent from derived expressions. Set normalization removes traversal order.
Join hashes sorted child identities and uses commutative $\cup/\oplus$.
Union classes are operand independent; same-proof member composition includes
all equivalence fields, while alternative max-merge is commutative and
idempotent.  An identical materialized fact is retained, and relation-level
union expressions are sorted before any downstream composition. Group keys and witness
commitments are sorted. The SQL compiler emits the same catalog-canonical page
suffix represented by the normal form. Each atomic rewrite therefore preserves
Effect; structural induction over well-typed contexts proves the result.
\end{proof}

\begin{theorem}[Split/page/join conservation]
Merging observations for disjoint projections or a complete page partition
equals observing the combined result. Overlapping pages and repeated terminal
observations charge each FactID at most once; join fanout changes witness
multiplicity but not the union of dependency support.
\end{theorem}
\begin{proof}
For $V=V_1\cup V_2$, distribute both unions in
Eq.~\eqref{eq:observe} over $V_1,V_2$; this gives
$\effect(R,V)=\operatorname{merge}(\effect(R,V_1),\effect(R,V_2))$.
E-Page copies each selected keyed row and cell, so a complete disjoint slice
partition distributes the same two unions over the row index set.  Overlap and
repetition disappear by set idempotence.  E-Join adds witness multiplicities
with $\oplus$, but Eq.~\eqref{eq:observe} takes their support sets; repeated
support membership consequently has dependency cardinality one.  (A changed
derived witness may still change its release Fact, as required.)
\end{proof}

V2 uses \code{taskgate-query-normal-form-v3}. Besides the rewrites above it
binds namespace, snapshot, lineage digest, canonical SQL types, collation
names/versions, PostgreSQL three-valued bag semantics, UTC, and exact numeric
mode. It deliberately performs no outer-join, arithmetic, window, subquery, or
general SQL equivalence reasoning.

\subsection{Compilation and Paired Execution}

An exposure-enabled grant accepts either a one-product structured plan or one
closed two-input form.  The latter is (i) an inner join of two distinct
Catalog-stable roles with one or more same-type, same-collation equalities, or
(ii) union-distinct over two filtered aliases of one product, with the complete
deduplication schema explicit even when final $V$ hides some of its fields.
Nested join/set trees, self-join roles, union-all, and relational pagination
fail closed.  Callers cannot supply SQL fragments, FactIDs, provenance, or
semantic role identities.  Branch aliases are syntactic; join and union output
roles must match Catalog identities.

The compiler validates fields, predicates, grouping, and one of four
aggregates; \code{COUNT(*)} and \code{COUNT(field)} have distinct normal forms.
It produces two SQL statements from the same typed plan. A join companion
returns each positive matched row pair, including both entity keys and every
projected/join/filter/group/aggregate field. The visible and companion statements share
a stable pair-key order when the ordinary row ceiling can cut the bag. A
union-distinct visible statement eliminates duplicates over its complete
declared schema, whereas its companion deliberately uses \code{UNION ALL} plus
a branch marker and both source entity keys. Consequently every member of each
delivered distinct class remains reconstructible; selecting one representative
would be rejected as incomplete evidence. Grouped and membership-expanded
companions request one row beyond their evidence ceiling to detect truncation.
All generated statements pass the same PostgreSQL AST authorization and
mandatory-scope injection policy.

After execution, the gateway reconstructs Catalog-bound Scan annotations,
retains only provenance-certified join pairs or delivered union classes, and
invokes the same \code{JoinOnV2}, \code{UnionDistinctV2},
\code{AggregateFromResultsV2}, and \code{ObserveV2} implementation tested by
the algebra oracle. It does not maintain a second ad hoc online dependency
rule. Hidden SQL output aliases are server-generated hashes and are mapped back
to stable field IDs before effect derivation and external delivery.

The connector executes both statements in one explicit read-only
\code{REPEATABLE READ} transaction \cite{postgres16transaction}. This prevents
a concurrent update from making output and provenance refer to different
database states. The connector reports business and provenance execution time
separately, while resource settlement charges their total. Truncation of the
provenance result is a hard error.

\subsection{Atomic Settlement}

For one successful exposure-enabled query, the gateway performs the following
steps:

\begin{enumerate}
\item Authorize the fixed plan, reserve ordinary and exposure budgets, then
execute and buffer its visible and provenance statements in one Business
PostgreSQL \code{REPEATABLE READ} snapshot.
\item Derive its release and positive-output-dependency observation and reject
truncated or inconsistent evidence.
\item In Control PostgreSQL, lock the query reservation and root ledger and
insert the observation's facts under a primary key on root, ledger kind, and
fact hash; conflicts contribute zero novel facts.
\item Conditionally increment both used counters only if both limits remain
valid.
\item In the same transaction, settle query/row/database-time resources, store
the encrypted buffered result, append terminal audit evidence, and persist a
signed V4 receipt.
\item Commit and only then return the buffered result.
\end{enumerate}

If the conditional budget update in Step 4 affects no row, the transaction
returns an exposure-budget error.
Fact inserts and result storage roll back, and the caller never receives the
buffer. PostgreSQL row locking serializes concurrent children at the shared
root. Unique fact keys make charge equal to successful novel inserts, rather
than a count computed before a race.

Let $n$ be the number of unique dependency and release facts in one
observation. Hashing is linear in encoded input size and normalization sorts at
most $n$ hashes, giving $O(n\log n)$ in-memory work and $O(n)$ memory. Ledger
inserts are chunked; index maintenance adds database-dependent
$O(n\log |\accounted_T|)$ work under a conventional balanced index model. These are
complexity bounds, not measured latency claims.

\subsection{Receipts and Failure Semantics}

A V4 Ed25519 receipt binds the root task, profile, actual and charged counts in
both dimensions, and the SHA-256 of the normalized observation, in addition to
authorization, datasource, resource budget, result, and audit evidence. It
does not expose raw values or FactIDs.

Failures before connector invocation release both reservations. Ambiguous
connector outcomes conservatively charge the ordinary resource reservation but
release exposure because no result can be delivered before successful
settlement. A process restart applies the same rule. Terminal request replay is
observational: it returns the first persisted status or result and never starts
a second execution.

Withholding the buffer does not hide the decision bit. Whether settlement
accepts a query reveals whether its data-dependent novel Effect fits the
remaining budgets, and a rejected Effect is not itself inserted into either
ledger. Thus rejection can act as an uncharged threshold oracle. The current
protocol is not a simulatable auditor and makes no denial-noninterference claim.

\section{Delegation}
\label{sec:delegation}

\subsection{Root-Family Conservation}

A child authorization signs both \code{root_task_id} and
\code{parent_task_id}. Its human subject, catalog, datasource, schema, and
profile remain fixed, while products, columns, scopes, sensitivity, expiry, and
all budget dimensions may only narrow. Every execution revalidates the signed
parent grant and active ancestor chain.

All descendants resolve to one root ledger. If a parent and child request the
same fact, only the first successful settlement inserts it. Revoking the root
blocks new descendant queries, while an already terminal request ID remains
readable. Consequently, creating agents or task nodes cannot create fresh
exposure capacity. A child that signs a lower exposure ceiling may add novel
facts only while the shared family total remains within that ceiling; a
zero-novelty replay remains admissible.

This conservation scope stops at the root boundary. A second root task for the
same principal has an independent ledger and therefore a fresh budget if a
human approves it. The prototype has no principal-, tenant-, or organization-
wide exposure ledger, so neither delegation monotonicity nor the theorem below
prevents cross-root accumulation.

\begin{theorem}[Atomic root-family budget safety]
After any committed settlement sequence, each root ledger equals the union of
the novel charges of its settled family queries, and neither cardinality
exceeds its root limit.
\end{theorem}
\begin{proof}[Proof sketch]
All family settlements lock the same root row. The unique fact key admits one
first insert for each root/kind/hash tuple. A transaction adds exactly its
successful inserts to the counters, checks both limits, and otherwise rolls
back. Induction over the resulting serial commit order establishes the union
identity and both bounds.
\end{proof}

\textbf{Budget calibration.} The two ceilings $B^r_T,B^i_T$ are authorizer
declarations, not learned parameters: the human approving a root task sets them
in the same distinct-fact-count units the ledgers record, derived from a
disclosure policy (how many distinct released facts, and how many distinct
dependency facts, this task family may account for). Fact counts are
unit-weighted by construction:
a highly sensitive cell and an ordinary cell both count one, because the model
bounds disclosure \emph{volume} (the number of distinct accounted facts), not
disclosure \emph{harm}. Per-fact sensitivity weighting and differential-privacy
composition are therefore explicit non-goals (Sec.~\ref{sec:limits}); a
deployment that needs harm-weighted limits must layer such a mechanism on the
same fact boundary rather than reinterpret the count.

\section{System Realization}
\label{sec:system}

The prototype is implemented in Go with separate control and business
PostgreSQL 16 databases. A logical catalog declares reporting views, mandatory
scopes, stable snapshots, entity keys, allowed operations, approval routes, and
resource/exposure profiles. Startup and per-query attestation bind datasource
identity, database, role, PostgreSQL major version, ordered view schema, and
normalized view definitions.

Agents use MCP tools to list products, request a task, execute one structured
plan, inspect both budgets, delegate a narrower task, and retrieve results or
receipts. An external approval adapter
signs the immutable grant. Arbitrary direct SQL remains available only for
legacy resource-only grants; it fails closed when exposure evidence is
required.
The wire and storage label \code{influence} is retained for compatibility;
under the V2 profile it denotes positive-output dependency, not causal
influence.

The control schema stores one dual ledger per root, per-query reservations, and
immutable fact identities. The primary-key and check constraints are backed by
application transactions and update/delete rejection triggers. Result rows are
encrypted with AES-GCM; audit events form a hash chain. These mechanisms are
orthogonal to exposure semantics but make settlement and later verification
observable.

\section{Finite-State Analysis}
\label{sec:formal}

The split TLA+ model \code{ExposureLedger.tla} contains one root, one child, two
requests, two facts in each ledger universe, both limits set to one, and one
terminal replay. Its transitions are reserve, execute/buffer, derive,
settle, over-budget reject, pre-execution release, replay, and root revocation.
It checks dual-budget safety, exact novel charge, no delivery before settlement,
no charge without settlement, buffered rejection, evidence/buffer agreement,
non-overlapping novel charges, task-family non-amplification, and at-most-once
physical execution for delivered requests.

Using pinned TLC 1.7.1, the provenance-checked run generated
\ExposureFormalStates{} states, found \ExposureFormalDistinct{} distinct states,
and reached depth \ExposureFormalDepth{} with no invariant error. Model,
configuration, and raw-log digests are validated before this manuscript builds
\cite{lamport2002specifying}.

This is exhaustive only for the submitted finite configuration. The model
assumes exact fact derivation, abstracts SQL bytes and cryptographic hashes, and
does not mechanically prove that Go/PostgreSQL refines TLA+. The repository
therefore includes an action-to-method-to-transaction-to-test refinement map
rather than claiming a proof that does not exist.

\subsection{RQ4: Multi-Scale Join--Group End-to-End}

executes a large relational result through effect derivation and settlement.

Orders--Lineitem relationship shape. It is TPC-H-derived, not an official TPC-H

materialized base contains 50,000 orders and 250,000 lineitems. Three fresh root

\subsection{Reproducibility Boundary}

RQ1 and the RQ2 exposure-invariance stream remain auditable in-process tests:
RQ1 has 16 source rows, while RQ2 invariance crosses \RQTwoExposureRewrites{}
closed-language rewrites over \RQTwoExposureDatasets{} small data instances, and
the PostgreSQL online-coverage test uses the bundled ten-row travel fixture.
Thus the counts are rewrite/data-instance pairs and operator scenarios, not
independent schemas or workloads.  The separate SQL result-equivalence stress
test and its normalized-pair accounting appear only in the supplement. The
small-fixture performance result is a controlled single-host microbenchmark on
the bundled ten-row travel fixture. The separate real Control PostgreSQL
campaign scales durable storage to \RQFourStorageMaxRows{} fact rows. The new
public-path campaign supplies the previously missing cross-cardinality
Join--Group execution: three scales culminate in \RQFourScaleMaxJoined{} joined
members and \RQFourScaleMaxFacts{} dependencies. It remains one deterministic,
warm-service, TPC-H-derived query shape on one host with three repeats---not an
official TPC-H/TPC-DS suite, controlled cold-cache study, multi-node deployment,
or production SLO evaluation. It also does not evaluate a live model, agent
task success, or utility. Source-controlled reports bind the environment,
corpus, implementation, raw results, and sample digests. These boundaries
especially limit RQ1/RQ2 external validity and RQ4 workload generality.

\section{Limitations and Threats to Validity}
\label{sec:limits}

\textbf{Semantic scope.} The model accounts positive explicit disclosure. It
does not measure rows rejected by selection, negative information implied by
empty answers, groups not returned, rows outside a delivered page, non-output
rows or fields used only to determine order/rank, cardinality or timing side
channels, correlations, or background knowledge.  Nor does it reproduce all
tuples and pages physically read by PostgreSQL.  Thus it is neither a complete
top-$k$/physical-read dependency nor a causal provenance semantics.  It is not
differential privacy and should be combined with a privacy mechanism when those
threats matter.

\textbf{Decision and subject scope.} A budget refusal exposes one uncharged bit
about whether the query's novel Effect crosses the remaining threshold; no
simulatability or denial-noninterference result is claimed. Ledgers are scoped to
one root family, not to a principal. Repeated human approval of new roots gives
the same subject independent ledgers unless an external policy imposes a
principal- or tenant-wide budget.

\textbf{Query scope.} The online compiler supports one-product plans and two
bounded multi-input forms: an inner conjunctive equijoin over two distinct
Catalog roles, and union-distinct over two filtered branches of one product
with an explicit complete deduplication schema. Both can feed grouping and
\code{COUNT(*)}/\code{COUNT(field)}/\code{SUM}/\code{MIN}/\code{MAX}. Nested
join/set trees, self-joins, union-all, relational pagination, outer joins,
\code{AVG}, windows, negation, difference, recursion, arbitrary subqueries,
and multi-datasource plans fail closed. These are prototype restrictions, not
limitations of the algebraic rules.

\textbf{Identity trust.} Stable entity keys and snapshot labels are
administrator declarations. Schema attestation cannot prove uniqueness or that
a snapshot was advanced after data changes. Production use requires a
versioned publication or CDC pipeline and collision/security review for the
chosen hash and serialization profile.

\textbf{Cost.} Exact dependency FactSets can be large, root-ledger locking can
become a hot spot, and immutable history grows monotonically. The million-fact
campaign directly observes \RQFourScaleHighNovelS{}-s novel latency,
\RQFourScaleHighReplayS{}-s replay latency, and
\RQFourScaleGatewayGiB{}-GiB gateway peak memory. Streaming derivation,
compression, sketches, partitioned settlement, retention, and audited deletion
are open design points; approximations would require new safety semantics.

\textbf{Deployment.} The prototype has one gateway instance, static local
tokens, an in-memory approval demo, and one PostgreSQL connector. It lacks a
distributed execution lease and centralized key custody. The measured
three-scale single-host workload does not establish multi-node scaling,
production SLOs, diverse schema/query generality, or live-agent task utility.

\section{Conclusion}

Task-bound authorization answers what an agent may query; task-bound exposure
accounting additionally constrains what one root ledger records for its
delegated workload. \system realizes that distinction with stable facts, separate
release and positive-output dependency sets, same-snapshot provenance, atomic novel-fact
settlement, and root-family budget conservation. The current
dependency set is a conservative footprint exact under the declared inductive
profile; it makes no claim of causal minimality or complete physical reads. The
current
artifact establishes a coherent semantic and systems foundation, finds no
violation in a finite ledger model, and observes zero mismatch for
\RQTwoExposureRewrites{} closed-language rewrite families (FactSet and
incremental charge invariant). Paired PostgreSQL tests additionally execute
online Join/Union exchange and downstream aggregation while checking the
derived observation. The small-fixture full path has
\RQFourFullOneMedian{}-ms p50 latency at one worker
(\RQFourFullOneRatio{}$\times$ direct-query p50) and exposes root-ledger
serialization at higher concurrency. More importantly, the multi-scale public
path completes a Join--Group observation with \RQFourScaleMaxFacts{}
dependencies: replay charges zero, but novel/replay medians are
\RQFourScaleHighNovelS{}/\RQFourScaleHighReplayS{}~s and gateway memory peaks at
\RQFourScaleGatewayGiB{}~GiB. This is feasibility evidence and a negative
systems result, not an acceptable SLO. The production ledger curve also shows
that exact high-overlap verification is a bottleneck. Official TPC suites,
multi-node execution, nested multi-input plans, and live-LLM generalization
remain outside the claims, along with cross-root accounting and inference
protection for denial or negative information.

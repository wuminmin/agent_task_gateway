\title{\systemname: Task-Scoped Clearance and Cumulative Exposure
Accounting for AI Agents}

\author{Anonymous Author(s)}
\date{}

\begin{document}
\maketitle

\begin{abstract}
Large enterprises already operate governed reporting estates, but these
systems typically do not provide a unified, task-scoped cumulative release
contract for adaptive agents. \systemname{} (BDG) governs agents that query
immutable reporting publications produced by scheduled synchronization. For
each approved root task and its delegated descendants, BDG models three
profile-defined effects: accounted result facts, declared positive-output
dependency facts, and canonical query outcomes. A visible query and its
provenance companion share one PostgreSQL snapshot. Before release, BDG
computes profile-relative exact set novelty against the root-family ledger and
atomically settles all three budgets, so within one root family on one
publication epoch no more than the approved number of distinct facts of each
kind can become retrievable per approved root and publication epoch; a
rejected attempt reveals one threshold bit,
their number bounded by the task tree's request budgets, and a settled query
returns its own charge. Failed promotion remains recoverable without
re-executing the business query. The admitted positive relational fragment supports connected
inner equijoins, grouping, bounded unions, and nested View expansion. Immutable
ordinals, compressed bitmaps, and an incrementally updated Merkle-radix set
represent cumulative effects. Paper theorems, bounded model checking, and
executable PostgreSQL differential and fault-injection tests support the
scoped semantics and protocol without proving the implementation. BDG targets periodic governed reporting
products and measures neither an agent's knowledge nor differential privacy.
\end{abstract}

\begin{IEEEkeywords}
data exposure, query auditing, provenance, adaptive workloads, cumulative
budget, positive-output dependency footprint, query-outcome accounting
\end{IEEEkeywords}

\section{Introduction}
\label{sec:introduction}

\IEEEPARstart{D}{atabase} authorization asks, ``Can this query execute?''
An adaptive agent adds, ``How much policy-defined exposure has this task
acquired?'' Within one approved task, an agent may split projections, overlap
pages, retry, rewrite, and delegate while individual queries remain legal,
and per-query authorization and row limits do not state the root family's
distinct cumulative exposure; BDG accounts that contract-defined quantity,
not the agent's knowledge. Data-flow control (DFC) asks whether a SQL flow is
allowed \cite{summers2026dataflow,summers2026passant}; conditional on
authorization and any DFC check, BDG asks whether the next allowed execution
fits the root's cumulative contract.

Query count ignores answer size, row count makes a one-row aggregate over
millions of source rows look cheap, and bytes depend on encoding; query
pricing develops anti-arbitrage objectives
\cite{koutris2012query,deep2017qirana,peng2025aria} and provenance explains
where results came from \cite{green2007provenance,amsterdamer2011aggregate},
whereas BDG asks how human authorization can create a stateful release
budget conserved across adaptive querying and delegation. Enterprise
operational analytics commonly serves scheduled ETL outputs rather than
OLTP primaries; BDG compiles each completed cut into an immutable
publication, new roots may bind the next cut, and unfinished roots stay on
the prior one through version routing or fail closed, so BDG bounds the
governed release of declared facts within one reporting epoch, not
freshness over a changing database.

Large enterprises already operate lakes or warehouses, reporting marts, Data
Catalogs, identity directories, and approval workflows, but none turns one
approved purpose into an enforceable contract across an agent's queries,
retries, pages, and delegated subtasks. Marketplace-integrated agents
close the discovery-and-request half of this gap: Data Product MCP lets an
agent find, request, and query governed data products over MCP and validates
the declared purpose against natural-language contracts with an LLM-based
check before each query \cite{tonnarelli2026dataproductmcp}, building on
an assistant over open-standard contracts
\cite{dietz2025automating,bitol2025odcs}. Once a purpose
is approved, per-query checks still do not state how much governed data the
task has cumulatively released across retries, pages, rewrites, and delegated
subtasks, and that system's own expert panel names letting a language model
make security decisions as an adoption barrier. BDG starts at that boundary
as a brownfield-compatible data-egress layer at the governed serving tier:
the reporting pipeline supplies immutable publications, the Catalog supplies
Products and attested stable keys, identity and workflow systems supply
subject, purpose, and approval, and BDG compiles these into a signed task
contract settled at a model-independent database boundary; the raw lake is
never exposed to the agent.

\system budgets the root task in three set-valued dimensions. \emph{Accounted
result exposure} identifies selected result values (wire label \emph{release});
accounting can precede availability. The \emph{positive-output dependency
footprint} identifies the base facts the declared rules read---neither minimal
causes nor all physical reads---so a one-cell
aggregate can expose large input. \emph{Query outcome} combines canonical
predicate atoms with one normalized query/result composite. Existing members
add zero novelty: related thresholds reuse shared atoms but charge different
literals/composites, while exact replay remains free.

The system follows a withhold-before-settlement discipline
(\code{reserve -> replay lookup / execute+stream -> derive -> settle -> publish}):
the visible query and ordinal companion share one frozen PostgreSQL snapshot
and remain withheld while one Control transaction computes exact set novelty,
checks all limits, advances the root head, and commits audit, receipt, and a
PENDING intent; a recoverable object-store step then promotes the staged
object and a second transaction records AVAILABLE/CONSUMED
(Fig.~\ref{fig:architecture-settlement}).

A preliminary preprint introduced the task-scoped authorization substrate
\cite{wu2026sessionbound}: a control plane that turns an approved task into a
signed, budgeted, auditable database session with safe views, row scope,
denied fields, operation limits, per-session counters, and receipts.
Everything that makes the budget a set rather than a counter is new here: the typed FactID semantics and closed
algebra, the same-snapshot ordinal companion and bitmap/Merkle-radix ledgers,
canonical Outcome atoms and composites, exact novelty with atomic
three-budget settlement before \code{AVAILABLE}, root-family delegation
conservation, the theorems and bounded models, and the publication campaign.
This article's five implementation-backed contributions are:

(1) a typed FactID semantics for accounted Result, positive-output
Dependency, and canonical-atom/composite Outcome sets in a restricted
algebra; (2) a same-snapshot ordinal companion for admitted one-Product,
connected equijoins (two-source joins evaluated end to end; up to 16 roles
admitted by the compiler), two-branch union, grouping, and aggregates, into
which bounded nested Views flatten; (3) profile-relative exact novelty and
atomic three-budget settlement per root family and publication epoch,
refined by immutable ordinal dictionaries, compressed bitmaps, and an exact
Merkle-radix Outcome set, with settlement before \code{AVAILABLE},
zero-novelty semantic replay, and a rejection that leaks a threshold bit
bounded by the request budget; (4) signed, monotonic delegation whose
descendants share one root-family ledger, so fan-out cannot multiply
exposure capacity while request budgets stay per task; and (5) algebraic
propositions, a normal-form soundness theorem, an abstract settlement-safety
property sanity-checked by two-fact TLA+ models, and executable
Go/PostgreSQL differential, generated-plan, and fault-injection evidence.

\section{Context and Related Work}
\label{sec:related}

\subsection{Closest System Families}

GAAP is the closest cross-tool IFC contrast \cite{stanley2026gaap}: its
persistent flow state spans steps, tasks, and services outside BDG's scope.

\textbf{History, pricing, and provenance.} Auditing reconstructs access or
whether a history determines forbidden data, and simulatable auditing also
protects denial
\cite{agrawal2004hippocratic,motwani2008auditing,kenthapadi2005simulatable};
query pricing studies determinacy, history, and information gain
\cite{koutris2012query,deep2017qirana,peng2025aria}; DP accounting and answer
reuse bound $\epsilon$ \cite{dwork2014foundations,mazmudar2022cachedp,zhang2023dprovdb}.
Statistical-database inference control studied trackers, query-set size and
overlap, and cumulative auditing
\cite{dobkin1979secure,denning1980tracker,adam1989security,kleinberg2003auditing,nabar2006robustness},
and BDG's Dependency ledger is an exact, provenance-derived, delegation- and
publication-bound engineering of that query-set-overlap lineage, bounding
how many settled predicates a task gets, not inference; PINQ's cumulative
budget is $\epsilon$ \cite{mcsherry2009pinq}, BDG's a set of declared
facts. BDG charges declared facts and successful outcomes within one signed
root, withholds delivery unless settlement succeeds, releases exact
answers, and models neither prior knowledge, denial leakage, nor
$\epsilon$; zero-novelty replay is the syntactic analogue of history-aware
pricing, and Theorem~\ref{thm:nf-soundness} covers listed rewrites only,
weaker than arbitrage-freedom. Why/where/how
provenance identifies witnesses, locations, and derivations
\cite{buneman2001why,green2007provenance,cheney2009provenance,amsterdamer2011aggregate},
and GProM and ProvSQL provide general rewrite/circuit mechanisms
\cite{arab2018gprom,senellart2018provsql,sen2026provsql}; BDG claims no new
provenance algebra but co-generates typed effects with answers and settles
cumulative novelty before release.

\textbf{Data-flow policy enforcement.} FlowGuard and DFC/Passant are the
closest database-layer comparators \cite{summers2026dataflow,summers2026passant}.
Passant formalizes optimizer-invariant aggregate predicates over each output
tuple's bag of provenance monomials and rewrites or terminates violating
queries, covering contributor thresholds, source combinations, grounding, and
prompt-bound flows that BDG does not subsume; trajectory policy is its future
work. BDG differs in temporal unit: after authorization and any flow check
it persists the three sets under one root and charges exact novelty across
queries, retries, pages, rewrites, and descendants in one root-head
transaction; DFC asks whether a flow is allowed, BDG whether another allowed
flow fits the cumulative contract (composition not evaluated).

\textbf{Authorization, delegation, and agent controls.} Task-based and
purpose-based authorization scope rights to an activity or a declared purpose
\cite{thomas1997tbac,byun2008purpose}, attenuation-only delegation is the
macaroon model \cite{birgisson2014macaroons}, query-rewriting fine-grained
control \cite{rizvi2004extending} is the per-query comparator for the closed
fragment, and usage/history control, RLS/VPD, ABAC, and query-policy systems
establish ongoing authority, quotas, and rows
\cite{park2004ucon,abadi2003history,li2003delegation,postgres16rls,hu2014abac,mehta2017qapla,zhang2022blockaid}; MCP authorization
and delegation scope capability invocation
\cite{mcp2025auth,mcp2025tools,south2025delegation}; AgentDojo evaluates
model behavior under prompt injection \cite{debenedetti2024agentdojo} and
SafeNLIDB inference risk on the model side \cite{liu2026safenlidb};
provenance-based access control \cite{park2012pbac} and CaMeL's tool-layer
capabilities \cite{debenedetti2025camel} decide admission, not cumulative
release. BDG assumes the authorization boundary, settles every descendant
against one root ledger, treats the agent and its SQL as untrusted, and
claims neither result sanitization, flow tracking, nor inference safety.

\section{Exposure Model}
\label{sec:model}

\textbf{Adversary and goal.} The agent, its plans, retries, pages, rewrites,
and delegated calls are untrusted and may be adaptive. The security goal is
bounded governed release: within one approved root family on one publication
epoch, no more than $B_X$ distinct FactIDs of each kind become
\code{AVAILABLE}, whatever sequence of admitted queries the agent issues.
Four extraction patterns motivate the three budgets and are the ones the
evaluation exercises: sweeping a Product page by page, bounded by $B_R$
(Section~\ref{sec:calibration}); aggregates that read far more base facts
than a purpose warrants, bounded by $B_D$ (the adaptive trace); probe
ladders, bounded by $B_O$ (the corpus ladder); and delegation fan-out,
bounded by the shared root ledger (the delegated child's refusal). Four
boundaries hold at this goal: it counts declared identities, not inference;
only the Catalog tie-break keys of a page order are order-only (every
\code{ORDER BY} column must be selected); every approved root and
publication epoch has fresh capacity, so release across days is bounded by
the approval workflow, not by BDG; and the settlement decision is two
data-dependent counter channels. A rejected attempt is a chosen membership
question over unaccounted facts answered by one bit, charged against $B_Q$
only and never $B_O$, so rejection capacity is $\sum B_Q$ over the approved
task tree, not $B_X$ (Section~\ref{sec:online}); a settled response returns
the per-dimension charge and the ledger's used and limit counters
(\code{exposure}, \code{exposure_budget}), so each of at most $B_O$
successful novel queries reveals $|\Delta_X|$, up to $\lceil\log_2
B_X\rceil$ bits of query-set-overlap information; returning only the
remaining budget would suffice for planning and is not implemented. The model
trusts identity, attribute, and approval assertions; Catalog and
Exposure-Profile authors and the immutable publication pipeline; PostgreSQL
execution and snapshot semantics; enforcement and Control services; key
management; and object-store access control.

\subsection{Publication Epochs and Task Binding}

BDG's upstream boundary is a completed reporting synchronization, not a
mutable transactional database; we model its compiled output as follows.

\begin{definition}[Publication epoch]
A publication epoch is
$P_e=\langle datasource,\allowbreak schema,\allowbreak snapshot\_bundle,\allowbreak catalog,\allowbreak dictionary\rangle$,
where \emph{snapshot\_bundle} maps every stable role to its immutable reporting
publication, \emph{catalog} binds the bundle's schema, policy, and lineage,
and \emph{dictionary} is the set of ordinal dictionaries. We write $h_e$
for the digest of a canonical descriptor of these five components; the
signed Catalog SHA transitively commits them, the upstream synchronization
cutoff is a trusted ETL premise, and a new synchronization creates a new
$P_{e+1}$ rather than mutating $P_e$.
\end{definition}

A deployment alias such as \code{latest publication} resolves to a concrete
Catalog digest in the authorization snapshot presented for approval and
becomes final when approval succeeds (\emph{``latest'' is resolved at
approval time, never at query time}; a draft that must follow a rollover is
reissued). Let $\mathsf Q(T)$ contain every query issued by an approved root
$T$ or any delegated descendant. Then
\begin{equation}
 \begin{aligned}
 \operatorname{publication}(T)&=P_e,\\
 \forall q\in\mathsf Q(T),\quad \operatorname{publication}(q)&=P_e.
 \end{aligned}
 \label{eq:publication-binding}
\end{equation}
The Catalog transitively binds the grant and FactID environment to that epoch;
ledger state, replay metadata, result evidence, audit events, and receipts
carry the corresponding publication and dictionary bindings. Execution,
settlement, and replay fail closed if they differ. Consequently an active root
cannot switch publications, even after the next cut becomes active for new
approvals.

\subsection{Facts and Task State}

\begin{definition}[Approved task]
\label{def:task}
An approved root task is the immutable authorization boundary
\begin{equation}
 T=(P,S,B,C), \qquad B=(B_R,B_D,B_O),
 \label{eq:task-tuple}
\end{equation}
where $P$ is the signed policy grant over the principal, data products,
fields, and scopes; $S$ is the immutable publication/snapshot binding from
Eq.~\eqref{eq:publication-binding}; $B$ gives the release, positive-output
dependency-footprint, and query-outcome ceilings; and $C$ is the signed set of
semantic and execution constraints, including the request budget $B_Q$ (the
maximum number of settled or rejected query attempts) and row/time guards.  In particular, $C$ binds the effect
profile and closed QueryPlan language, type/collation versions, semantic-View
contracts, delegation rules, replay identity, and result handling.  The
monotone accounted ledger $K(T)$ is mutable protocol state and is deliberately
\emph{not} a component of the approved tuple.
\end{definition}

The release/dependency algebra treats a FactID as a semantic object and its SHA-256 as only a database
index.  Its semantic environment is
$\Pi=\langle pg,\mathcal T,UTC,\mathcal C,D,h_C\rangle$: a PostgreSQL major
version, admitted type domain, timezone, exact deterministic collation
name/version map, immutable snapshot map, and catalog/lineage digest.  A
judgment is defined only for an \emph{admissible} $\Pi$: source schemas and
entity keys are attested, every collatable field has a deterministic collation,
and volatile expressions are absent.  Let $\nu$ be a catalog-owned source
namespace (not a view alias), $s$ an immutable snapshot, $e$ a canonical stable
entity key, $a$ a role-qualified field ID, $\tau\in\mathcal T$, and
$C_\tau(v)$ its typed canonical value.  Base identities are

\begin{align}
 f_{row}&=\langle\pi,\nu,s,e\rangle,\\
 f_{cell}&=\langle\pi,\nu,s,e,a,\tau,C_\tau(v)\rangle .
 \label{eq:fact}
\end{align}

A derived identity is
$f_d=\langle\pi,\mathcal B,k_o,N_\pi(x),\tau,C_\tau(v),CW(W)\rangle$,
where $\mathcal B=\operatorname{sort}\{(\nu,s)\}$ is the relation's snapshot
bundle, $k_o$ is the canonical output-row entity key, $N_\pi(x)$ erases aliases
and normalizes the supported expression, and
$W:\facts_{base}\rightharpoonup\mathbb N^+$
is a finite-support witness multiset (the empty support is allowed); the
product identity is the namespace projection of $\mathcal B$, never a
caller-supplied name. $CW(W)$ length-prefixes the sorted
$(\operatorname{FactHash}(f),W(f))$ pairs, the durable key is
$\mathrm{SHA256}(d_R\|\operatorname{Canon}(f))$ under the release/dependency
domain separator $d_R$, Control PostgreSQL stores $\operatorname{Canon}(f)$
and aborts on a same-hash, different-payload row, and Outcome facts use
disjoint tagged kinds under a separate separator $d_O$.

Let $N(q)$ be the accepted query normal form, $h_N$ its SHA-256, $m$ the
visible row count, $h_y$ the canonical result-observation commitment, and
$h_c$ the predicate-context commitment to the approved Catalog, immutable
publication/lineage, stable roles, and resolved expressions. Atomization
normalizes each accepted literal occurrence by PostgreSQL type, collation
name/version, operator, and canonical literal value. After exact
deduplication, let $k_a=\code{PREDICATE_ATOM}$ and define semantic atom
objects before their physical keys:
\begin{equation}
 \begin{aligned}
 a_i&=\langle k_a,\pi,h_c,p,r,f,e,\tau,\kappa,op,v\rangle,\\
 A(q)&=\{a_i\mid a_i\in\operatorname{Atomize}(q)\}.
 \end{aligned}
 \label{eq:predicate-atoms}
\end{equation}
Here $p,r,f,e$ are the semantic Product, stable role, public FieldID, and resolved-expression
digest; $\tau,\kappa,op,v$ are type, collation, operator, and canonical
literal. For any outcome Fact $f$, its physical key is
$\operatorname{FactHash}_O(f)=H(d_O\|\operatorname{Canon}(f))$.
Let $h_A$ commit the sorted $\operatorname{FactHash}_O$ values of $A(q)$ and
$k_c=\code{COMPOSITE_OUTCOME}$. BDG creates one semantic composite object
\begin{equation}
 \begin{aligned}
 c_q&=\langle k_c,\pi,\operatorname{profile}(N),h_N,h_y,m,h_c,h_A,|A(q)|\rangle,\\
 \facts_O(q)&=A(q)\cup\{c_q\},\\
 M_O(q)&=\{\operatorname{FactHash}_O(f)\mid f\in\facts_O(q)\}.
 \end{aligned}
 \label{eq:outcome-fact}
\end{equation}
Repeated literals and supported rewrites thus reuse atom identities, while
the composite commits to the normalized query, exact result observation, and
complete atom set, so every distinct successful query, including every page
of a paged result, adds one composite and $B_O$ therefore also caps the
number of distinct successful queries; the Merkle-radix set stores $M_O(q)$, empty results and
scalar zero remain explicit, and the signed grant bounds literal occurrences,
unique atoms, and atom payloads before settlement.

\begin{proposition}[Fact identity well-definedness]
\label{thm:fact-identity}
For every value in the supported PostgreSQL type domain, canonical encoding
is deterministic and injective over the typed semantic payload (that is, over
PostgreSQL semantic-value equivalence, not raw float NaN bit patterns).
\end{proposition}
\emph{Proof in the supplement.}

\begin{definition}[Exposure effect]
For query $q$ over snapshot $D_s$, the exposure effect
$\effect(q,D_s)=\langle \facts_R,\facts_D,\facts_O\rangle$ contains accounted
result facts (retaining the wire label \code{release})
$\facts_R$ and positive-output dependency-footprint facts $\facts_D$ under a
versioned profile $\pi$.  The latter are the base facts the inductive rules
below select for successfully derived output rows and cells; they are not
minimal causal provenance or all physical reads; the admitted language
requires every \code{ORDER BY} column to be selected, so only the Catalog
tie-break suffix of Page is order-only and outside this profile.
$\facts_O=A(q)\cup\{c_q\}$ contains the predicate footprint and composite
query/result identity from Eqs.~\eqref{eq:predicate-atoms}--\eqref{eq:outcome-fact}.
\end{definition}

\emph{Example (charged by the operator rules below).} Over a five-row Product with fields $(id,dept,amt)$, the
query $\pi_{id,amt}\sigma_{dept='S'}$ selects rows $r_1$--$r_3$ and charges
$6$ Result cells, $12$ Dependency facts (each selected row's row fact, its
$dept$ cell read by the predicate, and its two visible cells), and $2$
Outcome facts (the atom $dept{=}\text{'S'}$ and the composite). Splitting it
into $\pi_{id}$ and $\pi_{amt}$ charges $0/0/2$ (two new composites, the same
atom); a page returning $r_2,r_3$ charges $0/0/1$; adding $amt>5$ charges
one new atom and one composite and no new base facts; an exact replay by the
root or by a delegated child charges $0/0/0$.

For a successful $q$, settlement commits the complete candidate Result set
before the later, recoverable publication, so
$F_R^{\mathrm{available}}(q)\subseteq F_R^{\mathrm{accounted}}(q)
=F_R^{\mathrm{candidate}}(q)$; download is untracked, so accounting only
upper-bounds observation.

\begin{definition}[Task-scoped cumulative exposure]
\label{def:task-exposure}
Let $Q=\langle q_1,\ldots,q_n\rangle$ be a finite query-attempt history for a
root and its descendants, and let $Q^+\subseteq Q$ contain exactly the queries
that successfully settle under $T$. For $X\in\{R,D,O\}$,
$\facts_X(q,S)$ abbreviates $\facts_X(q,D_s)$ for the snapshot $D_s$ and
profile that $S$ and $C$ transitively bind; the two spellings denote one set.
The task exposure is
\begin{equation}
 \begin{aligned}
 E(T,Q)&=\langle E_R(T,Q),E_D(T,Q),E_O(T,Q)\rangle,\\
 E_R(T,Q)&=\bigcup_{q\in Q^+}\facts_R(q,S),\\
 E_D(T,Q)&=\bigcup_{q\in Q^+}\facts_D(q,S),\\
 E_O(T,Q)&=\bigcup_{q\in Q^+}\facts_O(q,S).
 \end{aligned}
 \label{eq:task-exposure}
\end{equation}
The components are respectively accounted result exposure (wire label
\code{release}), positive-output dependency
footprint, and query-outcome exposure. Failed or rejected attempts contribute
no set because BDG releases and commits none of their effects; this model
does not account the rejection bit. We abbreviate the singleton history by
$E(T,q)$.
\end{definition}

For every root task, the ledger service separately stores previously accounted
sets $K(T)=\accounted_T=\langle\accounted_T^R,\accounted_T^D,
\accounted_T^O\rangle$ and the approved limits
$B=\langle B_R,B_D,B_O\rangle$. Settlement computes

\begin{align}
 \Delta_T^R(q) &= \facts_R(q,D_s)\setminus\accounted_T^R,\\
 \Delta_T^D(q) &= \facts_D(q,D_s)\setminus\accounted_T^D,\\
 \Delta_T^O(q) &= \facts_O(q,D_s)\setminus\accounted_T^O.
 \label{eq:delta}
\end{align}

BDG measures cardinality independently in each dimension. A query may settle
only if
$|\accounted_T^R|+|\Delta_T^R|\leq B_R$ and
$|\accounted_T^D|+|\Delta_T^D|\leq B_D$ and
$|\accounted_T^O|+|\Delta_T^O|\leq B_O$.

\subsection{Exposure Profiles as Clearance Manifests}
\label{sec:clearance-profile}

\begin{definition}[Profile-relative clearance exactness]
\label{def:profile-relative-exactness}
For an approved $T=(P,S,B,C)$, $C$ binds one versioned Exposure Profile $\pi$.
For any admissible $\Pi$ and successful query in the closed language, write
$\facts_X^\pi(q)$ for the existing component $\facts_X(q,S)$ with its profile
binding made explicit. BDG exactly computes the canonical Result, Dependency,
and Outcome sets $\facts_R^\pi(q),\facts_D^\pi(q),\facts_O^\pi(q)$ and their
componentwise novelty
\[
 \Delta_T^X(q)=\facts_X^\pi(q)\setminus\accounted_T^X,
 \qquad X\in\{R,D,O\}.
\]
This definition fixes the scope of the word \emph{exact}: governance
accounting exactness under the signed contract and closed semantics, asserting
nothing beyond the results that follow. FactIDs are accounting identities, not
estimates of information content, knowledge, or privacy loss; BDG prevents
unaccounted governed release under a task-bound, versioned profile.
\end{definition}

Six obligations separate the assurance layers (O1--O4 semantic claims, O5
models plus transaction tests, O6 binding); none alone proves the
implementation.

The four accounting obligations---O1 output coverage, O2 positive
dependency coverage, O3 conservation under listed rewrites, splits, pages,
retries, and delegation, and O4 probe capacity (a rejected attempt creates
no atom and is charged only against the request budget)---are stated in the
supplement; the safety obligation is stated here.

\begin{property}[O5: No unaccounted governed release]
\label{prop:no-unaccounted-release}
Let $\mathsf{AVAILABLE}(q)$ mean that $q$'s canonical artifact has reached the
\code{AVAILABLE} state. For every modeled query and $X\in\{R,D,O\}$,
\[
 \mathsf{AVAILABLE}(q)\Longrightarrow
 \facts_X^\pi(q)\subseteq\accounted_T^X
 \ \wedge\ |\accounted_T^X|\leq B_X.
\]
\end{property}
Execution and private staging are not release; settlement may leave an
artifact \code{PENDING}, so the converse is false, and rejection cannot
create \code{AVAILABLE}. Evidence combines the bounded artifact and ledger
models with Control-PG fault-injection, receipt, and availability tests, not
a mechanized composition.

\textbf{O6: Profile binding.} $C$ binds effect/normal-form profiles,
type/collation, View contract, replay identity, and result handling;
derivation, settlement, replay, audit, and receipt all bind one
task/Catalog/publication/dictionary context, so a changed context cannot
reuse an old semantic replay.

\textbf{Three-way reconciliation.} The effect manifest, root-ledger heads,
and artifact/receipt/availability evidence must identify the same settled
observation and intent; any mismatch fails closed, and neither a receipt
alone nor an availability event without settlement suffices.

\begin{proposition}[Outcome separation and replay]
\label{thm:outcome-separation}
For successful queries in one predicate context, exact replay and supported
equivalent rewrites produce the same atom set and composite identity and hence
zero incremental Outcome charge. Changing one canonical predicate component
changes that atom except with a SHA-256 collision; changing the complete normal
form or result observation changes the composite except with a collision.
Consequently related probes reuse unchanged atoms but charge each novel atom
and novel composite exactly once, including for zero/empty answers.
\end{proposition}
\emph{Proof in the supplement.}

\subsection{Closed Typed Query Language}

Operational multi-source SQL first lowers to
$G_J=\langle V_J,E_J,\Theta_J\rangle$: $2$--$16$ distinct Catalog stable-role
nodes and connected equality edges. Stable-role ordering and a deterministic
fold erase aliases and accepted parenthesization, so the same connected graph
has one core term. Repeated roles, self edges, duplicate equalities, and type or
collation disagreement reject; the operational bounds and construction are
supplemental.

The complete core syntax is
\begin{align*}
e ::= {}& \operatorname{Scan}[\nu,s,r,\Gamma]
 \mid \sigma_{p;F}(e) \mid \pi_A(e) \mid e\bowtie_{\Theta}e \\
 &\mid e\cup_\delta e \mid \gamma_{G;\mathcal A}(e)
 \mid \operatorname{Page}_{O,K,o,l}(e),\\
p ::= {}& b \mid p\wedge b,\qquad b ::= a\;op\;c,\\
op\in {}&\{=,\ne,<,\le,>,\ge\}
 \cup\{\code{LIKE},\code{IN},\code{NOT IN}\},
\end{align*}
where $F$ is exactly the fields read by $p$, $\Theta$ is a nonempty
conjunction of equalities, $\cup_\delta$ is union-distinct, and
$\mathcal A\subseteq\{\code{COUNT(*)},\code{COUNT},\code{SUM},\code{MIN},
\code{MAX}\}$.  No implicit SQL construct is hidden in $e$: outer joins,
difference, negation beyond the listed scalar predicates, windows, recursion,
subqueries, volatile functions, and \code{UNION ALL} are not terms.

The partial judgment $\Pi\vdash e:\Gamma$ enforces child-local fields,
role-disjoint typed joins, identical distinctable union schemas, typed
grouping, and a proven total page order; undefined premises reject.

The nested-View front end lowers a bounded acyclic DAG of projection/rename,
inner equijoins, literal conjunctions, and at most one grouping barrier into
this core, rejecting richer SQL or unsafe dependencies; no general
View-equivalence result is claimed.

Predicates use PostgreSQL three-valued logic and retain only true rows, whereas
grouping/distinct use typed \code{IS NOT DISTINCT FROM}. The closed canonical
domain fixes integer/float widths, exact numeric and temporal encodings,
deterministic collation name/version, \code{jsonb} structural equality, and
PostgreSQL aggregate result types. Non-associative
floating SUM, unsupported casts, and overflow are undefined and settle
nothing; the complete type domain and encoders are supplemental.

\subsection{Annotated Bags and Complete Output Keys}

A relation is a typed PostgreSQL bag with unique occurrence keys and optional
proven total order; rows and cells carry support $S$, positive witness
multiset $W$, canonical lineage, and optional materialized release identity,
and every operator preserves
\begin{equation}
 \operatorname{support}(W_r)=S_r,\qquad
 \operatorname{support}(W_a)=S_a.                 \label{eq:anninv}
\end{equation}
Same-proof composition unions support and adds multiplicities; alternative
proofs union support and take pointwise maximum, so alternatives are
idempotent while join fanout remains visible. Row identity is
$\operatorname{RID}(R,t)=H(\code{relation-row},N(\Gamma),\mathcal B,t.k)$ with
$H$ typed, length-delimited, and domain-separated: Scan uses the Catalog
entity key, unary operators preserve keys, and join, union-distinct, and
group bind their complete canonical child/class/group identities; derived
Facts also bind source/snapshot, expression, value, and witness (key
construction and collision checks are supplemental).

\subsection{Operator Evaluation and Effect Extraction}

Evaluation is the partial judgment $\Pi;D\vdash e\Downarrow R$: a failed
premise yields no relation, effect, settlement, or release. A cell carries
value, type, annotation pair $(S_a,W_a)$, normalized lineage expression, and
an optional materialized release fact $\rho_a$; every rule constructs each
output cell explicitly (complete rules, NULL/empty-input cases, and page
bounds are in the supplement). Union is bag-aware and idempotent only when its typed tuples are proven
duplicate-free, grouping/distinct equivalence is \code{IS NOT DISTINCT FROM},
floating-point \code{SUM} is rejected because the bag fixes no fold order,
and pagination appends Catalog keys until the order is total; the relation is
a partial function, not a semantics for arbitrary SQL.

Finally, define materialization and the effect---they are not an implementation
afterthought:
\begin{align}
\operatorname{new}(R,t,a)&=
 f_d(\mathcal B,t.k,N(x_a),\tau_a,v_a,W_a),\\
\operatorname{mat}(R,t,a)&=
\begin{cases}
\rho_a,&\operatorname{valid}(\rho_a,R,t,a),\\
\operatorname{new}(R,t,a),&\text{otherwise},
\end{cases}\\
\facts_R(R,V)&=\{\operatorname{mat}(R,t,a)\mid t\in R,\ a\in V\},\\
\facts_D(R,V)&=\bigcup_{t\in R}S_r(t)\ \cup
                \bigcup_{t\in R,a\in V}S_a(t),\\
\rieffect_\Pi(e,D,V)&=\operatorname{normalize}
  \langle\facts_R(R,V),\facts_D(R,V)\rangle.       \label{eq:observe}
\end{align}
Here $\Pi;D\vdash e\Downarrow R$; $S_r(t)$ is row $t$'s support, the base
row facts and the predicate, join-key, group-key, and aggregate-argument cells
its derivation read, and $S_a(t)$ is the support of its cell $a$;
$\operatorname{valid}$ checks value, type and bundle, plus support for a base
fact or expression/witness for a derived fact, against the pre-existing
release fact.
Thus query bags and witness multiplicity are retained during composition, while
the two base ledgers are sets.  Equation~\eqref{eq:observe} is the declared
positive-output dependency-footprint profile: it is exact with respect to these
inductive rules, not with respect to arbitrary causal provenance or physical
source access.  Empty answers have an empty base effect except for the single
visible row of a global aggregate; BDG nevertheless adds the tested predicate
atoms and one composite outcome.

\begin{proposition}[Representation closure and partial-function semantics]
\label{thm:representation-closure}
For every admissible $\Pi$, typed finite $e$, and immutable $D$, evaluation has
at most one result.  If $\Pi;D\vdash e\Downarrow R$, $R$ satisfies
Eq.~\eqref{eq:anninv}, has canonical schema/bundle and unique row keys, and is a
valid input to every well-typed parent rule.
\end{proposition}
\emph{Proof in the supplement.}

\begin{proposition}[Dependency determinism]
\label{thm:dependency-determinism}
Fixed admissible $\Pi$, typed $e$, snapshot map $D$, and visible field set $V$
uniquely determine the positive-output dependency-footprint FactSet $\facts_D$, and hence
$\rieffect_\Pi(e,D,V)$, whenever evaluation succeeds.
\end{proposition}
\emph{Proof in the supplement.}


\subsection{Conservation Properties}

The properties below cover only the stated operators and rewrites, not
arbitrary equivalent SQL; the supplement proves Fact-set normalization and the
restricted selection--projection invariance the rewrite tests use.

\begin{definition}[Profile-indexed typed normal form $NF_{\Pi,\pi}$]
\label{def:nf}
$NF_{\Pi,\pi}$ maps accepted, well-typed inputs to canonical terms under the
one normal-form profile the task contract binds: aliases become Catalog
stable roles, the accepted join graph is canonicalized, and commutative
components are ordered by typed stable identity; equality is syntactic. Its
typed digest is the query-semantic component of replay/outcome identity,
distinct from final-ledger Fact-set $\operatorname{normalize}$.
\end{definition}

\begin{theorem}[Typed normal-form soundness]
\label{thm:nf-soundness}
For admissible $\Pi$, fixed profile $\pi$, immutable snapshot map $D$, $q_1,q_2$ in the closed
algebra or accepted graph-lowerable SQL fragment, and the same visible field
set $V$,
\[
 NF_{\Pi,\pi}(q_1)=NF_{\Pi,\pi}(q_2)\Longrightarrow
 \effect_\Pi(q_1,D,V)=\effect_\Pi(q_2,D,V).
\]
This is not completeness for arbitrary equivalent SQL: normalization neither
invents nor removes transitive/redundant equalities.
\end{theorem}
\emph{Proof in the supplement.}

For a fixed approved task, let $\pi_T$ be the normal-form profile bound in
$C$ and define the canonical replay descriptor
\begin{equation}
 \operatorname{RK}_T(q)=\langle P,S,C,\pi_T,NF_{\Pi,\pi_T}(q),
     \operatorname{params}_\Pi(q),\operatorname{encver}\rangle,
 \label{eq:replay-descriptor}
\end{equation}
where every component uses the typed, length-delimited encoding bound by the
Grant and Catalog; the implementation indexes a digest of this descriptor but
verifies the bound metadata before accepting a hit. Descriptor equality fixes
policy, publication, effect/View contracts, typed parameters, and normal form,
hence all three effect sets, so exact replay has zero novelty; the converse is
not claimed outside the stated rules. A semantic-View root $v$ compiles to a
closed core term with a binding $\beta_v$ over root identity, resolved
expressions, View contract, and predicate context; expansion over the
accepted acyclic DAG preserves the visible bag and all three effect sets when
the internal query retains $\beta_v$ (proof in the supplement), while a direct
terminal query can carry different Outcome FactIDs.

\begin{proposition}[Base-ledger split/page/join conservation]
\label{thm:base-conservation}
Merging release/dependency observations for disjoint projections or a complete
page partition equals observing the combined result. Overlapping pages and
repeated terminal observations charge each release/dependency FactID at most
once; join fanout changes witness multiplicity but not the union of dependency
support. Composite facts remain per normalized query/result outcome;
predicate atoms are reused exactly when their canonical footprint components
agree, so a family of page or threshold questions does not collapse wholesale.
\end{proposition}
\emph{Proof in the supplement.}

\section{Online Accounting}
\label{sec:online}

Terms: a publication's \emph{hot artifact} holds its entity-key-to-ordinal
map and verified hashes, its \emph{cold} payloads the content-addressed Fact
bytes, and its \emph{sidecar} the PostgreSQL table mapping attested entity
keys to ordinals; the \emph{root head} is the Control row holding a family's
three set digests and epoch, advanced only by compare-and-swap (\emph{CAS}).

Formal semantics and the RQ1 oracle cover scan/select/project, group with
four aggregates, inner equijoin, union-distinct, and page. Online lowering
admits one product, a connected 2--16-source equi-join graph, or two-branch
union-distinct, optionally grouped; the SQL-AST path covers the first two and
the semantic-View path eliminates a bounded nested DAG into them. Union is
structured-plan only, pagination is one-product only, and ``online'' does not
mean arbitrary SQL.

\subsection{Canonical Join and Semantic-View Lowering}

For joins, the PostgreSQL AST and Catalog types feed the canonical $G_J$
builder, which emits the multi-way join operator and the deterministic binary
SQL/effect fold; unsupported joins, set trees, and pagination fail closed,
and callers cannot supply roles, SQL fragments, FactIDs, or provenance. For
semantic Views, one catalog snapshot checks definitions, interfaces, and
dependency edges, expands safe acyclic Views to materialized leaves, and
emits the same core; four digests (root definition, dependency closure,
canonical plan, public interface) bind into the Grant and query, drift
detected at recompilation requires a new approval, and execution resolves
least-privilege terminal scopes before reservation.

\subsection{Snapshot Publication and Ordinal Compilation}

The publication compiler turns each frozen snapshot into immutable
per-row/per-field segments, sorting full Fact hashes and assigning 32-bit
ordinals (a FactID--ordinal bijection $D_j$ per segment; Roaring compression
changes representation, not membership \cite{chambi2016roaring}); a sidecar
maps entity keys to ordinals, payloads stay cold, and one manifest binds
snapshot, schemas, sidecar, dictionaries, and digests, so any collision
blocks publication.
Online, visible SQL and the ordinal companion run in one read-only
\code{REPEATABLE READ} transaction; the companion retains every dependency
the rules require, a k-way hash merge reproduces the witness commitment,
Release/Dependency use segmented Roaring bitmaps, Outcome hashes enter an
exact Merkle-radix set, and invalid handles, manifests, encodings, overflow,
or truncation fail closed.

\begin{proposition}[Exact bitmap refinement]
\label{thm:bitmap-refinement}
For canonical bitmaps $A$ and $B$ in one dictionary segment,
$\operatorname{Decode}(A\mathbin{\mathrm{OR}}B)=
\operatorname{Decode}(A)\cup\operatorname{Decode}(B)$,
$\operatorname{Decode}(A\mathbin{\mathrm{ANDNOT}}B)=
\operatorname{Decode}(A)\setminus\operatorname{Decode}(B)$, and
$\operatorname{popcount}(A)=|\operatorname{Decode}(A)|$. For every successful
query in the closed online algebra, decoding the streamed bitmap components
yields exactly the release and dependency components of $\effect(q,D_s)$.
\end{proposition}
\emph{Argument.} Bijective decoding turns OR, ANDNOT, and popcount into exact
set operations, and induction over the closed algebra substitutes ordinals
for singleton facts without changing support or witness commitments
(supplement).

For Outcome, hash prefixes route immutable, content-addressed leaves and
blocks, but membership always compares the full SHA-256 value. Physical
leaf/block encodings are supplemental.

\begin{proposition}[Exact incremental Outcome-set refinement]
\label{thm:outcome-radix-refinement}
Let $K_O$ be a valid Outcome root and $C_O$ a canonical candidate. Loading every
leaf family whose 16-bit prefix occurs in $C_O$, performing full-hash exact
difference/union within those families, rebuilding only their containing
blocks, and reusing all other references yields
$\operatorname{Decode}(K'_O)=\operatorname{Decode}(K_O)\cup C_O$ and charges
$C_O\setminus\operatorname{Decode}(K_O)$ exactly. Any changed member, count,
prefix, chunk, block, or root manifest changes a verified digest except with a
SHA-256 collision.
\end{proposition}
\emph{Argument.} Prefix routing partitions the full-hash universe, so an
inserted candidate affects only its own partitions; comparison is over all
256 bits and the Merkle path authenticates reused partitions.

\subsection{Atomic Ledger Settlement and Fail-Closed Artifact Publication}

For one successful query, the enforcement layer performs the following steps
(Fig.~\ref{fig:architecture-settlement}b):

\begin{enumerate}\setlength{\itemsep}{0pt}
\item Reauthorize and reserve resources; semantic replay lookup follows signed
grant/publication binding.
\item On a miss, execute visible and ordinal statements in one Business-PG
snapshot, derive all three effects, and stage encrypted Parquet. A hit loads an
already committed observation/materialization. Staging is never AVAILABLE.
\item In one Control-PG transaction, compute exact bitmap/full-hash novelty
against the root head, reject any $B_X$ excess, and CAS all three manifests;
conflicts reread and recompute every dimension.
\item The same transaction settles resources, observation/effects, PENDING
intent, terminal/registration audit, and the signed receipt.
\item Verify promotion to the canonical object, then co-commit AVAILABLE and
\code{QUERY_RESULT_CONSUMED} in a second transaction before returning the ID.
\end{enumerate}

Only root heads are mutable: pre-settlement failure rolls back heads,
observations, intent, audits, cache, and receipt, while post-settlement
promotion failure neither refunds nor re-executes but resumes the charged
PENDING artifact idempotently after verifying the canonical digest;
$(\code{root_task_id},\code{observation_sha256})$ then identifies
zero-novelty replay without rescanning effects.

The boundaries remain distinct: \emph{accounted} means settlement committed,
\emph{available} means canonical promotion plus consumption audit, and
\emph{observed} means an untracked download. Thus
$\mathsf{Observed}\subseteq\mathsf{Available}\subseteq\mathsf{Accounted}$ and
$\mathsf{Available}\Rightarrow\mathsf{Settled}$, but not conversely.

Unlike request idempotence, semantic replay binds task/grant, typed normal
form/parameters, Catalog/schema/publication/dictionaries, and every profile
and encoding version; a hit skips Business/provenance SQL but still
reauthorizes, charges resources, audits, receipts, and re-encrypts, any
mismatch takes the novel path, and $P_{e+1}$ roots cannot hit $P_e$ entries.

\subsection{Receipts and Failure Semantics}

A signed Ed25519 settlement receipt binds accounting evidence, result/object
metadata and hashes, the expected \code{PENDING} intent, and registration
audit without exposing raw values or FactIDs; availability separately requires
the hash-chained \code{QUERY_RESULT_CONSUMED} inclusion, a recovered
attestation may postdate settlement but authenticates the same intent, and a
dedicated receipt domain prevents cross-identity replay. Failures before
connector invocation release reservations, over-budget settlement creates no
canonical object or AVAILABLE row, ambiguous connector outcomes charge
resources but no exposure, and terminal replay returns the first status
without repeating Business execution.

Withholding the buffer does not hide the decision bit: a rejected attempt
returns only the code \code{EXPOSURE_BUDGET_EXHAUSTED} (no dimension, count,
or row), so the agent learns one inequality and nothing else; rejection
charges no exposure---in particular no Outcome atom---and is settled as a
failed query that consumes one unit of the request budget $B_Q$ and its
observed rows and database time, so $B_Q$ is an exposure parameter, not a
resource guard ($B_Q=110$ next to $B_O=18$ in Section~\ref{sec:delegation}
allows six rejected questions per settled predicate).

\begin{proposition}[Probing bound]
\label{prop:probing-bound}
Each rejected attempt reveals one comparison outcome---whether its novel
effect fits the remaining budgets---and consumes one unit of the attempting
task's own $B_Q$, which the prototype accounts per task; a delegated child
signs its own $B_Q$ no larger than its parent's, so a task tree of $k$ tasks
obtains at most $\sum_{i\le k}B_Q^{(i)}$ comparisons in total, independently
of $B_R$, $B_D$, and $B_O$. Each successful novel query additionally
returns its charge $|\Delta_X|$, the size of its footprint outside the
ledger; at most $B_O$ such counts exist per root family.
\end{proposition}
The bound is on comparisons, not on what a comparison reveals about
unreleased facts, and it grows with the approved task tree because request
budgets, unlike exposure budgets, are not pooled at the root; charging
Outcome atoms on rejection would fold this capacity into $B_O$ at the cost of
penalizing legitimate near-boundary queries, and is not implemented. The
protocol is not a simulatable auditor and makes no denial-noninterference
claim.

\section{Delegation}
\label{sec:delegation}

\subsection{Root-Family Conservation}

A child authorization signs both \code{root_task_id} and
\code{parent_task_id}. Its human subject, catalog, datasource, schema, and
profile remain fixed, while products, columns, scopes, sensitivity, expiry, and
all budget dimensions may only narrow; every execution revalidates the signed
parent grant and active ancestor chain; View-bound descendants inherit the
parent's contract set and cannot add or replace a contract.

All descendants resolve to one root ledger: if a parent and child request the
same fact, only the first successful settlement accounts it, revoking the
root blocks new descendant queries while a terminal request ID stays
readable, and creating workers or task nodes cannot create fresh exposure
capacity; every child grant is itself a human-approved authorization on the
Catalog's route (the prototype's only mode is manual approval), so the tree's
size, and the summed request budget of Proposition~\ref{prop:probing-bound},
is set by approvals, not by the agent. Settlement checks the settling task's own signed ceiling against
the shared family total, so a child with a lower ceiling adds novel facts only
while the family total stays within it and otherwise settles only
zero-novelty replays, as intended: a narrower child must not widen the family.

Conservation stops at the root and at the publication epoch: a second root
for the same principal, or a root approved on $P_{e+1}$, has an independent
ledger, so two approved roots on one Product double its capacity and
unchanged content may be accounted again under $P_{e+1}$ (snapshot identity
is part of FactID identity); an existing root continues against $P_e$ through
a retained route or fails closed. Cross-root deduplication would need a
tenant-wide semantic identity outside the task-scoped guarantee.

Because Definition~\ref{def:task-exposure} sums over the queries that
settled, $K_X(T)=E_X(T,Q)$ is not itself a theorem. The claim is a safety
property of the following abstract settlement system. A root state is
$(K,e)$: three decoded sets and an epoch. A settlement transaction for
$q$ reads $(K,e)$, computes $\Delta_X=\facts_X(q,S)\setminus K_X$, and
attempts one compare-and-swap that publishes $(K\cup\facts(q,S),e+1)$ only if
the swap sees epoch $e$ and $|K_X|+|\Delta_X|\le B_X$ for all $X$; a swap
that sees $e'\neq e$ rereads and recomputes; a rejected or failed attempt
publishes nothing. Transactions of a root family, including every
descendant, interleave arbitrarily but each swap is atomic.

\begin{property}[Atomic root-family budget safety]
\label{thm:root-family-safety}
In every execution of this system, every committed head equals the
componentwise union of the effects of exactly the queries whose swap
succeeded and satisfies $|K_X|\le B_X$ for all $X\in\{R,D,O\}$; the
property is unchanged when $K_X$ is represented by dictionary bitmaps or the
Merkle-radix set (Propositions~\ref{thm:bitmap-refinement}--\ref{thm:outcome-radix-refinement}).
\end{property}
\emph{Argument.} Induct on successful swaps in linearization order: the
initial head is empty, each successful swap extends the head by exactly the
effect it computed against the head it read, and the bound check precedes
the swap; the \code{ExposureLedger} model (Section~\ref{sec:formal}) and
the Control-PG race and fault-injection tests are correspondence evidence,
not a mechanized refinement.

\subsection{Budget Calibration}
\label{sec:calibration}

\textbf{Catalog-issued capacity.} The supplement's calibration table separates
profile units from resource guards and from quantities they do not estimate;
$B_Q$ belongs with the exposure units because it bounds rejected probes.
These declarations are neither risk scores nor optimization targets: 1,000
permits 1,000 declared units, and the bound profile must remain acceptable
when fully used.

\textbf{Worked policy.} The campaign's bounded trace profile binds every
exposure dimension before any counter: for ``review this department's
receipts'' it grants
$B_R/B_D/B_O=\FinalVFivePublicationRLSBudgetRelease{}/\FinalVFivePublicationRLSBudgetDependency{}/\FinalVFivePublicationRLSBudgetOutcome{}$
next to a request budget of 110 and a row budget of 1,000, so on the
\FinalVFivePublicationRLSQueries{}-query trace the counters admit
everything (\FinalVFivePublicationRLSRowsRLS{} rows in
\FinalVFivePublicationRLSQueries{} queries) while the Dependency budget
refuses at query \FinalVFivePublicationRLSBoundedRefusalIndex{}, the first
equivalent predicate that reads new base facts (Section~\ref{sec:attack-provsql}
compares counters). The ladder shows $B_O$ binding
(\FinalVFivePublicationAttackThresholdCeiling{} atoms and composites refuse
the third count probe); $B_R$ binds in the sweep case: under the campaign's
default low route ($B_R=2{,}000{,}000$, $B_D=8{,}000{,}000$, $B_O=B_Q=128$
on $10^5$-row Products) paging a $10^5\times16$ Product in 100 pages
releases $1.6\times10^6$ Facts and 100 composites, each page legal under
any row limit, and a second sweep is refused at $B_R$ (budget arithmetic,
not a measured cell). Since every page settles one composite, $B_O$ caps
pages as well as probes; $B_D$ sized to rows times aggregable fields bounds
the \emph{distinct} base facts any aggregate sequence touches, not how many
run. $B_O$ bounds how many distinct predicates a task may \emph{settle}
(one atom and composite per answered ladder step), not what an answer
reveals, and not rejected probes, which $B_Q$ bounds: a binary search on
one hidden value fits within $B_O=128$ answered steps or $B_Q$ refusals.
Ranking a hidden field is not admitted: an \code{ORDER BY} column that is
not selected is rejected (\code{ORDER_FIELD_NOT_SELECTED}), so
\code{SELECT id ... ORDER BY salary} must release \code{salary}.

\section{System Realization}
\label{sec:system}

The Go prototype uses separate Control and Business PostgreSQL 16 databases.
Its Catalog declares reporting Views, mandatory scopes, immutable
publications, entity keys, operations, approval routes, and profiles;
Products bind source, schema, snapshot, ordinal artifacts, and digests, and
startup and per-query attestation verify these bindings. Each service
instance is Catalog-bound, so rollover routes old roots to retained $P_e$
instances and new approvals to $P_{e+1}$. MCP tools cover Product discovery, task
approval/execution/delegation, View rebind, budgets, results, and receipts,
an external adapter signs Grants, and direct SQL is lowered to the same
canonical plan or fails closed, so no path executes agent-authored text;
Control PostgreSQL persists set metadata, the root head, observations, and
View bindings, results use AES-GCM, and audits form a hash chain; retention
and reclamation are specified in the supplement.

\textbf{Integration and threat boundary.} BDG sits on the path
lake/warehouse $\rightarrow$ curated data products $\rightarrow$ immutable
Reporting Publications $\rightarrow$ BDG $\rightarrow$ agent, fronting the
governed serving tier and replacing none of the lake, Catalog, IAM/HR,
OA/BPM, object store, RLS/DFC, audit, or agent platform (supplement
interface table; not a completed production deployment); OA/BPM may impose principal- or tenant-level issuance policies
across roots, while the ledger stays scoped to one root family. The trusted
parties are those of Section~\ref{sec:model}: crashes, concurrency, stale
bindings, replay, and promotion failure are in scope; compromised trusted
authorities, direct bypass, colluding independent roots, and external-tool
leakage are not. BDG enforces an approved policy without judging its
appropriateness.


\section{Three-Layer Assurance}
\label{sec:formal}

Paper theorems establish representation-independent Fact identity,
deterministic effects, and exact novelty for the closed algebra, and
Property~\ref{thm:root-family-safety} states root-family conservation over an
abstract settlement system; none proves the parser or implementation. Four
bounded TLC models \cite{lamport2002specifying} check abstract root
settlement, FactSet/bitmap correspondence, exact Outcome-set settlement with
collision fail-closed safety, and PENDING/AVAILABLE recovery at small
configurations---the ledger model has one root and one child, two requests,
two facts per dimension, limits $1/1/2$, and one replay
(\ExposureFormalStates{} states, depth \ExposureFormalDepth{}); the others
explore \BitmapFormalStates{}, \OutcomeFormalStates{}, and
\ArtifactFormalStates{} states (bounds in the supplement): sanity checks of
the specification that abstract away SQL, rows, hashes, signatures, and
ciphertext. Executable Go/PostgreSQL differential, concurrency, tamper, and
fault-injection tests check implementation correspondence (the supplement
maps layers and gaps); among them a randomized root-family test settles
\VFiveFamilyPropertyQueries{} random observation sets over
\VFiveFamilyPropertySeeds{} random delegation trees (up to
\VFiveFamilyPropertyMaxTasks{} tasks) in sequential steps and concurrent
bursts against the live Control store, checking after every step that the
committed head equals an independent plain-set union in all three
dimensions and never exceeds its limits, that each sequential charge is
exactly the novelty, and that each of the \VFiveFamilyPropertyRefused{}
refusals exceeds a limit even against the final union. We claim bounded
model checking plus implementation evidence, not a mechanized refinement.

\section{Limitations and Threats to Validity}
\label{sec:limits}

\textbf{Semantic and subject scope.} Outcome atoms and composites are
governance units, not bits; BDG omits rejected rows, non-output groups/pages,
rank-only inputs, timing, correlations, background knowledge, and physical
reads, and provides neither minimal causality nor differential privacy
(Section~\ref{sec:model} states the counter-channel and fresh-capacity
boundaries). \textbf{Query and identity scope.} Evidence uses
frozen, manifest-proven publications; the closed fragment fails closed on
richer joins, sets, paging, negation, recursion, and subqueries, and it is a
reporting-Product fragment, not ad-hoc analytics: the production lowerer
admits \TPCHLowerableExplicitJoin{} of the \TPCHQueries{} TPC-H templates
even after rewriting comma joins to explicit joins, stopping first at
subqueries (\TPCHSubqueryQueries{}), arithmetic in aggregates or projections
(\TPCHArithmeticQueries{}), and multi-product \code{LIMIT} (supplement
table). Materialized Views are opaque leaves; stable keys and publications
are trusted declarations; View drift is checked at request, approval, and
execution.

\textbf{Applicability envelope.} Publication artifacts cost
\RQFiveBytesPerFact{}~B and \RQFiveBuildMicrosPerFact{}~$\mu$s per Fact
(RQ5 Day~0) plus derivation microseconds per Fact; a $10^9$-Fact Product
would need hundreds of gigabytes and hours per build and global aggregate,
so the evaluated envelope is $10^5$--$10^6$-row Products.

\textbf{Throughput scope.} Every settlement of a root family serializes on
its head; same-root throughput falls from
\FinalVFivePublicationConcurrencyTenNaturalRequestsPerSecond{} to
\FinalVFivePublicationConcurrencyFiftyNaturalRequestsPerSecond{} contending
requests per second from width 10 to 50, and multi-root throughput is
unmeasured.

\textbf{Governance and deployment scope.} Profile correctness is trusted:
BDG validates bindings, supported semantics, and settlement, not policy
appropriateness. Its single database path and demo approval adapter provide
no production integration or practitioner study of budget calibration of the
kind marketplace-integrated agents report
\cite{tonnarelli2026dataproductmcp}; multi-engine connectors and Policy
Studio remain future work.

\section{Conclusion}

\system provides profile-relative exact accounting of modeled Result,
Dependency, and Outcome sets within one publication-bound root family, with
theorems, bounded models, and executable tests behind the scoped claim that
no governed artifact becomes \code{AVAILABLE} before atomic root-family
settlement: a release layer that makes an approved policy enforceable as
autonomous querying unfolds, without deciding what that policy should be.

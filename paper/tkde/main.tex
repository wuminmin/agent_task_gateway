\title{TaskGate: Task-Scoped Accounting of Cumulative Query Exposure over
Versioned Reporting Snapshots}

\author{Anonymous Author(s)%
\thanks{The artifact includes a controlled local PostgreSQL performance
campaign and a three-scale, representative two-source TPC-H-derived
Join--Group campaign. Results remain single-host evidence; the latter is not
an official TPC-H run and neither campaign claims production generality.}}
\date{}

\begin{abstract}
We study enterprise analytical agents that query governed reporting replicas
refreshed through scheduled daily synchronization rather than mutable OLTP
primaries. Each cut becomes an immutable, versioned Reporting Snapshot; every
approved root and delegated child remains bound to one publication for life.
Within that epoch, adaptive rewrites, pages,
retries, and delegation can accumulate disclosure. TaskGate meters this
accumulation with typed FactID sets for accounted result values, conservative
positive-output dependency footprints, and successful query outcomes. Before release,
the visible query and provenance companion observe one PostgreSQL snapshot;
TaskGate derives exact effects and atomically charges only facts novel to the
root-family ledger. Semantic replay is free of new exposure only within the
same publication-bound identity. We give semantics for a positive relational
fragment, conservation properties, and finite-state checks. A restricted
semantic-View front end recursively discovers nested PostgreSQL View DAGs and
accepts a closure only when it flattens to the same typed SPJG/JoinMany core;
task-scoped dependency binding closes new work after View drift. The current
V5 outcome profile charges canonical predicate atoms plus one composite result
identity and stores the cumulative SHA-256 membership in an incrementally
updated Merkle radix set; release and dependency retain V4's immutable
publication-time ordinals and streamed compressed bitmaps. Independent-oracle,
rewrite, concurrency, PostgreSQL, and fixed-host experiments validate the
scoped mechanisms. Four \RQFiveRows{}-row daily
publications finish every measured cycle within
\RQFiveMaxCycleS{}~s, and a retained-route campaign passes all five rollover conditions.
TaskGate targets periodic reporting publications; mutable OLTP, continuous
CDC, intra-task epoch switching, and cross-publication knowledge accounting
are outside scope.
\end{abstract}

data exposure, query auditing, provenance, adaptive workloads, cumulative

\section{Introduction}
\label{sec:introduction}

\IEEEPARstart{D}{atabase} authorization asks, ``Can this query execute?''
An adaptive database agent creates a second, cumulative question: ``How much
policy-defined exposure has this task acquired?'' During a single
human-approved task, the agent can issue many individually legal
queries. It can split a projection, overlap pages, retry with a new request
identifier, ask an equivalent query, or delegate a narrower subtask. Per-query
authorization and row limits do not state how much distinct exposure the
resulting root family has accumulated. TaskGate addresses this task-scoped
accounting question; its contract-defined exposure is not a model of the
agent's knowledge.

Counting queries is insensitive to answer size. Counting returned rows makes a
one-row aggregate appear cheap even when it depends on millions of source rows.
Counting bytes or cells varies with encoding and query shape. Monetary query
pricing has developed formal anti-arbitrage objectives
\cite{koutris2012query,deep2017qirana,peng2025aria}, while provenance explains
where results came from \cite{green2007provenance,amsterdamer2011aggregate}.
Our question is narrower and operational: how can a human authorization create
a stateful, explicit-disclosure budget that remains conserved while adaptive
clients query and delegate? The mechanism neither inspects an LLM nor depends
on an agent-specific planning algorithm; agents are one important client class.

Enterprise operational analytics commonly separates transactional systems
from reporting access. Production systems feed a governed analytical replica
through scheduled ETL or synchronization; TaskGate does not query the OLTP
primary. After each cut, TaskGate compiles the resulting dataset into an
immutable publication. For example, an overnight synchronization may finish at
01:00, after which that day's approved tasks bind to the new publication. The
next cut creates another publication for newly approved tasks, while any
unfinished task and all its descendants continue reading the prior one in a
retained, version-routed deployment; without that route, access fails closed.
Thus TaskGate addresses adaptive disclosure within one approved reporting
epoch, not freshness or consistency over a continuously changing database.

\system treats the root task as the budget subject. A result has three effects.
\emph{Accounted result exposure} identifies result values selected for logical
publication when a query successfully settles. The wire label \emph{release}
is retained for compatibility; an accounted value can remain unavailable if
artifact promotion fails.
\emph{Positive-output dependency footprint} is a contract-defined conservative
set of base facts participating in the successful derivation of selected output.
It is neither minimal causal provenance nor the complete physical read set.
This second dimension prevents a count from being accounted as one input fact
merely because it returns one cell. Both effects are sets, so a fact already
recorded in the root-family ledger has zero incremental charge.  The third,
\emph{query outcome}, is V5's union of canonical predicate atoms and one
composite binding the full normalized query/atom set to the result observation
and visible cardinality. Thus ``no row satisfies $x>100$'' and ``no row
satisfies $x>200$'' reuse any shared atoms but charge their different literal
atoms and composites even when release and dependency coincide; exact replay
remains free.

The system follows a withhold-before-settlement discipline:

\begin{center}
\small
\code{reserve -> replay lookup / execute+stream -> derive -> settle -> publish}.
\end{center}

The visible query and its ordinal provenance companion observe one frozen
publication in a PostgreSQL snapshot. The TaskGate enforcement layer releases neither while a
control-database transaction computes exact bitmap/radix-set differences, advances
one three-dimensional root head, checks all Catalog limits, settles resource
use, and persists terminal audit, a V7 settlement receipt, and a PENDING result
intent. After that atomic settlement commits, a recoverable object-store step
promotes the private staging object and a second Control transaction records
AVAILABLE/CONSUMED. A failed limit check rolls back the settlement while the
business execution remains separately measurable. Figure~\ref{fig:architecture-settlement} separates
the offline publication index from the online withhold-before-settlement path.

The preliminary preprint of this work, \emph{SessionBound: Turning Enterprise
Task Approval into Budgeted Database Sessions} (arXiv:2607.00751v1), introduced
the task-scoped authorization substrate: approval-bound short-lived database
sessions, signed task tokens, SQL/View/scope enforcement, resource budgets,
and audit receipts \cite{wu2026sessionbound}. The present, substantially
revised article develops the database-specific accounting semantics,
implementation, formal analysis, and evaluation. Its five
implementation-backed contributions are:

\begin{enumerate}
\item A versioned, typed FactID and three-set semantics separating accounted
result facts (wire label \code{release}), positive-output dependency footprints, and V5 outcomes composed
of reusable canonical predicate atoms and one query/result composite in a
restricted relational algebra.
\item A same-snapshot streamed ordinal companion for one-product plans and
connected inner-equijoin graphs over two to 16 distinct Catalog roles, plus
two-branch union-distinct, including grouping and four aggregates; a bounded
nested-View compiler eliminates transparent View layers into this existing
core rather than introducing an unaccounted SQL path.
\item A representation-independent exact settlement rule, physically refined
by immutable snapshot dictionaries, segmented compressed bitmaps, and an exact
incremental Merkle radix set for outcome hashes: atomically charge
$E_q\setminus\accounted_T$, withhold on
any limit, and make semantic replay zero-novelty for exposure (ordinary
query/row resource accounting still applies).
\item Signed, monotonic root-family delegation whose descendants share one
three-dimensional ledger, preventing task-tree fan-out from multiplying exposure capacity.
\item New formal properties and evidence for these mechanisms: three-budget
safety, exact/non-overlapping novel charge, no pre-settlement delivery, and
task-family non-amplification; algebraic/rewrite tests, a finite TLA+ ledger
model, and full-path PostgreSQL experiments through one million dependency
facts.
\end{enumerate}

The implementation does \emph{not} claim arbitrary SQL equivalence, differential
privacy, inference control, principal-wide accounting, or denial-oblivious
auditing. The join grammar canonicalizes aliases and INNER JOIN
parenthesization into any connected 2--16-role equi-join graph, with multiple
equalities per edge; 16 is an operational, not topological, guard.
Disconnected, self, outer, cross, and non-equality joins reject. Union-distinct
remains two-branch/same-product, and nested set trees and multi-input pagination
remain outside the grammar. Nested ordinary Views may have any acyclic layering
within explicit depth/size guards, but are admitted only if recursive expansion
erases that layering into one such SPJG plan with at most one aggregate
barrier; this is not general PostgreSQL View equivalence. At query time one
semantic-View root may be composed with projection/filter/grouping over an
ungrouped closure, or with pure projection over an aggregate barrier; joining
that root to another product and ordering/paging above it are not admitted.
A newly approved root creates a distinct ledger. V5 Outcome accounting bounds
the number of distinct predicate atoms and composite successful outcomes
admitted by this grammar; it is not an information-theoretic bound on the bits
revealed by either unit. These boundaries are part of the result, rather than
hidden behind a broad ``SQL support'' label.

The commercial fit is a governed analytics or operations copilot operating
inside one approved case: finance agents testing reimbursement/credit
thresholds, fraud or compliance investigators refining ``no matching case''
queries, customer-support agents searching entitlement conditions, and
delegated analysts splitting one investigation. Release limits cap repeated
value extraction, dependency limits expose large-source aggregates, and the
outcome limit makes adaptive yes/no or empty-result probing consume explicit
case capacity. Organizations that need population-level privacy across many
approved roots still require differential privacy or a tenant-wide policy;
TaskGate supplies auditable workflow conservation, not that replacement.

\cite{stanley2026gaap}. It keeps private data and permissions outside the

\subsection{History-Based Query Auditing and Inference Control}

History-based auditing treats a query log, not one query, as the security
object. Hippocratic auditing reconstructs access \cite{agrawal2004hippocratic};
batch auditing asks whether answers determine a forbidden view
\cite{motwani2008auditing}; simulatable auditing protects the accept/deny bit
\cite{kenthapadi2005simulatable}; and inference-control surveys include prior
knowledge \cite{farkas2002inference}. TaskGate neither models such knowledge nor
protects denial leakage or implicit inference. It charges a successful empty or
zero answer as one normalized proposition, not an estimate of its information,
and scopes history to one signed root family. Stronger history controls remain
complementary.

\subsection{Query Pricing and Privacy Accounting}

Query pricing studies determinacy and arbitrage \cite{koutris2012query}; QIRANA
extends history-aware pricing to broad SQL with aggregation
\cite{deep2017qirana}, and ARIA uses tuple information gain for SPJA and simple
aggregates \cite{peng2025aria}. Weighting, historical charging, and rewrite
resistance are therefore established. TaskGate instead admits against explicit
contract facts, scopes state to a root family, and withholds delivery when
atomic settlement fails.

CacheDP reuses noisy answers \cite{mazmudar2022cachedp}, while DProvDB tracks
privacy loss by analyst provenance \cite{zhang2023dprovdb}; both compose
randomized mechanisms \cite{dwork2014foundations}. TaskGate releases exact
answers, offers no $\epsilon$-DP guarantee, and bounds only facts recognized by
its active profile.

\subsection{Database Provenance}

Why-provenance identifies witness input tuples and where-provenance identifies
source locations for output values \cite{buneman2001why}; lineage traces
warehouse outputs through transformations \cite{cui2001lineage}.  How-provenance,
including semiring annotations, records how input tokens combine under positive
relational operators \cite{green2007provenance}. Cheney et al. survey this
database-provenance design space \cite{cheney2009provenance}, and aggregation
requires value-level treatment beyond tuple annotations
\cite{amsterdamer2011aggregate}.

GProM rewrites provenance questions \cite{arab2018gprom}, and ProvSQL adds
general circuit-based provenance and probability to PostgreSQL, including
multiset relational algebra and terminal aggregation
\cite{senellart2018provsql,sen2026provsql}. TaskGate
claims neither a new algebra nor a general provenance engine. It specializes
provenance to explicitly released facts and a conservative positive-output
dependency footprint, co-generates answer and effects in one snapshot, and
settles before release. ProvSQL explains the origin (and, where configured,
probability) of data for a query; TaskGate instead uses a restricted provenance
profile to manage cumulative exposure across an adaptive multi-query task. Its
profile admits finite connected inner-equijoin graphs under an operational
source guard and a two-branch union-distinct form; outer joins, negation, and
recursion remain outside it.

\subsection{Usage Control, Delegation, and Quotas}

Usage control extends authorization across an ongoing use \cite{park2004ucon};
execution-history access control makes past actions part of authorization
\cite{abadi2003history}; and delegation has mature logical foundations
\cite{li2003delegation}. PERMIS combines delegated authorization with
history-sensitive cumulative-resource decisions \cite{chadwick2008permis}.

These works establish attenuation, delegation depth, consumable authority, and
quotas. TaskGate's narrower claim is that every descendant settles its semantic
effect against one root ledger, so delegation cannot mint disclosure capacity.
The prototype is centralized; distributed vouchers would need another safety
argument.

\subsection{Database Access Control}

PostgreSQL row-level security (RLS) attaches role- and command-specific Boolean
policies that determine which rows a query may see or modify
\cite{postgres16rls}. Oracle Virtual Private Database (VPD) associates policy
functions with protected objects and transparently adds their predicates to
SQL statements \cite{oracle26vpd}. At a system-policy level, attribute-based
access control (ABAC) decides requested operations from subject, object,
action, and environment attributes \cite{hu2014abac}; XACML standardizes a
policy and request/response language for such decisions \cite{xacml2013}.
Database-backed systems such as Qapla and Blockaid similarly rewrite or validate
queries against application policy \cite{mehta2017qapla,zhang2022blockaid}, and
SafeNLIDB aligns natural-language database access with policy
\cite{liu2026safenlidb}.

These mechanisms answer whether an operation is authorized and may restrict
the rows or columns it can access. They are complementary prerequisites to
TaskGate, not baselines that it replaces. Their documented access-decision
primitives do not define typed release/dependency/outcome FactIDs, the union of
facts accumulated by one task over many legal queries, or atomic
budget-before-release settlement. TaskGate therefore assumes an approved
policy boundary and asks the additional question: how much policy-defined
exposure has the task accumulated so far?

\subsection{Agent Identity, Tool Authorization, and Security}

The Model Context Protocol (MCP) separates HTTP transport authorization from
tool discovery and invocation: its authorization profile binds OAuth access
tokens to an MCP resource, while servers advertise tools and clients issue
named tool calls \cite{mcp2025auth,mcp2025tools}. Work on authenticated agent
delegation argues for identities and scoped credentials that preserve the
user--agent authority chain \cite{south2025delegation}. Complementary agent
security work measures indirect prompt injection against tool-using agents
\cite{debenedetti2024agentdojo} and enforces runtime data-flow controls
\cite{summers2026dataflow}.

Agent identity and tool permissions answer which subject may invoke which
capability under whose authority. They do not, by themselves, provide
database fact-level accounting of what a sequence of successful tool calls has
released, depended upon, or established as query outcomes. TaskGate treats the
agent and its generated SQL as untrusted clients behind those controls, then
meters cumulative exposure across retries, pages, supported rewrites, and
delegation.

\textbf{Novelty boundary.} The literature establishes history, inference
control, pricing, provenance, database access control, agent identity and tool
authorization, mediation, delegation, quotas, task-bound SQL, receipts, and
persistent disclosure logs. Within this boundary, the present
article develops three-set FactID semantics, same-snapshot provenance, exact
novel-set settlement, and shared-root delegation, together with formal and
empirical checks. Relative to GAAP, it is database-specific semantic accounting
rather than cross-task IFC: narrower than noninterference, but stronger than
stateless authorization for the modeled threat.

\section{Exposure Model}
\label{sec:model}

\subsection{Publication Epochs and Task Binding}

TaskGate's upstream boundary is a completed reporting synchronization, not a
mutable transactional database. We model its compiled output as follows.

\begin{definition}[Publication epoch]
A publication epoch is
\begin{equation}
 \begin{aligned}
 P_e=\langle& datasource,schema,snapshot\_bundle,\\
             & catalog,dictionary\rangle,
 \end{aligned}
 \label{eq:publication-epoch}
\end{equation}
where \emph{snapshot\_bundle} maps every stable role to its immutable reporting
publication, \emph{catalog} binds the bundle's schema, policy, and lineage,
and \emph{dictionary} is the set of V4 ordinal dictionaries. We write $h_e$
for the digest of a canonical descriptor of these five components. In the prototype the
signed Catalog SHA transitively commits the datasource/schema, snapshot ID,
and manifest/dictionary/sidecar digests. The upstream synchronization cutoff
is a trusted ETL premise and co-versioned routing metadata; TaskGate does not
cryptographically enforce it as a separate manifest field.
A new synchronization creates a new $P_{e+1}$; it never mutates $P_e$.
\end{definition}

Any deployment alias such as \code{latest publication} must resolve to the
concrete Catalog digest whose transitive binding instantiates $P_e$ in the
authorization snapshot presented for approval; that binding becomes final
when approval succeeds. The prototype
has no mutable runtime alias: it eagerly writes the candidate digest into the
draft and approval revalidates it, so a deployer that requires the newest epoch
after a rollover must cancel and reissue the draft rather than rewrite it. In
particular, \emph{``latest'' is resolved at approval time, never at query time}. Let
$\mathsf Q(T)$ contain every query issued by an approved root
$T$ or any delegated descendant. Then
\begin{equation}
 \begin{aligned}
 \operatorname{publication}(T)&=P_e,\\
 \forall q\in\mathsf Q(T),\quad \operatorname{publication}(q)&=P_e.
 \end{aligned}
 \label{eq:publication-binding}
\end{equation}
The Catalog transitively binds the grant and FactID environment to that epoch;
ledger state, replay metadata, result evidence, audit events, and V7 receipts
carry the corresponding publication and dictionary bindings. Execution,
settlement, and replay fail closed if they differ. Consequently an active root
cannot switch publications, even after the next cut becomes active for new
approvals.

\subsection{Facts and Task State}

\begin{definition}[Approved task]
\label{def:task}
An approved root task is the immutable authorization boundary
\begin{equation}
 T=(P,S,B,C), \qquad B=(B_R,B_D,B_O),
 \label{eq:task-tuple}
\end{equation}
where $P$ is the signed policy grant over the principal, data products,
fields, and scopes; $S$ is the immutable publication/snapshot binding from
Eq.~\eqref{eq:publication-binding}; $B$ gives the release, positive-output
dependency-footprint, and query-outcome ceilings; and $C$ is the signed set of
semantic and execution constraints.  In particular, $C$ binds the effect
profile and closed QueryPlan language, type/collation versions, semantic-View
contracts, delegation rules, replay identity, and result handling.  The
monotone accounted ledger $K(T)$ is mutable protocol state and is deliberately
\emph{not} a component of the approved tuple.
\end{definition}

The V2 release/dependency algebra treats a FactID as a semantic object and its SHA-256 as only a database
index.  Its semantic environment is
$\Pi=\langle pg,\mathcal T,UTC,\mathcal C,D,h_C\rangle$: a PostgreSQL major
version, admitted type domain, timezone, exact deterministic collation
name/version map, immutable snapshot map, and catalog/lineage digest.  A
judgment is defined only for an \emph{admissible} $\Pi$: source schemas and
entity keys are attested, every collatable field has a deterministic collation,
and volatile expressions are absent.  Let $\nu$ be a catalog-owned source
namespace (not a view alias), $s$ an immutable snapshot, $e$ a canonical stable
entity key, $a$ a role-qualified field ID, $\tau\in\mathcal T$, and
$C_\tau(v)$ its typed canonical value.  Base identities are

\begin{align}
 f_{row}&=\langle\pi,\nu,s,e\rangle,\\
 f_{cell}&=\langle\pi,\nu,s,e,a,\tau,C_\tau(v)\rangle .
 \label{eq:fact}
\end{align}

A derived identity is
$f_d=\langle\pi,\mathcal B,k_o,N_\pi(x),\tau,C_\tau(v),CW(W)\rangle$,
where $\mathcal B=\operatorname{sort}\{(\nu,s)\}$ is the relation's snapshot
bundle, $k_o$ is the canonical output-row entity key, $N_\pi(x)$ erases aliases
and normalizes the supported expression, and
$W:\facts_{base}\rightharpoonup\mathbb N^+$
is a finite-support witness multiset (the empty support is allowed).  The product identity is not a caller-supplied
name: it is exactly the namespace projection of $\mathcal B$.  The witness
commitment $CW(W)$ length-prefixes the lexically sorted
$(\operatorname{FactHash}(f),W(f))$ pairs; the empty multiset has a separate
token.  The durable key is
$\mathrm{SHA256}(\texttt{TASKGATE-FACT-V2\textbackslash0}\|\operatorname{Canon}(f))$.
Control PostgreSQL stores $\operatorname{Canon}(f)$ and compares it on every
hash conflict; a same-hash, different-payload row aborts the transaction. V5
retains V2 release/dependency identities but gives predicate atoms and
composite outcomes disjoint tagged kinds under
$d_5=\texttt{TASKGATE-FACT-V5\textbackslash0}$.

Let $N(q)$ be the accepted V4 query normal form, $h_N$ its SHA-256, $m$ the
visible row count, $h_y$ the canonical result-observation commitment, and
$h_c$ the predicate-context commitment to the approved Catalog, immutable
publication/lineage, stable roles, and resolved expressions. Atomization
normalizes each accepted literal occurrence by PostgreSQL type, collation
name/version, operator, and canonical literal value. After exact
deduplication, let $k_a=\code{PREDICATE\_ATOM}$ and define semantic atom
objects before their physical keys:
\begin{equation}
 \begin{aligned}
 a_i&=\langle k_a,\pi_5,h_c,p,r,f,e,\tau,\kappa,op,v\rangle,\\
 A(q)&=\{a_i\mid a_i\in\operatorname{Atomize}(q)\}.
 \end{aligned}
 \label{eq:predicate-atoms}
\end{equation}
Here $p,r,f,e$ are the semantic Product, stable role, public FieldID, and resolved-expression
digest; $\tau,\kappa,op,v$ are type, collation, operator, and canonical
literal. For any V5 semantic Fact $f$, its physical key is
$\operatorname{FactHash}_5(f)=H(d_5\|\operatorname{Canon}(f))$.
Let $h_A$ commit the sorted $\operatorname{FactHash}_5$ values of $A(q)$ and
$k_c=\code{COMPOSITE\_OUTCOME}$. V5 creates one semantic composite object
\begin{equation}
 \begin{aligned}
 c_q&=\langle k_c,\pi_5,\operatorname{ver}(N),h_N,h_y,m,h_c,h_A,|A(q)|\rangle,\\
 \facts_O(q)&=A(q)\cup\{c_q\},\\
 M_O(q)&=\{\operatorname{FactHash}_5(f)\mid f\in\facts_O(q)\}.
 \end{aligned}
 \label{eq:outcome-fact}
\end{equation}
Thus repeated literals and supported rewrites reuse atom identities, while the
composite commits to the complete normalized query, exact result observation,
and the complete atom set. The Merkle radix set stores $M_O(q)$; Control
PostgreSQL stores each canonical Fact payload and fails closed on a same-hash,
different-payload collision. Empty results and scalar zero remain explicit.
The signed grant bounds raw literal occurrences, unique atoms, one atom
payload, and total atom payload before settlement.

\begin{theorem}[Fact identity well-definedness]
\label{thm:fact-identity}
For every value in the V2 supported PostgreSQL type domain, canonical encoding
is deterministic and injective over the typed semantic payload (that is, over
PostgreSQL semantic-value equivalence, not raw float NaN bit patterns).
\end{theorem}
\emph{Proof in the supplement.}

\begin{definition}[Exposure effect]
For query $q$ over snapshot $D_s$, the V5 effect
$\effect(q,D_s)=\langle \facts_R,\facts_D,\facts_O\rangle$ contains accounted
result facts (retaining the wire label \code{release})
$\facts_R$ and positive-output dependency-footprint facts $\facts_D$ under a
versioned profile $\pi$.  The latter are the conservative base facts selected
by the inductive rules below for successfully derived selected output rows and
cells; they are not claimed to be minimal causal provenance or all physical reads.
$\facts_O=A(q)\cup\{c_q\}$ contains the predicate footprint and composite
query/result identity from Eqs.~\eqref{eq:predicate-atoms}--\eqref{eq:outcome-fact}.
\end{definition}

For a successfully evaluated query $q$, let
$F_R^{\mathrm{candidate}}(q)$ be the result facts derived inside the withheld
execution, $F_R^{\mathrm{accounted}}(q)$ the subset committed by settlement,
and $F_R^{\mathrm{available}}(q)$ the facts whose canonical artifact has reached
\code{AVAILABLE}. Successful settlement commits the complete candidate set, so
$F_R^{\mathrm{accounted}}(q)=F_R^{\mathrm{candidate}}(q)$, whereas publication
is a later recoverable step and only
\[
 F_R^{\mathrm{available}}(q)\subseteq F_R^{\mathrm{accounted}}(q)
\]
is guaranteed. Download and human/agent observation are not tracked. Thus the
ledger conservatively upper-bounds both logically available and actually
observed result facts; it does not assert either event occurred.

\begin{definition}[Task-scoped cumulative exposure]
\label{def:task-exposure}
Let $Q=\langle q_1,\ldots,q_n\rangle$ be a finite query-attempt history for a
root and its descendants, and let $Q^+\subseteq Q$ contain exactly the queries
that successfully settle under $T$. For $X\in\{R,D,O\}$,
$\facts_X(q,S)$ denotes the component obtained on the dataset and profile
transitively bound by $S$ and $C$. The task exposure is
\begin{equation}
 \begin{aligned}
 E(T,Q)&=\langle E_R(T,Q),E_D(T,Q),E_O(T,Q)\rangle,\\
 E_R(T,Q)&=\bigcup_{q\in Q^+}\facts_R(q,S),\\
 E_D(T,Q)&=\bigcup_{q\in Q^+}\facts_D(q,S),\\
 E_O(T,Q)&=\bigcup_{q\in Q^+}\facts_O(q,S).
 \end{aligned}
 \label{eq:task-exposure}
\end{equation}
The components are respectively accounted result exposure (wire label
\code{release}), positive-output dependency
footprint, and query-outcome exposure. Failed or rejected attempts contribute
no set because TaskGate releases and commits none of their effects; this model
does not account the rejection bit. We abbreviate the singleton history by
$E(T,q)$.
\end{definition}

For every root task, the ledger service separately stores previously accounted
sets $K(T)=\accounted_T=\langle\accounted_T^R,\accounted_T^D,
\accounted_T^O\rangle$ and the approved limits
$B=\langle B_R,B_D,B_O\rangle$. Settlement computes

\begin{align}
 \Delta_T^R(q) &= \facts_R(q,D_s)\setminus\accounted_T^R,\\
 \Delta_T^D(q) &= \facts_D(q,D_s)\setminus\accounted_T^D,\\
 \Delta_T^O(q) &= \facts_O(q,D_s)\setminus\accounted_T^O.
 \label{eq:delta}
\end{align}

V5 measures cardinality independently in each dimension. A query may settle
only if
$|\accounted_T^R|+|\Delta_T^R|\leq B_R$ and
$|\accounted_T^D|+|\Delta_T^D|\leq B_D$ and
$|\accounted_T^O|+|\Delta_T^O|\leq B_O$.

The word ``accounted'' is intentional. Result facts describe values selected
for publication and charged at settlement, not proof of availability or
observation. Dependency FactIDs remain internal to the enforcement layer; the agent receives
only result data, counts, and receipt digests. Hence $\accounted_T^D$ is not a
set of facts known by the agent, and no component is a complete epistemic
or privacy-loss state.  The wire and storage label \code{influence} is retained
for compatibility; under the V2--V5 profiles it denotes the positive-output
dependency footprint, not causal influence.

\begin{theorem}[Outcome separation and replay]
\label{thm:outcome-separation}
For successful queries in one V5 predicate context, exact replay and supported
equivalent rewrites produce the same atom set and composite identity and hence
zero incremental Outcome charge. Changing one canonical predicate component
changes that atom except with a SHA-256 collision; changing the complete normal
form or result observation changes the composite except with a collision.
Consequently related probes reuse unchanged atoms but charge each novel atom
and novel composite exactly once, including for zero/empty answers.
\end{theorem}
\emph{Proof in the supplement.}

\subsection{Closed Typed Query Language}

Operational multi-source SQL first lowers to
$G_J=\langle V_J,E_J,\Theta_J\rangle$: $2$--$16$ distinct Catalog stable-role
nodes and connected undirected edges carrying nonempty sets of type- and
collation-compatible column equalities. Aliases and AST parenthesization are
absent. Canonicalization orders nodes by $(\nu,s,r,\text{product})$, orients and
sorts edges by node rank, and groups/sorts each edge's stable field pairs. A
deterministic fold repeatedly adds the first remaining node adjacent to the
current component with all connecting predicates, yielding one left-deep term
$\operatorname{Fold}_\Pi(G_J)$ for the existing binary algebra. Thus any
connected topology (including cycles) and accepted parenthesization of the same
graph share one term. The source ceiling is an operational guard, not a planner
or algebraic limit; repeated products/roles, self edges, and duplicate
equalities reject.

The complete core syntax is
\begin{align*}
e ::= {}& \operatorname{Scan}[\nu,s,r,\Gamma]
 \mid \sigma_{p;F}(e) \mid \pi_A(e) \mid e\bowtie_{\Theta}e \\
 &\mid e\cup_\delta e \mid \gamma_{G;\mathcal A}(e)
 \mid \operatorname{Page}_{O,K,o,l}(e),\\
p ::= {}& b \mid p\wedge b,\qquad b ::= a\;op\;c,\\
op\in {}&\{=,\ne,<,\le,>,\ge\}
 \cup\{\code{LIKE},\code{IN},\code{NOT IN}\},
\end{align*}
where $F$ is exactly the fields read by $p$, $\Theta$ is a nonempty
conjunction of equalities, $\cup_\delta$ is union-distinct, and
$\mathcal A\subseteq\{\code{COUNT(*)},\code{COUNT},\code{SUM},\code{MIN},
\code{MAX}\}$.  No implicit SQL construct is hidden in $e$: outer joins,
difference, negation beyond the listed scalar predicates, windows, recursion,
subqueries, volatile functions, and \code{UNION ALL} are not terms.

The typing judgment $\Pi\vdash e:\Gamma$ is partial: every operator requires a
typed child; predicates and projections may name only child fields; join
equalities require disjoint role-qualified schemas and identical canonical
types/collations; union branches require one identical distinctable schema;
grouping requires typed group keys and aggregates; and pagination requires a
proven total order. Undefined premises reject the plan. The complete inference
rules are provided in the supplementary material.

The nested-View front end is only a source language for this core: direct
projection/rename, INNER equality joins, AND-combined literal filters, optional
grouping, and the four aggregates. Expansion admits one aggregate barrier;
above it only pure projection/rename is legal. DISTINCT/set/CTE/subquery/window
forms, volatile dependencies, and repeated expanded stable roles reject. The
closure may have any acyclic layering up to depth 16 and any connected topology
up to 16 expanded sources, with multiple equalities per edge. The complete
grammar and resource guards are supplemental; no general PostgreSQL
View-equivalence result is claimed.

Here $\mathbb B_3=\{\mathsf T,\mathsf F,\mathsf U\}$ is PostgreSQL
three-valued logic.  Equality with either operand NULL is $\mathsf U$;
$\mathsf F\wedge x=\mathsf F$, $\mathsf T\wedge x=x$, and
$\mathsf U\wedge\mathsf U=\mathsf U$.  Selection retains only $\mathsf T$.
By contrast, grouping and distinct use the typed equivalence
$v\equiv_\tau w$ defined by \code{IS NOT DISTINCT FROM}, so NULL is equivalent
to NULL.  Predicate evaluation and ordering are PostgreSQL functions fixed by
$pg$ and $\mathcal C$, not Go approximations.

The closed scalar domain $\mathcal T$ contains exactly the canonical types
\code{smallint}, \code{integer}, \code{bigint}, \code{numeric}, \code{real},
\code{double precision}, \code{boolean}, \code{bytea}, \code{date},
\code{time without time zone}, \code{timestamp without time zone},
\code{timestamp with time zone}, \code{uuid}, \code{text}, \code{character},
\code{character varying}, and \code{jsonb}, with PostgreSQL
aliases mapped to these canonical names.  Integers retain their
16/32/64-bit ranges; exact numerics are encoded as reduced rationals and never
accepted through a binary-float conversion; floats use their IEEE width and
canonicalize NaN, infinities, and negative zero.  Temporal values have
PostgreSQL microsecond precision, \code{timestamptz} is UTC, and
\code{time with time zone} is excluded.  Text equality/order binds exact
deterministic collation name and actual version.  The text-preserving
\code{json} type is excluded: PostgreSQL retains insignificant whitespace,
object-key order, duplicate keys, and numeric lexical forms, while \code{jsonb}
has structural canonical equality \cite{postgres16json}.  Aggregate result
types are exactly PostgreSQL's:
\code{COUNT}$\to$\code{int8}, \code{SUM(int2/int4)}$\to$\code{int8},
\code{SUM(int8)}$\to$\code{numeric}, \code{SUM(numeric)}$\to$\code{numeric},
and \code{MIN/MAX}$\to$the input type.  \code{SUM(real)} and
\code{SUM(double precision)} are not admitted: IEEE-754 addition is
non-associative, so a floating-point SUM depends on the physical aggregation
order, which the typed bag and the normal form do not fix.  Any cast,
arithmetic, aggregate, witness-multiplicity, or canonical-range overflow makes
evaluation undefined and the enforcement layer releases and settles nothing.

\subsection{Annotated Bags and Complete Output Keys}

A relation is $R=\langle\Gamma,\mathcal B,M,\prec?\rangle$, where $M$ is a
finite PostgreSQL bag implemented by unique row keys.  Equal value tuples remain
distinct bag occurrences when their keys differ; only union-distinct and group
quotient occurrences into classes.  An optional $\prec$ records a proven total
order.  A row is
$t=\langle k,\{a\mapsto c_a\},S_r,W_r,O_r\rangle$ and a cell is
$c_a=\langle v,\tau,S_a,W_a,x_a,\rho_a?\rangle$.  $S$ is a finite set of
snapshot-covered base facts, $W$ a finite multiset with positive stored
multiplicities (possibly empty), $x$ a canonical
data-independent lineage expression, and $\rho$ an optional already
materialized release fact.  Every operator preserves
\begin{equation}
 \operatorname{support}(W_r)=S_r,\qquad
 \operatorname{support}(W_a)=S_a.                 \label{eq:anninv}
\end{equation}
For annotations define same-proof composition
$\bigoplus_i(S_i,W_i)=(\bigcup_iS_i,\sum_iW_i)$ and alternative-proof
composition
$\bigsqcup_i(S_i,W_i)=(\bigcup_iS_i,\max_iW_i)$, with pointwise multiset
sum/max.  Thus $A\bigsqcup A=A$, while join fanout remains in $\bigoplus$.

Let
\begin{equation}
 \operatorname{RID}(R,t)=H(\code{relation-row},N(\Gamma),\mathcal B,t.k).
 \label{eq:rid}
\end{equation}
$H$ is domain-separated, typed, and length delimited. Scan uses the Catalog
entity key; unary operators preserve the child key; join hashes the sorted
immediate-child RIDs (with operational graph joins using the canonical fold
above); union-distinct hashes the complete typed tuple; and group hashes its
canonical group key (or a distinct global token). Every derived Fact
also binds the merged source/snapshot bundle, expression, value, and witness.
Thus equal-looking results from different sources or derivations remain
distinct, while SQL aliases and caller-provided product names do not
participate. The complete output-key construction is in the supplement; a
same-hash unequal key is a validation error, not a row merge.

\subsection{Operator Evaluation and Effect Extraction}

Evaluation is the partial judgment $\Pi;D\vdash e\Downarrow R$; ``partial''
means that a failed premise yields no relation, effect, settlement, or release.
For compactness, $\alpha_r(t)=(S_r,W_r)$,
$\alpha_a(t)=(S_a,W_a)$, $\operatorname{aug}_F(t)$ replaces
$\alpha_r(t)$ by $\alpha_r(t)\oplus\bigoplus_{a\in F}\alpha_a(t)$, and cell
maps are otherwise copied.  In the derived rules a cell is written as the
5-tuple $c_a=\langle v_a,\tau_a,\alpha_a,x_a,\rho_a\rangle$: value, type, the
annotation pair $\alpha_a=(S_a,W_a)$ that expands to support and witness, the
normalized lineage expression, and the optional materialized release fact.
E-Scan alone displays the fully expanded base-cell 6-tuple; every other rule
constructs each output cell explicitly, so representation closure does not rely
on prose. Table~\ref{tab:effect-summary} retains the review-relevant accounting
choices; the complete inference rules, auxiliary functions, NULL/empty-input
cases, and page bounds are in the supplementary material.

Union is conservatively bag-aware and becomes idempotent only when its complete
typed tuples are proven duplicate-free. Grouping/distinct equivalence is
\code{IS NOT DISTINCT FROM}. Exact/integer \code{SUM} is admitted, but
floating-point \code{SUM} is rejected because the typed bag does not fix a
physical fold order. Pagination appends Catalog keys until the PostgreSQL order
is total. These restrictions make the summarized relation a partial function,
not a semantics for arbitrary SQL.

Finally, define materialization and the effect---they are not an implementation
afterthought:
\begin{align}
\operatorname{new}(R,t,a)&=
 f_d(\mathcal B,t.k,N(x_a),\tau_a,v_a,W_a),\\
\operatorname{mat}(R,t,a)&=
\begin{cases}
\rho_a,&\operatorname{valid}(\rho_a,R,t,a),\\
\operatorname{new}(R,t,a),&\text{otherwise},
\end{cases}\\
\facts_R(R,V)&=\{\operatorname{mat}(R,t,a)\mid t\in R,\ a\in V\},\\
\facts_D(R,V)&=\bigcup_{t\in R}S_r(t)\ \cup
                \bigcup_{t\in R,a\in V}S_a(t),\\
\rieffect_\Pi(e,D,V)&=\operatorname{normalize}
  \langle\facts_R(R,V),\facts_D(R,V)\rangle.       \label{eq:observe}
\end{align}
Here $\Pi;D\vdash e\Downarrow R$, and $\operatorname{valid}$ checks value,
type and bundle, plus support for a base fact or expression/witness for a
derived fact, against the pre-existing release fact.
Thus query bags and witness multiplicity are retained during composition, while
the two base ledgers are sets.  Equation~\eqref{eq:observe} is the declared
positive-output dependency-footprint profile: it is exact with respect to these
inductive rules, not with respect to arbitrary causal provenance or physical
source access.  Empty answers have an empty base effect except for the single
visible row of a global aggregate; V5 nevertheless adds the tested predicate
atoms and one composite outcome.

\subsection{Conservation Properties}

The following properties apply only to the operators and rewrites stated here.
They are not claims about all semantically equivalent SQL.

\begin{property}[Normalization]
\label{prop:normalization}
Fact-set normalization is deterministic, idempotent, and commutative under
merge.
\end{property}
\emph{Proof in the supplement.}

\begin{theorem}[Restricted projection/selection invariance]
\label{thm:projection-selection}
For $F\cup V\subseteq A$, selection followed by projection and projection
followed by selection have the same visible effect:
\[
 \rieffect_\Pi(\pi_A(\sigma_{p;F}e),D,V)=
 \rieffect_\Pi(\sigma_{p;F}(\pi_Ae),D,V).
\]
Reordering $A$ also preserves this normalized terminal effect.
\end{theorem}
\emph{Proof in the supplement.}

\begin{definition}[Profile-indexed typed normal form $NF_{\Pi,\pi}$]
\label{def:nf}
$NF_{\Pi,\pi}$ maps accepted, well-typed inputs to canonical terms under the
normal-form profile fixed by the task contract. Multi-source SQL
first replaces aliases by Catalog stable roles, orders graph nodes, endpoint
pairs, edges, and per-edge predicates as above, then applies
$\operatorname{Fold}_\Pi$. Structure-recursive normalization erases display
names; sorts conjunctions, dependency/projection fields, group keys,
aggregates, binary join children/equalities, and union children by stable field,
expression, or digest; collapses an identical union branch only when
full-tuple distinctness is proven; and canonicalizes a stable page suffix.
Equality of normal forms is syntactic. Let $\pi_3$ denote the legacy V2--V4
Outcome path and $\pi_5$ the V5 predicate/composite path. Their version bindings are
\[
\begin{aligned}
 \operatorname{ver}(NF_{\Pi,\pi_3})
   &= \text{\code{taskgate-query-normal-form-v3}},\\
 \operatorname{ver}(NF_{\Pi,\pi_5})
   &= \text{\code{taskgate-query-normal-form-v4}}.
\end{aligned}
\]
Neither version performs outer-join, arithmetic, window, subquery, or general
SQL equivalence reasoning. The complete typed digest for the profile bound by
the task remains the query-semantic component of replay/outcome identity;
authorization and settlement also bind grant/policy/effect context. The
graph-only digest is diagnostic, and previously admitted encodings are
unchanged. Query normalization is distinct from final-ledger Fact-set
$\operatorname{normalize}$.
\end{definition}

\begin{theorem}[Typed normal-form soundness]
\label{thm:nf-soundness}
For admissible $\Pi$, fixed profile $\pi$, immutable snapshot map $D$, $q_1,q_2$ in the closed
algebra or accepted graph-lowerable SQL fragment, and the same visible field
set $V$,
\[
 NF_{\Pi,\pi}(q_1)=NF_{\Pi,\pi}(q_2)\Longrightarrow
 \effect_\Pi(q_1,D,V)=\effect_\Pi(q_2,D,V).
\]
This is not completeness for arbitrary equivalent SQL: normalization neither
invents nor removes transitive/redundant equalities.
\end{theorem}
\emph{Proof in the supplement.}

For a fixed approved task, let $\pi_T$ be the normal-form profile bound in
$C$ and define the canonical replay descriptor
\begin{equation}
 \operatorname{RK}_T(q)=\langle P,S,C,\pi_T,NF_{\Pi,\pi_T}(q),
     \operatorname{params}_\Pi(q),\operatorname{encver}\rangle,
 \label{eq:replay-descriptor}
\end{equation}
where every component uses the typed, length-delimited encoding already bound
by the Grant and Catalog. The implementation indexes a digest of this
descriptor but verifies the bound metadata before accepting a hit.

\begin{theorem}[Canonical replay consistency]
\label{thm:canonical-replay}
For a fixed $T=(P,S,B,C)$ and two accepted queries $q_1,q_2$,
\[
 \operatorname{RK}_T(q_1)=\operatorname{RK}_T(q_2)
 \quad\Longrightarrow\quad E(T,q_1)=E(T,q_2).
\]
If $q_1$ has already committed to $K(T)$, settling $q_2$ has
$\Delta_T^X(q_2)=\varnothing$ for every $X\in\{R,D,O\}$.
\end{theorem}
\emph{Proof sketch.} Descriptor equality fixes the approved policy, immutable
publication, effect/View contracts, typed parameters, and normal form.
Theorem~\ref{thm:nf-soundness} therefore gives identical accounted-result and
dependency-footprint FactSets. For $\pi_T=\pi_5$,
Eqs.~\eqref{eq:predicate-atoms}--\eqref{eq:outcome-fact} give the same atom set
and composite identity; for $\pi_T=\pi_3$, the legacy single-Outcome
construction uses its bound V3 normal form. The first settlement placed all three
sets in $K(T)$, so each subsequent set difference is empty. The converse is
not claimed: equivalent SQL outside the stated normalization rules can have
different descriptors and incur a new outcome.

Let $\operatorname{Expand}_C(v)=(e,\mu,\beta_v)$ denote successful compilation
of a semantic-View root $v$ into a closed core term $e$, with $\mu$ mapping its
ordered public fields to stable terminal FieldIDs. The binding $\beta_v$
commits the root Product/public-field identity, resolved expressions, signed
View contract, and V5 predicate context. Compilation defines the View query
normal form from $e$ while retaining $\beta_v$ in $C$.

\begin{theorem}[View expansion preservation]
\label{thm:view-expansion}
If $\operatorname{Expand}_C(v)=(e,\mu,\beta_v)$ succeeds for task $T$, snapshot $S$,
and an admitted View query $q_v$ requests public fields $V$, let
$q_e^{\beta_v}$ be its internal lowered core query over $e$ and $\mu(V)$ while
preserving that binding. Then $q_v$ and $q_e^{\beta_v}$ have the same
typed visible bag and
\[
 E(T,q_v)=E(T,q_e^{\beta_v})
\]
componentwise in accounted result exposure (wire label \code{release}),
positive-output dependency footprint, and
query-outcome exposure. No preservation claim is made when expansion rejects
or for PostgreSQL constructs outside the admitted View grammar. An ordinary
public query directly against a terminal Product need not have the same V5
Outcome FactIDs: it carries a different public-product contract. Release and
dependency effects remain equal when their lowered core term and terminal
bindings are equal, but Outcome equality additionally requires $\beta_v$.
\end{theorem}
\emph{Proof sketch.} Induct over the acyclic View DAG. A terminal View maps to
the Catalog-bound Scan over the same publication. Each transparent
projection/rename, literal selection, and inner equijoin compiles to its
corresponding core operator; stable FieldIDs erase aliases while preserving
types, collations, row keys, and annotations. The only aggregate barrier maps
once to the matching group operator, and the compiler permits only projection
above it. Hence induction preserves the visible bag and the release/dependency
extraction of Eq.~\eqref{eq:observe}. Because the internal query preserves
$\beta_v$, its atoms retain the same root public-field identities, resolved
expressions, View binding, and predicate context; the result digest,
cardinality, atom set, and composite FactID therefore agree.

\begin{theorem}[Base-ledger split/page/join conservation]
\label{thm:base-conservation}
Merging release/dependency observations for disjoint projections or a complete
page partition equals observing the combined result. Overlapping pages and
repeated terminal observations charge each release/dependency FactID at most
once; join fanout changes witness multiplicity but not the union of dependency
support. V5 composite facts remain per normalized query/result outcome;
predicate atoms are reused exactly when their canonical footprint components
agree, so a family of page or threshold questions does not collapse wholesale.
\end{theorem}
\emph{Proof in the supplement.}

The legacy V2--V4 Outcome path uses \code{taskgate-query-normal-form-v3}; the
V5 predicate/composite path uses \code{taskgate-query-normal-form-v4}. Besides
the rewrites above, each profile binds namespace, snapshot, lineage digest,
canonical SQL types, collation
names/versions, PostgreSQL three-valued bag semantics, UTC, and exact numeric
mode. It deliberately performs no outer-join, arithmetic, window, subquery, or
general SQL equivalence reasoning.

\section{Online Accounting}
\label{sec:online}

Formal semantics and the independent oracle cover scan/select/project, group
with four aggregates, inner equijoin, union-distinct, and page. Online lowering
admits one product, a connected 2--16-source equi-join graph, or two-branch
union-distinct, optionally grouped. The SQL-AST path covers the first two;
the semantic-View path first eliminates a bounded nested DAG into the same
first-two forms. Union is structured-plan only and pagination is one-product only. Paired
PostgreSQL tests derive effects for hidden keys, join fanout, union members,
aggregates, and page withholding; ``online'' does not mean arbitrary SQL.

\subsection{Canonical Join and Semantic-View Lowering}

For joins, the PostgreSQL AST and Catalog types feed the canonical $G_J$
builder, which emits existing \code{JoinMany} and the deterministic binary
SQL/effect fold. Edges may carry multiple compatible equalities; topology and
accepted parenthesization are otherwise unrestricted. The 16-source guard
bounds SQL/evidence width and PostgreSQL planning work. Disconnected, self-,
outer, cross, non-equality, natural, and \code{USING} joins fail closed, as do
union-all, nested set trees, and multi-input pagination. Union-distinct retains
two filtered branches of one product and an explicit complete deduplication
schema. Callers cannot choose semantic roles or supply SQL fragments, FactIDs,
or provenance; aliases are syntactic and roles are Catalog identities.

For a semantic-View product, one catalog snapshot combines exact
\code{pg\_get\_viewdef} bytes, ordered type/collation interfaces, and
\code{pg\_rewrite}/\code{pg\_depend} edges; parsed references must agree.
DFS recursively expands ordinary Views, rejects cycles/unsafe dependencies,
and stops only at Catalog-mapped populated materialized Views. The pure
compiler resolves aliases to stable roles and emits the existing $G_J$,
\code{JoinMany}, filters, projection, and optional group. Guards are 16
expanded sources/depth, 64 nodes, 128 dependency edges/predicates, and 1~MiB
of definitions; details are supplemental.

The Catalog contract separates four digests: exact root definition,
transitive dependency closure, alias-free canonical plan, and ordered public
interface. A domain-separated task digest binds the sorted product contracts
in the approval Manifest/Grant and query record. Request, approval callback,
and each new query recompile it; the connector makes the final registry check
immediately before visible/evidence SQL in their same read-only
\code{REPEATABLE READ} transaction. Mismatch irreversibly records
\code{REQUIRE\_REBIND} and rejects new execution/delegation. Exact terminal
replay/history remains available; rebind creates a new root and approval rather
than mutating the old Grant.

For execution, the validated artifact is not merely drift evidence. The
composer replaces public root outputs by their bound stable FieldIDs and feeds
the expanded Scan/\code{JoinMany} plan through the existing
\code{CompileRelational} exposure path. An aggregate artifact is a hard barrier:
only projection/reordering of already computed outputs is accepted above it.
The current composer admits one outer semantic root and rejects a query-time
join to another Product and \code{ORDER BY}/\code{LIMIT}/\code{OFFSET} above
the root. The signed public Grant continues to name only that root. For each
query the TaskGate enforcement layer deterministically derives least-privilege internal grants for
the artifact's terminal Products; root scopes are translated through
\code{Artifact.Output.FieldID}, and every terminal mandatory scope must be
covered or execution rejects before reservation. These internal grants are
neither persisted nor exposed as approved Products. Consequently V4 compiles
the relational plan against each terminal's actual publication ordinals and
sidecar rather than assigning a fictitious publication to the semantic root.

\subsection{Snapshot Publication and Ordinal Compilation}

V4 first compiles each frozen Reporting Snapshot as an immutable publication.
The compiler calls the existing canonical FactID encoder, creates a separate
segment for base rows and for each base-cell field, sorts each segment by the
full 256-bit FactHash, and assigns a 32-bit ordinal. A segment is split by a
deterministic hash prefix before reaching $2^{32}$ entries. A Business-PG
sidecar maps each attested entity key to a dense row handle and the applicable
row/cell ordinals. The hot artifact contains only this map, ordinal-to-hash
arrays, bounds, and digests; canonical payloads remain in a sealed,
content-addressed cold artifact. Control storage may split and compress that
artifact into verified chunks. The publication manifest binds the datasource,
schema, snapshot, sidecar, dictionaries, compiler/profile versions, type and
collation contracts, and every artifact digest. Duplicate entity keys,
hash/payload collisions, count mismatches, or non-canonical artifacts prevent
publication.

The online compiler still validates fields, predicates, grouping, and one of
four aggregates; \code{COUNT(*)} and \code{COUNT(field)} retain distinct normal
forms. It emits a visible statement and an ordinal companion. A join companion
streams each matched source-handle tuple and the fields needed by projection, join,
filter, group, and aggregate rules. A union-distinct companion uses
\code{UNION ALL} plus a branch marker so that every member of a delivered class
remains reconstructible. Both statements pass the PostgreSQL AST policy and run
in one explicit read-only \code{REPEATABLE READ} transaction
\cite{postgres16transaction}. The small visible result is buffered; the
companion is ordered by canonical output group and streamed.

The ordinal engine retains only the current group's support bitmap, an
ordinal-to-extra-multiplicity sparse map, and query-level dependency bitmaps.
Same-proof witnesses add multiplicities and alternative proofs take their
pointwise maximum exactly as in the algebra. At a group boundary, a k-way merge
over hash-sorted segments produces the same witness commitment and derived
release FactID as Eq.~\eqref{eq:observe}; those sparse derived releases and the
outcome fact enter dynamic dictionaries. Release is therefore a union of
base-cell and derived-release bitmaps, and dependency uses base-row/base-cell
bitmaps. V5 Outcome hashes bypass a growing dynamic ordinal dictionary and
enter the exact Merkle radix set described below. Unknown handles, out-of-range
ordinals, manifest mismatch, non-canonical bitmaps or radix objects, overflow, or companion
truncation fail closed before release. The V2/V3 materialized algebra remains
the independent test oracle, not the V4 hot path.

For segment $j$, let $D_j$ be the publication-time bijection from its canonical
FactIDs to ordinals and let $\operatorname{Decode}_j(A)=
\{D_j^{-1}(x):x\in A\}$. Dynamic segments use the same interface after an exact
hash/payload collision check. Release and dependency use portable segmented Roaring bitmaps
\cite{chambi2016roaring}; compression changes representation, not membership.

\begin{theorem}[Exact bitmap refinement]
\label{thm:bitmap-refinement}
For canonical bitmaps $A$ and $B$ in one dictionary segment,
$\operatorname{Decode}(A\mathbin{\mathrm{OR}}B)=
\operatorname{Decode}(A)\cup\operatorname{Decode}(B)$,
$\operatorname{Decode}(A\mathbin{\mathrm{ANDNOT}}B)=
\operatorname{Decode}(A)\setminus\operatorname{Decode}(B)$, and
$\operatorname{popcount}(A)=|\operatorname{Decode}(A)|$. For every successful
query in the closed online algebra, decoding the streamed bitmap components
yields exactly the release and dependency components of $\effect(q,D_s)$.
\end{theorem}
\emph{Intuition.} Bijective decoding turns OR, ANDNOT, and popcount into exact
set operations; induction over the closed algebra then substitutes ordinals
for singleton facts without changing support or witness commitments. The full
proof is in the supplement.

For Outcome, the first 16 hash bits select a leaf family and the first eight
select its block. A leaf stores at most 4096 sorted full SHA-256 members; a
block manifest commits to ordered $(\mathit{prefix16},\mathit{chunk},
\mathit{leafDigest},\mathit{count})$ references; the root manifest commits to
at most 256 ordered block references and total cardinality. All objects are
immutable and content addressed.

\begin{theorem}[Exact incremental Outcome-set refinement]
\label{thm:outcome-radix-refinement}
Let $K_O$ be a valid V5 root and $C_O$ a canonical candidate. Loading every
leaf family whose 16-bit prefix occurs in $C_O$, performing full-hash exact
difference/union within those families, rebuilding only their containing
blocks, and reusing all other references yields
$\operatorname{Decode}(K'_O)=\operatorname{Decode}(K_O)\cup C_O$ and charges
$C_O\setminus\operatorname{Decode}(K_O)$ exactly. Any changed member, count,
prefix, chunk, block, or root manifest changes a verified digest except with a
SHA-256 collision.
\end{theorem}
\emph{Intuition.} Prefix routing partitions the full-hash universe; therefore
an inserted candidate can affect only its own partitions. Exact comparison is
still over all 256 hash bits, while the Merkle path authenticates reused
partitions. The refinement does not use truncated hashes as membership keys.

\subsection{Atomic Ledger Settlement and Fail-Closed Artifact Publication}

For one successful V5 query, the enforcement layer performs the following steps
(Fig.~\ref{fig:architecture-settlement}b):

\begin{enumerate}
\item Reauthorize the fixed plan and complete the ordinary resource reservation.
Lookup of a semantic replay entry occurs only after binding the signed grant and
publication.
\item On a miss, execute and buffer the visible statement while streaming its
ordinal companion in the same Business-PG snapshot, then derive exact Release
and dependency bitmaps plus the V5 Outcome candidate. On a hit, load only an already committed
observation reference and encrypted materialization.
\item Encode and encrypt the canonical Parquet result, then upload it to a
private staging key. Staging is neither canonical nor AVAILABLE and is never
returned to the caller.
\item In one Control-PG transaction, read the root head and epoch. For each
$X\in\{R,D\}$ compute $E_X\mathbin{\mathrm{ANDNOT}}K_X$ and its popcount.
For Outcome, read the small root manifest, group candidate hashes by 16-bit
prefix, load only touched eight-bit blocks and 16-bit leaf families, and
perform exact full-hash difference/union. Reject if any resulting cardinality
exceeds $B_X^{Catalog}$.
\item Publish the Release, dependency, and Outcome set manifests through one
root-head epoch compare-and-swap. Persist only new Outcome leaves, changed
blocks, and the new root manifest. On conflict, reread the head and recompute all
three dimensions; they are never committed independently.
\item In that same transaction, settle query/row/database-time resources,
store the committed observation and PENDING artifact metadata (including the
expected canonical key and object digest), append terminal audit evidence, and
persist a signed V7 settlement receipt. Commit this accounting transaction.
\item Promote staging to the canonical object key and verify the committed
object digest. A second Control-PG transaction changes PENDING to AVAILABLE,
sets \code{consumed\_at}, and appends the hash-chained
\code{QUERY\_RESULT\_CONSUMED} event. Only then return \code{result\_id}.
\end{enumerate}

Content-addressed containers and manifests are immutable; only the root head is
mutable. A budget failure, corrupt dictionary, CAS exhaustion, or settlement
persistence error rolls back heads, observations, PENDING metadata, terminal
audit, cache entry, and receipt. A private staging object may transiently
remain, but it is unavailable and is deleted or reconciled. Once settlement
commits, promotion failure does \emph{not} refund exposure, rewrite the V7
receipt, or re-execute Business SQL: the legal conservative state is
COMPLETED/charged/receipt/PENDING/not-available. Readiness fails closed until
idempotent recovery verifies and promotes the object. Saving
$(\code{root_task_id},\code{observation_digest})$ is also exact:
because a successfully committed root ledger grows monotonically, a repeated
committed observation has zero novelty without rescanning its effect payload.

Three boundaries must therefore remain distinct. \emph{Accounted} means the
ledger settlement and V7 receipt committed. \emph{Available} means canonical
object promotion and the consumption audit committed; it is the logical
release boundary. \emph{Observed} would mean a caller actually downloaded
bytes, which the prototype intentionally does not track. Thus
\[
 \begin{aligned}
 \mathsf{Observed}&\subseteq\mathsf{Available}\subseteq\mathsf{Accounted},\\
 \mathsf{Available}&\Rightarrow\mathsf{Settled}.
 \end{aligned}
\]
but settlement alone does not imply availability.

Semantic replay is distinct from same-request idempotence. Its key binds the
task and grant/scope digest, typed normal form and every parameter, Catalog,
schema, publication and dictionary-set digests, and profile/compiler/order/page/
result-encoding versions. A hit skips Business and provenance SQL but still
reauthorizes, charges ordinary query/row resources, writes audit and a new
receipt, and re-encrypts under the new query's AAD. Cross-grant mismatch, cache
miss, erased key, removed result, or failed digest verification returns to the
novel path; the enforcement layer never guesses a hit.

Activating $P_{e+1}$ changes the Catalog, publication, and dictionary-set
digests, so its semantic replay identity cannot equal a $P_e$ identity. New
tasks therefore miss the old cache by construction; entries for $P_e$ remain
usable only by roots still bound to $P_e$. No separate cache-invalidation
protocol is required for publication separation.

Let $F$ be the number of base facts in a publication, $n$ the streamed ordinal
references for a query, $s$ the number of touched segments, $c$ the number of
compressed containers touched during Release/dependency settlement, $g$ the largest one-group
support, and $x$ the number of multiplicity entries above one. Let $k$ be the
deduplicated Outcome candidate cardinality, $b$ its touched eight-bit blocks,
$\ell$ the touched leaf chunks, and $h$ the full hashes loaded from them. Publication
construction sorts facts in $O(F\log F)$ comparison work (external sorting may
bound memory) and stores $32F$ hash bytes plus sidecar, compressed bitmap, and
cold-payload artifacts. Online derivation scans $n$ references; canonical
witness output uses $O(n\log s)$ merge work and $O(s)$ merge state. Its live
semantic state is $O(g+x)$ plus compressed query bitmaps rather than $O(n)$ Go
string/map/JSON objects. Release/dependency novelty and union cost are
proportional to the $c$ touched compressed containers, not to one SQL insert
per fact. Outcome novelty cost is $O(k\log k+h+\ell+b)$ plus rebuilding a root
manifest of at most 256 references; it never scans untouched radix partitions.
Its worst case is linear in the membership and manifest references of
candidate-touched 16-bit partitions, which can approach total root size under
adversarially concentrated prefixes. Runtime telemetry reports
\code{root\_cardinality}, \code{candidate\_cardinality},
\code{blocks\_loaded}, \code{leaves\_loaded}, \code{hashes\_loaded},
\code{blocks\_reused}, and \code{leaves\_changed}. A verified
semantic replay makes exposure lookup constant-size metadata work, although
authorization, result re-encryption, audit, and ordinary resource accounting
still scale with their own payloads. These are design bounds, not V5 latency
measurements.

\subsection{Receipts and Failure Semantics}

A V7 Ed25519 \emph{settlement} receipt binds the root task, profile, Catalog SHA, dictionary set,
three effect digests, actual and charged counts, committed root epoch, result
digest, and SHA-256 of the normalized observation, in addition to authorization,
datasource, resource budget, and audit evidence. The dictionary set commits the
publication manifests. It proves accounting and the expected result/PENDING
publication intent, not availability. Subsequent availability is proved by
the hash-chained \code{QUERY\_RESULT\_CONSUMED} audit event that names the
verified canonical object; no new receipt version is required. The receipt
does not expose raw values or FactIDs.
For a View-bound task, the signed Grant transitively commits the task View
binding digest and the query record stores the same digest; exact replay cannot
cross that identity. Legacy receipt verifiers remain available, but V7 uses a
disjoint digest domain.

Failures before connector invocation release both reservations. An
over-budget settlement never creates a canonical object or AVAILABLE row;
private staging may exist transiently and is unavailable until deleted or
reconciled. Ambiguous
connector outcomes conservatively charge the ordinary resource reservation but
commit no accounted result exposure because no result effect successfully
settled. A process restart applies the same rule. Terminal request replay is
idempotent: it returns the first persisted status, resumes PENDING promotion if
needed, and never starts a second Business execution.

Withholding the buffer does not hide the decision bit. Whether settlement
accepts a query reveals whether its data-dependent novel Effect fits the
remaining budgets, and a rejected Effect is not committed to any ledger
dimension. Thus rejection can act as an uncharged threshold oracle. The current
protocol is not a simulatable auditor and makes no denial-noninterference claim.

\section{Delegation}
\label{sec:delegation}

\subsection{Root-Family Conservation}

A child authorization signs both \code{root_task_id} and
\code{parent_task_id}. Its human subject, catalog, datasource, schema, and
profile remain fixed, while products, columns, scopes, sensitivity, expiry, and
all budget dimensions may only narrow. Every execution revalidates the signed
parent grant and active ancestor chain.

View-bound descendants inherit the parent's complete original contract set;
their approved subset cannot add or replace a contract, so narrowing is not an
implicit semantic rebind.

All descendants resolve to one root ledger. If a parent and child request the
same fact, only the first successful settlement accounts it. Revoking the root
blocks new descendant queries, while an already terminal request ID remains
readable. Consequently, creating workers or task nodes cannot create fresh
exposure capacity. A child that signs a lower exposure ceiling may add novel
facts only while the shared family total remains within that ceiling; a
zero-novelty replay remains admissible.

This conservation scope stops at the root boundary. A second root task for the
same principal has an independent ledger and therefore a fresh budget if a
human approves it. The prototype has no principal-, tenant-, or organization-
wide exposure ledger, so neither delegation monotonicity nor the theorem below
prevents cross-root accumulation.

The boundary also stops at a publication epoch. The ledger subject is the pair
$(T,P_e)$, not a permanent model of the user's knowledge. A new $P_{e+1}$ is
available only to a newly approved root with a new ledger; an existing root
continues against $P_e$ through a retained version route (or fails closed if
that route is unavailable), and its ledger is neither copied nor migrated. Because
snapshot identity is part of FactID identity, unchanged business content may
be accounted again after independent approval in $P_{e+1}$. This conservative
choice deliberately avoids cross-publication deduplication. Such accounting
would require a principal- or tenant-wide semantic identity and policy, outside
the task-scoped guarantee.

\begin{theorem}[Atomic root-family budget safety]
\label{thm:root-family-safety}
For an approved task $T=(P,S,B,C)$ and any committed query history $Q$, each
$X\in\{R,D,O\}$ in the decoded root head satisfies
\[
 K_X(T)=E_X(T,Q),\qquad |K_X(T)|\le B_X.
\]
This statement is independent of whether $K_X$ is materialized as FactID rows
or represented by immutable dictionary bitmaps.
\end{theorem}
\emph{Proof sketch.} Induct on committed settlements. The initial head and
$E(T,\langle\rangle)$ are empty. For the next successful query, exact set
difference computes novelty against the inductive head; one transaction checks
all three cardinalities and one CAS publishes
$K_X(T)\leftarrow K_X(T)\cup E_X(T,q)$. A conflicting transaction retries from
the newly published head, and a rejected or failed attempt changes no head.
Every descendant resolves to this same head. Thus the committed head equals the
componentwise union in Eq.~\eqref{eq:task-exposure}, and the pre-commit checks
preserve every component bound. The representation-refinement details are in
the supplement.

\textbf{Catalog-issued capacity.} The three ceilings $B_R,B_D,B_O$ are
human-governed capacity declarations, not learned risk scores or optimization
targets. An organization publishes a versioned profile with its data product
and sensitivity policy; the approval manifest binds the complete profile to the
root task. Normal issuance grants that full approved capacity. TaskGate assigns
no value to unused capacity, does not infer a smaller allowance from Agent
behavior, and does not optimize budget utilization. An explicitly narrower
human grant remains an authorization decision, not an automatic calibration
step. Hence 1,000 means capacity for 1,000 distinct semantic facts, not
``risk 1,000,'' and the profile must remain acceptable when all 1,000 units are
consumed. Query count, row, and DB-time limits are separate availability guards.

Unit weights provide representation-independent integers, exact replay/delegation
set union, and stable audit thresholds. They do not equate harm: field and
sensitivity policy remains the first boundary. A harm model may maintain a
separate sensitivity-weighted ledger over the same FactIDs; neither that model
nor differential-privacy composition is claimed here.

\section{System Realization}
\label{sec:system}

The prototype is implemented in Go with separate Control and Business
PostgreSQL 16 databases. The default Catalog selects V5 and declares reporting views, mandatory
scopes, immutable snapshot publications, entity keys, allowed operations,
approval routes, and resource/exposure profiles. An opaque terminal Product
references a publication that binds its source, namespace, schema, snapshot,
ordinal sidecar, dictionaries, and manifest digest. A semantic-View Product
instead carries the four-digest contract above; its
recursive closure must terminate only at Catalog-mapped, populated materialized
View Products with those publication identities. Startup verifies the entire hot
artifact before activation; per-query attestation rebinds datasource identity,
database, role, PostgreSQL version, ordered view schema, and publication.
One service instance is Catalog-bound and rejects a task/Catalog mismatch.
During a publication rollover, a deployment therefore version-routes old roots
to retained $P_e$ instances while a $P_{e+1}$ instance accepts new
approvals; rollover never changes an active task in place.

Clients use MCP tools to list products, request a task, execute one structured
plan, inspect both budgets, delegate a narrower task, rebind a stale semantic
View task into a new approval draft, and retrieve results or receipts. An external approval adapter
signs the immutable grant. Arbitrary direct SQL remains available only for
legacy resource-only grants; it fails closed when exposure evidence is
required.
The Control schema stores immutable dictionary manifests and chunks, sparse
dynamic release dictionaries, content-addressed bitmap containers and set
manifests for Release/dependency, and SHA-256 Merkle-radix leaves, blocks, and
roots for Outcome. It maintains one three-dimensional head/epoch per root, committed
observations, and constant-size query references. It also stores
content-addressed canonical View-binding sets, a task-to-dependency reverse
index, and the monotonic \code{ACTIVE}/\code{REQUIRE\_REBIND} status. Canonical payload blocks are
cold and expanded only for audit; they do not occupy the enforcement layer's resident hot
heap. Result rows are encrypted with AES-GCM and audit events form a hash chain.
A single high-cardinality semaphore isolates million-fact derivation from the
small-query pool; a query-private encrypted spool is used once the configured
working-set threshold is crossed.

Publication retention follows active task references. The current publication
and every older publication with a live root retain their complete HOT, COLD,
sidecar, and dictionary artifacts locally. Once the last bound root terminates,
COLD payloads may move to audit object storage, while manifests, digests,
receipts, and audit-chain evidence remain for the policy-defined audit period.
Local artifacts and replay entries may be reclaimed only when no live root
references the epoch and its retention deadline has expired. With root
lifetimes bounded by one daily refresh interval, this normally requires the
current and immediately preceding publications; longer tasks extend the set.
The prototype does not evaluate archival bandwidth or automated garbage
collection.

The ordinal foundation is a clean-cut V4 migration, and V5 adds a disjoint
head/profile rather than reinterpreting an existing root. The process refuses activation when a legacy
per-Fact ledger is non-empty and requires an explicit offline rebuild; it does
not silently delete history, dual-write, or infer ordinal membership from an
incomplete ledger. The old materialized algebra and receipt verifiers remain
test/compatibility paths, not V5 production storage.

\section{Finite-State Analysis}
\label{sec:formal}

The split TLA+ model \code{ExposureLedger.tla} contains one root, one child, two
requests, two facts in each ledger universe, release/influence limits of one,
an Outcome limit of two, and one
terminal replay. Its transitions are reserve, execute/buffer, derive,
settle, over-budget reject, pre-execution release, replay, and root revocation.
It checks three-budget safety, exact novel charge, accounted iff settled,
no charge without settlement, buffered rejection, evidence/buffer agreement,
non-overlapping novel charges, task-family non-amplification, and at-most-once
physical execution for settled requests. It deliberately makes no artifact
availability claim.

Using pinned TLC 1.7.1, the provenance-checked run generated
\ExposureFormalStates{} states, found \ExposureFormalDistinct{} distinct states,
and reached depth \ExposureFormalDepth{} with no invariant error. Model,
configuration, and raw-log digests are validated before this manuscript builds
\cite{lamport2002specifying}.

A separate \code{ArtifactPublication.tla} model admits STAGED,
SETTLED/PENDING, failed promotion, hash mismatch, retry, recovery, and
AVAILABLE states. Failed/mismatched attempts remain PENDING and unavailable.
Its checked invariants require
AVAILABLE $\Rightarrow$ settled, AVAILABLE object hash equality with the
committed hash, rejected $\Rightarrow$ not AVAILABLE, and zero Release,
dependency, and Outcome deltas with one physical execution on recovery. The
provenance-checked run generated \ArtifactFormalStates{} states, found
\ArtifactFormalDistinct{} distinct states, and reached depth
\ArtifactFormalDepth{}. This is a safety model; without weak fairness it does
not claim that a PENDING artifact eventually becomes AVAILABLE.

This is exhaustive only for the submitted finite configuration. The model
assumes exact fact derivation, abstracts SQL bytes and cryptographic hashes, and
does not mechanically prove that Go/PostgreSQL refines TLA+. The repository
therefore includes an action-to-method-to-transaction-to-test refinement map
rather than claiming a proof that does not exist.

View compilation/rebinding is not modeled in TLA+; the ledger results start
after a View has produced a well-typed core plan and do not prove expansion.

The finite \code{ExposureBitmapRefinement.tla} model separately represents an
immutable ordinal--FactID bijection, exact OR/ANDNOT/popcount, stale-epoch
refresh, and one three-dimensional head commit. Its configured invariants
require decoded bitmap state to equal the abstract FactSet state after every
transition and a committed-observation replay to add no facts. Its independently
digest-checked TLC run generated \BitmapFormalStates{} states, found
\BitmapFormalDistinct{} distinct states, and reached depth
\BitmapFormalDepth{} without an invariant error. This bounded refinement
obligation is not a proof for unbounded dictionaries or the Go/Roaring
implementation.

The companion \code{OutcomeHashSetRefinement.tla} model is an abstract exact-set
settlement model. It checks exact difference/union, no double charge,
Outcome-budget safety, replay idempotence, and fail-closed abstract
collision/corruption states. It does not model physical prefix16 routing,
chunks, blocks, radix manifests, or unchanged-object reuse; those obligations
are covered by the executable full-rebuild-reference and PostgreSQL
regressions below. Its digest-checked run generated
\OutcomeFormalStates{} states, found \OutcomeFormalDistinct{} distinct states,
and reached depth \OutcomeFormalDepth{}.

\section{Evaluation}

\subsection{Questions and Reproducibility}

The evaluation is organized around five questions: RQ1 ground-truth accuracy;
RQ2 rewrite invariance of exposure accounting; RQ3 accounting conservation
under deterministic scripted split, page, retry, zero/empty threshold probing,
snapshot-identity substitution, join/union, delegation, and concurrency
patterns; RQ4 legacy bottlenecks and V4 ordinal-foundation gates; and RQ5 safe daily refresh. The
archived RQ1--RQ3 corpus is regenerated for \ExposureProfile{} from the
digest-bound corpus \ExposureCorpusHash{}; V5-specific outcome claims are
covered by the implementation/formal regressions stated below and are not
retroactively attributed to that corpus. RQ2's
primary evidence is closed-language FactSet/charge invariance; broad SQL
result-equivalence and detailed RQ4 protocols remain in the supplement. Each
call executes one plan against the complete signed profile; no representation-
or budget-selection planner is evaluated.

\subsection{RQ5: Daily Publication Refresh}

\textbf{Question.} Can TaskGate refresh a daily Reporting Snapshot while
preserving task binding, root-ledger isolation, and replay separation? We use
four deterministic, TPC-H-shaped (not official TPC-H) publications of
\RQFiveRows{} rows and \RQFiveFacts{} FactIDs each. Day~0 is the base; Days~1
and 2 modify the first 1\% and 5\% of sorted rows; Day~3 modifies 10\% and
inserts/deletes 1\%. Each day has an excluded calibration followed by
\RQFiveBuildRunsPerDay{} measured production build--strict-verify--receipt-bound
activate sequences. Their direct-child wall intervals and builder VmHWM exclude
Compose startup, PostgreSQL memory, and cache reset. The gate is five minutes
per summed sequence for this daily dataset, not an industry SLO.

\textbf{Correctness conditions.} After $P_{e+1}$ activates: (1) a live root
bound to $P_e$ returns $P_e$ data through its version-routed service; (2) a new
root resolves and observes $P_{e+1}$; (3) the old root head and ledger digests
are unchanged by activation and $P_{e+1}$ traffic; (4) a $P_{e+1}$ request
cannot hit a $P_e$ replay entry; and
(5) every child retains its root's publication. Publication, Catalog,
dictionary-set, direct-oracle result, cache, and ledger digests check these
conditions; result equality alone is insufficient.

\textbf{Results.} All \RQFiveTotalBuildRuns{} measured sequences pass. Maximum
build, verification, activation, and summed times are \RQFiveMaxBuildS{},
\RQFiveMaxVerifyS{}, \RQFiveMaxActivateS{}, and \RQFiveMaxCycleS{}~s;
maximum direct-builder VmHWM is \RQFiveBuilderPeakGiB{}~GiB. Each epoch is
about \RQFiveArtifactGiB{}~GiB total and \RQFiveHotArtifactMiB{}~MiB HOT. A
separate experiment-only pointer routes approvals and task IDs over four
retained Catalog-bound Services and snapshot databases. Across
\RQFiveTransitions{} switches, pointer switch p50/p95 is
\RQFiveSwitchMedianMS{}/\RQFiveSwitchTailMS{}~ms, first-query p50/p95 is
\RQFiveFirstQueryMedianMS{}/\RQFiveFirstQueryTailMS{}~ms, and semantic-replay
p50/p95 is \RQFiveReplayMedianMS{}/\RQFiveReplayTailMS{}~ms. All
\RQFiveChecksPassed{}/\RQFiveChecksTotal{} conditions pass at every switch.
The online run regenerates the same row fingerprints but re-attests the live
views, so its artifacts are independently bound rather than asserted byte-equal
to the offline timing artifacts.

\section{Limitations and Threats to Validity}
\label{sec:limits}

\textbf{Semantic scope.} V5 accounts canonical predicate atoms and one
composite identity for each successful normalized query/result, including an
empty relation or zero scalar. Each identity has unit weight rather than an
estimate of information content. Shared atoms reduce repeated-charge
arbitrage, but atom boundaries are the declared typed grammar rather than an
inference-theoretic decomposition. It does not enumerate rejected rows as
dependencies or account non-output groups/pages, order/rank-only inputs,
timing, correlations, background knowledge, or physical reads. A single rich
proposition may reveal more than one bit. The mechanism is neither minimal
causal provenance nor differential privacy.

\textbf{Decision and subject scope.} Refusal exposes an uncharged threshold bit;
no denial noninterference is claimed. Ledgers cover one root family, so repeated
approval creates fresh capacity unless an external principal/tenant policy
prevents it. The same applies across independently approved publication
epochs; TaskGate does not model or deduplicate a principal's durable knowledge.

\textbf{Query and identity scope.} The measured V4 ordinal SLO scope is a genuinely frozen,
manifest-proven publication, not a mutable source or an arbitrary MVCC view.
TaskGate targets immutable reporting publications produced by scheduled daily
synchronization. It does not query mutable OLTP primaries, serve continuously
changing CDC streams, or migrate an active root between publication epochs.
Minute- or second-level freshness would require an incremental-publication
design and a separate cross-epoch accounting argument.
Online support is one product, a connected inner-equijoin graph over two to 16
distinct Catalog roles, or a two-branch one-product union-distinct, optionally
grouped. A semantic-View root may recursively traverse an acyclic ordinary-View
DAG, but only when the closure flattens to the one-product/SPJG part of that
same core with one aggregate barrier; the prototype guards depth at 16,
reachable nodes at 64, dependency edges at 128, expanded sources at 16, and
definition bytes at 1~MiB. Graph topology/parenthesization and multiple
equalities per edge are supported within the operational source guard.
The expanded artifact enters the same relational exposure and terminal-ordinal
path, but the current query-time composer admits only one outer semantic root:
it rejects joining the root to another Product and ordering/paging above it;
above an aggregate barrier it admits pure projection only.
Disconnected, repeated-role/self, outer, cross, and non-equality joins,
aggregate-consuming joins/filters/reaggregation, union-all, nested set trees,
multi-input pagination, windows, negation, recursion, and arbitrary subqueries
fail closed. Materialized Views are opaque governed leaves, not recursively
expanded definitions. Stable
entity keys and snapshot publications are administrator declarations backed by compiler checks;
production still requires a trustworthy versioned publication pipeline and
collision review. The online gates exclude offline index build, arbitrary SQL,
mutable sources, and queueing delay.

\textbf{View-change scope.} The reverse dependency index makes affected tasks
addressable, but the prototype's safety path rechecks at request, approval, and
execution boundaries; it does not claim a continuously running DDL event
listener. Exact dependency revision changes are conservatively rebind-worthy
even if $h_{plan}$ remains equal. The current tests establish canonicalization
and fail-closed drift behavior for the restricted grammar, not general SQL
semantic preservation or View-DAG discovery/performance at enterprise scale.

\textbf{Cost and deployment.} The measured legacy per-Fact path is expensive:
the million-fact result is
\RQFourScaleHighNovelS{}/\RQFourScaleHighReplayS{}~s novel/replay and
\RQFourScaleGatewayGiB{}~GiB enforcement-layer memory. V4 removes that hot-path
representation; in the measured campaign its maximum-point novel/replay
p50 is \RQFourVFourNovelMedianS{}~s/\RQFourVFourReplayMedianMS{}~ms and its cgroup
peak is \RQFourVFourGatewayPeakMiB{}~MiB. V5's 100K-root regression establishes
touched-branch I/O shape but not production latency at 1M or under sustained
CAS contention. Immutable indexes shift rather than
erase cost: only \RQFourVFourBuildRuns{} build and one deployment were measured,
and dynamic dictionaries, same-root CAS contention, retention automation, encrypted
spooling, and audit expansion still require production evaluation. The single
enforcement-layer instance, local tokens, demo approval service, and one connector do not establish
distributed, production, multi-engine, or live-agent behavior.

\section{Conclusion}

\system conserves typed release, dependency, and outcome exposure within one
approved root family and immutable Reporting Snapshot. Approval-time
publication binding stabilizes FactIDs, replay, delegation, and exact
withhold-before-settlement accounting; dependency-aware semantic-View binding
additionally freezes each accepted nested View closure and requires a new root
and approval after drift. A later daily publication is reserved for new roots.
V5 combines V4's immutable ordinals and streamed Release/dependency bitmaps
with predicate-atom/composite Outcome semantics and an exact touched-branch
Merkle radix set under one three-dimensional CAS. The formal models and scoped campaigns support exactness, atomicity, and
compact representation on one fixed host; RQ5 additionally supports daily
rollover within its stated measurement boundary. Arbitrary SQL, mutable
OLTP/CDC, cross-publication knowledge accounting, and multi-host latency remain
outside the claim.

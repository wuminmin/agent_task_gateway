\section{Complete Inference Rules}

This section contains the full typing and big-step rules summarized in the
main paper. Undefined premises reject the plan. Operational SQL join trees are
first resolved through the canonical equi-join graph and deterministic binary
fold defined in the main paper, so the existing binary T-Join/E-Join rules
apply at every fold step. Join fields are stable role-qualified IDs; equality
requires the same canonical type and collation; union schemas are identical
including type and collation.

\subsection{Canonical Scalar Domain}

The closed domain contains \code{smallint}, \code{integer}, \code{bigint},
\code{numeric}, \code{real}, \code{double precision}, \code{boolean},\linebreak
\code{bytea}, \code{date}, \code{time without time zone}, both timestamp forms,
\code{uuid}, \code{text}, \code{character}, \code{character varying}, and
\code{jsonb}, with PostgreSQL aliases mapped to these names. Integers retain
their widths; exact numerics are reduced rationals; floats retain IEEE width
with canonical NaN, infinities, and negative zero. Temporal values use
PostgreSQL microseconds and \code{timestamptz} uses UTC. Text binds deterministic
collation name and actual version. Text-preserving \code{json},
\code{time with time zone}, and floating-point SUM are excluded. Aggregate
results follow PostgreSQL: COUNT returns \code{int8}; SUM of int2/int4 returns
\code{int8}, int8/numeric returns \code{numeric}; MIN/MAX retain input type.
Unsupported casts, arithmetic, or overflow make evaluation undefined.

\subsection{Big-Step Evaluation}

Write $\alpha_r(t)=(S_r,W_r)$ and $\alpha_a(t)=(S_a,W_a)$.
$\operatorname{aug}_F(t)$ replaces $\alpha_r(t)$ by
$\alpha_r(t)\oplus\bigoplus_{a\in F}\alpha_a(t)$ and otherwise copies the
cell map. A derived cell is
$\langle v_a,\tau_a,\alpha_a,x_a,\rho_a\rangle$. Each displayed bag is paired
with its statically derived schema and source/snapshot bundle. Every conclusion
is followed by the representation validator; failure removes the derivation.

At graph-fold step $i$, $e_1$ denotes the accumulated component and $e_2$ the
next canonical node.  The step predicate $\Theta_i$ is the union of every
per-edge predicate set connecting that node to a node already in $e_1$.
Connectivity makes $\Theta_i$ nonempty, and adding each edge when its later
endpoint enters the component consumes every graph edge exactly once.

Here $\equiv_\Gamma$ is componentwise \code{IS NOT DISTINCT FROM}. Union
support includes every candidate and every distinctness field; pointwise
maximum combines alternative witnesses. Grouping includes group-key inputs and
the complete declared aggregate argument, including NULL and non-extreme
\code{MIN/MAX} inputs. Exact/integer \code{SUM} is admitted; floating-point
\code{SUM} is undefined. Pagination uses PostgreSQL ordering plus a Catalog
key suffix that proves totality, and copies annotations only for the selected output
slice. These are positive-output dependencies, not physical-read or minimal
causal provenance.

\section{Restricted Semantic-View Front End}
\label{sec:supp-view-front-end}

\subsection{Registry and Expansion Boundary}

Let $\mathcal R$ be a finite registry keyed by canonical schema-qualified
relation names. A record contains a kind, ordered column contract, and either
(i) an ordinary-View definition and sorted direct dependencies, or (ii) the
Catalog Product identity of an opaque terminal publication. Discovery reads
\code{pg_class}, \code{pg_rewrite}, \code{pg_depend},
\code{pg_attribute}, type/collation metadata, and exact
\code{pg_get_viewdef} output in one read-only \code{REPEATABLE READ}
transaction. It also parses the definition independently; the parsed relation
set must equal the catalog-derived dependency set. This second path exposes,
and then rejects, recursive self references and unsupported built-in/object
dependencies that a relation-only dependency walk could otherwise miss.

DFS colors each ordinary View white/gray/black, so a gray back-edge rejects as
a cycle. Ordinary Views recurse; a populated materialized View is a leaf only
when mapped to an authorized Product. Raw/partitioned/foreign/system relations,
temporary or nonpersistent relations, row-security/options, unpopulated
materializations, and volatile, user-defined, or otherwise unsupported object
dependencies reject. Stable names, exact definitions, ordered columns,
dependency edges, and PostgreSQL major version form the registry revision;
transaction-local OIDs are not serialized.

For a successfully parsed View $v$, expansion computes a fragment
\[
 X(v)=\langle S,\Theta,F,G,A,O,b\rangle ,
\]
where $S$ is the occurrence-preserving sequence of governed base scans,
$\Theta$ the typed equality predicates, $F$ the typed literal filters, $G$
the group fields, $A$ the aggregate bindings, $O$ the ordered public outputs,
and $b$ records whether an aggregate barrier has been crossed. A relation
reference recursively obtains and clones its child fragment; alias-qualified
columns are substituted by the child's stable field bindings. INNER JOIN
concatenates child occurrences and equalities, selection appends conjuncts,
and direct projection substitutes output bindings. A grouped definition sets
$b$ and binds only direct group fields plus approved
\code{COUNT(*)}/\code{COUNT(field)}/\code{SUM}/\code{MIN}/\code{MAX}
expressions. If any child already has $b=1$, the parent must have exactly that
one input and be only a direct projection/rename; a join, filter, group, or new
aggregate is undefined.

The source grammar additionally excludes \code{DISTINCT}, all set operations,
CTEs/subqueries, \code{HAVING}, windows, row locking, ordering/paging,
projection expressions and casts, non-AND conditions, and non-equality join
conditions. Literal casts emitted by PostgreSQL's deparser are allowed only
when the cast's canonical type equals the resolved field type. The expanded
fragment must contain a connected equi-join graph and at most 16 distinct
Product/stable-role scans; a shared DAG child is not silently deduplicated, so
two occurrences that resolve to the same stable role reject. The implementation
also caps View depth at 16, reachable nodes at 64, dependency edges at 128,
expanded predicates at 128, and reachable definition text at 1~MiB.

After these checks, the compiler constructs the same canonical $G_J$ used for
direct SQL, emits existing \code{JoinMany}, attaches $F,G,A,O$, and invokes the
shared typed normalizer. Hence transparent nesting is eliminated before the
accounting semantics. This is a constructive mapping for the accepted AST
fragment. It is neither a theorem about PostgreSQL's full rewrite system nor a
semantic-equivalence decision procedure for rejected SQL.

At query time the composer accepts an outer plan naming one semantic root and
uses the artifact's ordered output bindings to replace public names by stable
FieldIDs. For an ungrouped artifact it composes supported projection, literal
filtering, grouping, and aggregation with the expanded input. For an artifact
that has crossed the aggregate barrier, only projection/reordering of its
already computed outputs is defined. A query-time join between the semantic
root and another Product, and \code{ORDER BY}, \code{LIMIT}, or \code{OFFSET}
above the root, are undefined in the current profile. These restrictions are
above the root: they do not reduce the arbitrary connected topology or
multi-equality edges accepted inside a closure of at most 16 sources/depth 16.
The resulting plan is passed to the existing \code{CompileRelational} path, so
its visible statement, provenance program, normal form, and terminal
ordinal bindings share the non-View implementation.

publication/sidecar bindings. The derived grants are neither signed as new
authority nor persisted or returned to the client.

\subsection{Compiler and Drift Test Evidence}

Five independent, fixed-seed \code{testing/quick} properties each execute 64
generated cases in the restricted grammar. Each generator constructs a
connected graph of two to five governed relations, forces at least one
two-equality edge, varies traversal priorities and aliases, and chooses one to
three transparent wrappers for nested cases. The properties separately check:
(i) complete-artifact determinism across repeated calls and registry/Product
insertion orders; (ii) alias invariance; (iii) connected join-order invariance;
(iv) direct-versus-nested equivalence; and (v) digest sensitivity that
distinguishes semantic, public-interface, and transitive-dependency drift.
Boundary tests additionally cover cycles, parsed/catalog dependency mismatch,
schema mismatch, safe literal casts, forbidden projection casts, occurrence-
preserving shared DAG expansion, depth 16/17, and source count 16/17.

Separate PostgreSQL integration tests discover a three-level View chain ending
at a materialized publication, verify transitive child replacement changes the
registry revision while the root definition remains equal, reject unsafe and
recursive definitions, and observe \code{repeatable read} on the query path.
These tests support deterministic implementation behavior and fail-closed
change detection. They are not a generated proof for every grammar term, a
formal refinement of PostgreSQL parsing, a multi-source View-DAG performance
study, or part of the digest-bound RQ counts in the main paper.

\section{Proofs of Main-Text Results}
\label{sec:supp-proofs}

The theorem and property names below match the labeled statements in the main
paper. References to effect extraction, annotation invariants, row identity,
and outcome identity denote the corresponding displayed main-paper
definitions; the complete operator rules they use appear above. These are
paper-level, representation-independent arguments over the declared algebra.
They do not prove the SQL parser, complete AST, PostgreSQL row execution,
cryptographic primitives, network, or ciphertext implementation.

\begin{proof}[Proof of Fact identity]
Each scalar encoder is a canonical representative of its typed equivalence
class: bounded integers use signed decimal, exact numerics reduced rationals,
floats fixed-width hexadecimal with canonical NaN and zero, temporal values
PostgreSQL microseconds (UTC for \code{timestamptz}), and NULL a disjoint token.
Every tuple component is type tagged and length delimited; every list is count
prefixed and sorted where its mathematical carrier is a set. Decoding first
recovers the unique tag and component boundaries, then the unique scalar
representatives. Therefore equal encodings imply equal typed payloads, and
determinism follows from the unique representative and ordering functions.
\end{proof}

\begin{proof}[Proof of Outcome separation and replay]
Every Outcome atom payload length-prefixes the predicate context, stable role and
FieldID, resolved expression, type/collation, operator, and canonical literal.
Changing any component changes the payload and, under the collision assumption,
its FactID. The composite length-prefixes the normal-form and result-observation
digests, row count, context, complete atom-set digest, and atom cardinality.
Exact replay or a supported rewrite makes all these components equal; changing
the normal form, result observation, or complete atom set changes the composite
payload. Exact set difference therefore charges each novel atom/composite once
and charges replay zero.
\end{proof}

\begin{proof}[Proof of Representation closure and partial-function semantics]
For an operational join graph, first use induction over the deterministic fold:
connectedness gives the next node at each step, and its nonempty $\Theta_i$
contains all predicates on edges from that node to the accumulated component,
so every edge is consumed exactly once. Then proceed by structural induction
on the resulting $e$. Scan is fixed by $D$ and constructs singleton
support/witness pairs. Select's three-valued predicate and dependency set are
fixed by $\Pi$; Select, Project, and Page only take a deterministic subbag or
copy annotations. Each binary Join enumerates a uniquely determined bag of
matching child-row pairs; disjoint schemas and the canonical pair key make its
output usable by the next fold step. Union first collapses an identical annotated branch only under
the duplicate-free full-tuple premise, then has unique typed-tuple equivalence
classes and uses deterministic same-proof union/addition within a candidate and
alternative union/max across candidates; E-Union constructs each output cell
$\langle v_a,\tau_a,\bigsqcup\alpha_a,N(\code{union}(x)),\rho_a\rangle$ from
those classes. Group has unique not-distinct classes, the explicitly defined
empty class, deterministic exact/numeric sum folds (floating-point SUM is
excluded, so no order-dependent fold arises), and one complete PostgreSQL
result per class. E-Group composes every group-key input into the row annotation
and constructs both group-key and aggregate cells from that result. Set union
with multiset sum or max preserves equal support. Total order makes Page's
slice unique. Each case constructs the annotation invariant, and validation
turns any range, collision, schema, oracle, or multiplicity violation into no
derivation.
\end{proof}

\begin{proof}[Proof of Dependency determinism]
Representation closure gives a unique $R$. Effect extraction ranges over its
unique keyed occurrences and fields. $C_\tau$, expression normalization,
bundle/key construction, witness commitment, Fact materialization, and final
set normalization are deterministic functions. Therefore both finite Fact
sets, and hence their ordered canonical encodings, are unique.
\end{proof}

\begin{proof}[Proof of Group-key completeness]
E-Group includes $\bigoplus_{g\in G}\alpha_g(t)$ in the output row annotation.
Projection preserves that annotation, and effect extraction includes every
selected output row's $S_r$ independently of $V$.
\end{proof}

\begin{proof}[Proof of Distinct-dependency completeness]
E-Union first composes every schema-field annotation into $\beta_\Gamma(t)$,
then alternative-composes all candidates into the output row annotation.
Alternative max changes multiplicity but its support is the union, which
effect extraction includes.
\end{proof}

\begin{proof}[Proof of Conservative aggregate input]
This is the aggregate-cell clause of E-Group followed by effect extraction.
PostgreSQL's scalar fold may ignore NULL or retain only an extreme value, but
the dependency rule deliberately ranges over the complete argument bag.
\end{proof}

\begin{proof}[Proof of Normalization]
By Fact identity well-definedness, a validated canonical payload has one map
key; a same-digest unequal payload aborts rather than merges. Normalization is
therefore finite-set insertion followed by lexical canonical-payload order.
Idempotence and commutativity follow from $A\cup A=A$ and $A\cup B=B\cup A$;
the fixed serialization order gives the same bytes in each case.
\end{proof}

\begin{proof}[Proof of Restricted projection/selection invariance]
Because $F\subseteq A$, both selection predicates read identical typed cells
and retain exactly the rows whose truth value is $\mathsf T$. By E-Select each
retained row receives the same
$\alpha_r(t)\oplus\bigoplus_{a\in F}\alpha_a(t)$; by E-Project both retain the
same keys and cells in $A$. Effect extraction over $V\subseteq A$ therefore
yields identical release and dependency sets. Field traversal order is absent
from Fact payloads and removed by set normalization.
\end{proof}

\begin{proof}[Proof of Typed normal-form soundness]
The SQL front end first resolves relation aliases to Catalog stable roles, so
caller-chosen aliases are absent from graph nodes, fields, and derived
expressions.  Canonical graph construction sorts nodes by Catalog semantic key,
orients each endpoint pair by node rank, coalesces predicates for that pair,
and sorts edges and their stable field-pair predicates.  The deterministic fold
then chooses the first not-yet-joined node adjacent to the accumulated component
and attaches every equality from that node to the component.  Consequently any
accepted INNER JOIN AST with the same connected graph produces the identical
binary term, regardless of source order, equality direction/order, or
parenthesization.  This is not a reassociation rule for arbitrary SQL: it
applies only after the AST has passed the equi-join graph boundary.

The remaining typed normalizer can erase only derived display names,
conjunction/set traversal order, binary join operand and predicate order, union
operand order, an identical duplicate union branch whose child is proven
full-tuple distinct, and alternate spelling of the same stable page suffix. A
Scan carries no such distinctness proof; Union and Group produce it,
Select/Page preserve it, and Project preserves it only for an unchanged schema.
Set normalization removes traversal order. Each folded Join enumerates the same
matching bag, hashes sorted child identities, and uses commutative and
associative $\cup/\oplus$. Union classes are operand independent; same-proof
member composition includes all equivalence fields, while alternative
max-merge is commutative and idempotent. An identical materialized fact is
retained, and relation-level union expressions are sorted before downstream
composition. Group keys and witness commitments are sorted. The SQL compiler
emits the same Catalog-canonical page suffix represented by the normal form.
Every accepted graph spelling therefore denotes the same folded term; each
remaining recursive rewrite preserves its effect. Structural induction over
well-typed contexts proves the result.
\end{proof}

\begin{proof}[Proof of Base-ledger split/page/join conservation]
For $V=V_A\cup V_B$, distribute both unions in effect extraction over
$V_A,V_B$; this gives
$\rieffect(R,V)=\operatorname{merge}(\rieffect(R,V_A),\rieffect(R,V_B))$.
E-Page copies each selected keyed row and cell, so a complete disjoint slice
partition distributes the same two unions over the row index set. Overlap and
repetition disappear by set idempotence. E-Join adds witness multiplicities
with $\oplus$, but effect extraction takes their support sets; repeated support
membership consequently has dependency cardinality one. A changed derived
witness may still change its release Fact, as required. Induction over the
canonical fold length applies the same support-union argument to every node in
an admitted join graph.
\end{proof}

\begin{proof}[Proof of Exact bitmap refinement]
The first three equalities follow pointwise from the dictionary bijection and
exact bitmap membership. For query derivation, structural induction follows
the same Scan, Select, Project, Join, Union, Group, and Page cases as effect
extraction. Handles substitute singleton base FactIDs; bitmap union substitutes
support-set union; sparse maps preserve witness addition/max; and hash-ordered
merging preserves the canonical witness commitment. Every case therefore
decodes to the oracle FactSet, while any missing premise aborts. For JoinMany,
induction over the deterministic fold replaces a two-source handle pair by one
handle per source in the companion tuple without changing these pointwise
arguments.
\end{proof}

\begin{proof}[Proof of Atomic root-family budget safety]
Every descendant resolves to the same root head. Exact bitmap refinement for
Release/dependency and exact Merkle-radix refinement for Outcome make each
concrete candidate decode to $K_d\cup E_d$ and its charged count to
$|E_d\setminus K_d|$. A successful epoch CAS linearizes all three candidate
heads at one point; a conflicting transaction recomputes rather than publishing
a stale difference. The precondition checks every Catalog bound and failure
publishes no head. Induction over successful CAS order establishes the modeled
union identity and all three bounds. The bounded TLA+ model separately checks
instances of this abstract transition. Correspondence to the physical
implementation is supported by executable evidence rather than by a mechanized
refinement proof.
\end{proof}

\section{Outcome Set and Radix Refinement}

The current Outcome effect is $A(q)\cup\{c_q\}$. The atomizer expands \code{IN} to
typed equality atoms and \code{NOT IN} to typed inequality atoms, removes exact
duplicates, and binds every atom to the predicate context. The composite binds
the canonical normal form, result observation, row count, context, sorted atom
set digest, and atom count. Signed limits bound raw literals, unique atoms, one
payload, and total payload before Business SQL.

The exact SHA-256 set partitions members by prefix16 into deterministic
4096-member chunks. A prefix8 block commits ordered leaf references, and the
root commits at most 256 block references and total cardinality. For a
candidate, settlement reads only its prefix8 blocks and prefix16 leaf families,
compares full hashes, rebuilds only affected leaf families/blocks, and reuses
all other digests. Hence the physical work is
$O(k\log k+h+\ell+b)$ for candidate cardinality $k$, hashes loaded $h$, leaf
chunks $\ell$, and blocks $b$, plus a root manifest bounded by 256 references;
the algorithm never scans untouched radix partitions. Its worst-case cost is
linear in the membership and manifest references of candidate-touched
partitions, which may approach total root size under adversarially concentrated
prefixes. The source-controlled PostgreSQL regression commits a
\VFiveRootCardinality{}-member object graph before an independent merge
transaction; the \VFiveSamePrefixMembers{}-member same-prefix regression covers
multi-chunk boundary shifts and missing-chunk failure. These regressions, not
the abstract TLA+ model, cover radix partitioning, touched-branch reconstruction,

\section{Ordinal/Bitmap Refinement}

For each immutable dictionary segment $j$, the publication compiler checks a
bijection $D_j:F_j\leftrightarrow[0,n_j)$ between canonical FactIDs and 32-bit
ordinals. Let
\[
 \operatorname{Decode}_j(A)=\{D_j^{-1}(x)\mid x\in A\}.
\]
The concrete OR and ANDNOT operators are ordinary exact set operations on
canonical Roaring bitmaps, so decoding commutes with union and difference and
popcount equals decoded cardinality. Dynamic release/outcome dictionaries obey
the same invariant after exact hash/payload collision checks. Segments are
disjointly tagged by dictionary and segment identity; cross-segment decoding is
their disjoint union.

The streamed companion replaces each singleton Scan annotation with its
publication ordinal. For one canonical output group the engine preserves the
support bitmap and stores only multiplicities above one. Same-proof
composition adds multiplicities, alternative-proof composition takes maximum,
and a hash-ordered k-way merge emits the identical witness sequence used by the
canonical commitment. Consequently decoding the three bitmap components
recovers $(F_r,F_i,F_o)$ exactly; no approximation or probabilistic membership
test appears in the safety path.

The root state is one tuple $(H_r,H_i,H_o,e)$ of three immutable set-manifest
digests and an epoch. A transaction based on epoch $e$ computes exact novelty
with ANDNOT, checks all decoded cardinalities, and can publish the three
candidate heads only together at epoch $e+1$. A stale candidate refreshes all
three dimensions. This simulates the abstract transition
$K'_d=K_d\cup F_d$ for every $d\in\{r,i,o\}$ and preserves the root-family
theorem. The finite model \code{ExposureBitmapRefinement.tla} specifies this
commuting relation and configured invariants for bounded dictionaries,
requests, replay, and CAS conflicts; it is not a mechanized proof of the Go
implementation and is not itself performance evidence. The accompanying
action/transaction/test correspondence is an auditable refinement map, not a
machine-checked refinement theorem.

\subsection{Receipt Persistence-Time Semantics}

The normal production enforcement path creates a \emph{co-committed receipt}: receipt
signing and insertion occur in the same Control-PG transaction as resource and
exposure settlement, terminal and artifact-registration audit evidence, and
the PENDING artifact row.  The implementation also retains a compatibility
recovery path for a terminal query, artifact row, and registration event that
already exist while the receipt row is absent.  This path first validates the
original registration event against the immutable audit chain and then emits a

settlement and the receipt itself was not co-committed with that settlement.
Both forms prove intent rather than availability; the normal Compose path
produces the co-committed form. They share one wire format and verification
rule rather than carrying a recovery-mode flag.

\section{Clearance-Accounting Obligations and Evidence}
\label{sec:supp-clearance-accounting}

Fix an approved root $T=(P,S,B,C)$ whose contract binds versioned profile
$\pi$. Let $K_X(T)$ denote the decoded Fact set in the corresponding committed
root-family head---equivalently, its accounted set. We write
$\facts_X^\pi(q)$ for the Result, Dependency, or Outcome
component already defined by the main-paper effect under $S$ and $C$, and
$\Delta_T^X(q)=\facts_X^\pi(q)\setminus K_X(T)$.  This notation exposes the
profile parameter; it does not add a second exposure algebra.  A selected
visible cell is exactly a pair $(t,a)$ with $t$ in the successful result bag
and $a$ in its requested visible field set.

\textbf{O1---Output coverage.} Every selected visible cell contributes its
validated materialized Result identity. Equal semantic identities may collapse
under set normalization, so coverage is neither returned-row count nor one
distinct FactID per wire-cell occurrence. Changing the selected field set changes the
covered cells.

\textbf{O2---Positive dependency coverage.} The Dependency set is exactly the
support selected by E-Scan, E-Project, E-Select, E-Page, E-Join, E-Union, and
E-Group: retained predicate fields, join keys, group keys, distinctness fields,
and complete aggregate arguments are included. It is not minimal causal
provenance or a physical-read trace, and it omits rejected rows and non-output
pages under this profile.

\textbf{O3---Conservation.} Only the listed typed normal-form rewrites,
disjoint projection splits, complete page partitions, overlaps/retries,
canonical join folds, and root-family delegation are covered. Their Fact-set
union cannot be reduced by changing the admitted representation; arbitrary SQL
equivalence is not claimed.

\textbf{O4---Probe capacity.} A successful query contributes canonical
predicate atoms and one normalized query/result composite, even for zero or
empty output. Exact replay reuses both; a changed canonical predicate or
normalized query/result observation separates the corresponding identity
except for collision. Cardinality is governance capacity, not entropy or
privacy bits.

\textbf{O5---No unaccounted governed release.} If a canonical artifact for $q$
is \code{AVAILABLE}, then each $\facts_X^\pi(q)$ must already be included in
$K_X(T)$ and every $|K_X(T)|\leq B_X$. Settlement can precede availability, so
the reverse implication is false. Staging, failed settlement, and a bare
settlement receipt do not cross this boundary.

\textbf{O6---Profile binding.} Query derivation, settlement, semantic replay,
receipt verification, and audit must agree on the task, Grant, Catalog,
publication/dictionary, profile, normal form, View contract, type/collation,
and result handling. The receipt directly records the profile version and
observation/component digests; the complete environment is transitively bound,
not represented by a \code{profile_digest} field.

\section{RQ5: Daily Publication and Retained-Publication Routing}
\label{sec:rq5-supp}

Publication retention follows live root references. The current epoch and any
older epoch with a live root retain complete HOT, COLD, sidecar, and dictionary
artifacts locally. After the last bound root terminates, COLD payloads may move
to audit object storage, while manifests, digests, receipts, and audit-chain
evidence remain for the policy audit period. Local artifacts and replay entries
may be reclaimed only after both the last reference and retention deadline.
The prototype does not evaluate archival bandwidth or automated collection.

\textbf{Offline publication campaign.}
The source-controlled campaign builds four \RQFiveRows-row,

is not an official TPC-H benchmark. Day~0 is the base. Relative to its
predecessor, Day~1 updates the sorted-prefix 3,450 rows (1\%), Day~2 updates

\textbf{Illustrative scenarios (not evaluated as production deployments).}
In a telecommunications enterprise, headquarters marketing could analyze
nationwide aggregate metrics while a provincial marketer's mandatory regional
scope limits the same Product to one province. Subscriber phone numbers, names,
and government identifiers would not enter the marketing Product. Where
small-cohort disclosure matters, a separate policy, such as a
minimum-contributor threshold, statistical disclosure control, differential
privacy, or DFC, remains necessary. An enterprise-wide salary query would
require a separate HR-leader-approved task. Operations personnel could use a
distinct equipment-and-facility Product, but the present analytical BDG path would not
control a network in real time. In banking, branch staff
could analyze regional aggregates, while risk or fraud casework uses a
short-lived, high-sensitivity, independently approved task. This does not make
BDG a regulatory-compliance decision maker. In an electric utility, regional
load, loss, and equipment-health Products could remain
separate from marketing and finance domains; BDG would not perform subsecond
control, protection actions, or equipment-configuration writes. The scenarios
only illustrate how Product, scope, approval, and the task-bound root-family
Exposure Ledger compose.

\textbf{Future Policy Studio (not implemented).}
A future governance plane could move a profile through
Draft $\rightarrow$ metadata discovery $\rightarrow$ stable-key validation
$\rightarrow$ sensitive-field inheritance $\rightarrow$ generated negative
tests $\rightarrow$ shadow execution $\rightarrow$ multi-role approval
$\rightarrow$ signed profile publication. Data owners would decide purpose and
releasable scope; security/privacy teams would define sensitive boundaries;
IAM/OA would attest identity and approval; DBAs/data engineers would validate
database facts and performance mappings; BDG would compile and enforce the
published contract; and auditors would reconcile approval, settlement, and
AVAILABLE evidence. Multi-engine connectors, DFC/Passant composition,
principal/tenant-wide policy, differential privacy, and cross-tool IFC remain
separate future work. The present prototype does not implement this complete
governance platform.
